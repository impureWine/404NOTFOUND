# 数据库部分答辩讲稿（约 100 秒）

大家好，我负责 404 烦恼未找到的数据库设计与信息检索设计。

本轮范围统一为六个模块、REQ01 到 REQ17。其中 REQ13 是屏幕无损发泄，REQ14 是文字销毁，REQ15 是禅意编曲弹珠机，REQ16 是注册、登录、改密和退出，REQ17 是私密个人主页。漂流瓶、公开主页、账号注销、密码找回或重置，以及自动跨入口同步均不在本轮范围。

技术基线已经确定为 Node.js 服务通过 `pg` 和 Repository 访问 PostgreSQL，使用 SQL migration；交付目标是同源 Web/API 加私网数据库。时间点统一保存 UTC，日历日期按用户时区解释。密码使用 Argon2id 摘要，随机会话凭据仅安全传输，数据库只保存 SHA-256 摘要。

ER 模型以 `user_accounts`、`entry_points` 和 `saved_records` 为核心。所有可回看的业务对象都继承账号、入口、请求幂等、版本和删除状态；具体内容再进入消息、情绪、物件、排练、寄存或查询子表。跨入口读取必须经过 `consent_grants` 的用途、范围、有效期和撤回校验。

检索链路保留问题限制词，完成来源去重和 Claim-Evidence-Source 绑定，并显式区分空结果、超时、冲突和过期。只有用户确认保存时，查询和证据链才写入数据库。

隐私上，REQ14 是独立零持久化流程，正文不进入网络、数据库、浏览器持久缓存、日志、模型、搜索或备份。删除事务同时写清除任务和 outbox；独立删除日志至少保留 8 天，覆盖 7 天备份窗口。恢复必须先重放清除日志并撤销旧登录会话。

最后强调：这些文件是已统一基线的设计交付，DDL 尚未在运行数据库执行，验收清单中的运行项仍需联调证据，不能表述为系统已经部署或测试通过。
