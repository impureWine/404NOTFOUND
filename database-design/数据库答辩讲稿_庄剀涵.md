# 数据库部分答辩讲稿（约 100 秒）

大家好，我负责 404 烦恼未找到的数据库设计与信息检索设计。

先说明一个边界：本次分工文档把范围冻结为六个模块、REQ01 到 REQ17，并明确不重新加入密码找回、公开主页、漂流瓶和自动跨端同步。因此这份设计只保留私密资料和必要的账号会话，不把历史材料里已排除的功能写成既成事实。数据库选用 PostgreSQL 兼容设计作为待确认基线，生产位置和密钥服务仍需团队确认。

ER 图的中心是账号、入口和授权。所有可回看的业务对象同时绑定账号与入口，跨入口读取必须有用途、范围、有效期和可撤回的 `consent_record`。陪伴、训练和排练默认只在当前任务存在；只有用户主动保存时才进入加密的会话、情绪记录、物件、认可表达、寄存或查询表。物件可以只保存外观，日历只记录不自动分析，寄存到期只变为“可取出”，不会自动展开正文或调用模型。

检索链路是“明确问题、保留限制词的规范化、授权校验、检索、去重、主张—证据—来源绑定、展示不确定性，最后再由用户决定是否保存”。来源按官方原文、机构解释、可靠二手、社区线索分层；空结果、超时、冲突和过期分别有状态，不用一个空列表或一个顺滑答案掩盖差异。

隐私上，REQ15 文字焚化是独立的零持久化流程：正文不进数据库、浏览器持久缓存、日志、模型、搜索或备份。删除也不是只删一行，而是建立 `deletion_job`，逐个跟踪主库、缓存、索引、派生物和备份延迟，失败可以重试。

最后强调，DDL 和验收表是设计验证附件，目前没有运行数据库或通过测试的证据。答辩中我会把“设计结论”和“待确认/待执行”分开说明。
