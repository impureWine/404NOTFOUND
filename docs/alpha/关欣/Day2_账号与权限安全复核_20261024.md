## 1. 结论速览

| 编号 | 安全要求（摘要） | 结论 | 依据 |
|---|---|---|---|
| 1 | 重复注册、登录名标准化及失败提示 | **部分** | 大小写和 NFKC 同名被拒，相关表无重复行；409 仍明确提示“登录名已被使用”，见 D2-M01 |

## 3. 风险与缺口

分级依据：**高**＝应在开放相应入口或发布前处理；**中**＝需要修正的反馈或异常契约问题；**低**＝纵深防御与文档类问题。

### 高

#### D2-H01｜上下文换发改变入口范围（高）

- **复现**：同账号创建 WEB 记录；在隔离数据库构造合法 DESKTOP 会话；直接读取 WEB 记录返回 404；携带该 Cookie 请求 `/api/auth/context`，使用新 Cookie 再读取同一记录。
- **预期 / 实际**：入口范围保持不变，仍应拒绝；实际从 **404 变为 200**。对应 **D2-22**。
- **原因位置**：[app.js](../../../backend/src/app.js) 第 88～104 行换发时仅传 accountId；[auth-service.js](../../../backend/src/services/auth-service.js) 第 35～48 行固定取 WEB 入口。
- **建议**：上下文换发保留可信会话的入口，并核对该端点允许的入口；入口不能由客户端字段自报。明确跨端身份使用与记录隔离的契约，再补上下文轮换的回归用例。
- **协作**：李泉毅主修，庄剀涵复核作用域，关欣复测，曾俊涛回归。
- **边界**：真实 HTTP 和实际服务已执行；DESKTOP 会话由 PGlite 测试夹具设置，未完成桌面或微信的原生登录。因此不能写成“已在三端复现”。
- **状态**：本机复现；业务未修复，未做修复后复测。

#### D2-H02｜未知异常回显内部信息（高）

- **复现**：在已认证资料查询的数据库调用点注入合成异常，消息包含 `synthetic:db-private-detail`、合成密码字段、SQL 字样及合成内部路径。
- **预期 / 实际**：客户端只得到通用错误与请求标识；实际返回 **503**，`error.message` 完整包含上述标记。对应 **D2-17**。
- **原因位置**：[request.js](../../../backend/src/http/request.js) 第 81～88 行将未知错误默认映射为 `SERVICE_UNAVAILABLE`，只有状态 500 才改为通用提示，503 仍输出原始 `error.message`。
- **建议**：只对白名单业务错误返回经过审核的消息；未知异常统一安全响应，禁止直接序列化任意 `message/details`。内部诊断记录按字段白名单处理，与客户端响应分开。
- **协作**：李泉毅主修，关欣复测。
- **边界**：这是故障注入证据，没有使用或发现真实密码、真实数据库异常中的用户内容。
- **状态**：本机复现；未修复、未复测。

#### D2-H03｜匿名请求能进入内部模型路由（高）

- **复现**：不带 Cookie、CSRF、Origin 或服务凭据，向 `/internal/v1/model/generate` 发送合成 JSON；用只计数的模型适配器替身观察是否分派。
- **预期 / 实际**：未经内部服务授权的请求在调用前被拒绝；实际 **HTTP 200，适配器调用 1 次**。对应 **D2-20**。
- **原因位置**：[app.js](../../../backend/src/app.js) 第 72 行路由位于 `/api` 安全中间件之前，也没有独立的内部身份校验。
- **建议**：内部路由增加服务身份、允许来源及请求上限，或仅由受控业务服务调用；游客陪伴通过有外发许可与限流的业务入口提供，不能让“内部路由”名称替代访问控制。
- **协作**：李泉毅、程群，关欣复核边界。
- **边界**：这里只证明 HTTP 路由缺少调用闸门；模型适配器为替身，**没有调用真实模型，也没有验证或产生供应商费用**。当前 server 默认绑定回环地址，外部部署可达性没有验收。
- **状态**：路由替身复现；未修复、未复测。

#### D2-H04｜body-parser 高风险依赖告警（高，审计证据）

- **实际结果**：`pnpm audit --registry=https://registry.npmjs.org --audit-level=high --json` 退出 1；路径为 `express → body-parser`，本地锁定 **2.3.0**，告警 **GHSA-27r3-jxmh-p828 / CVE-2026-111181**。
- **上游依据**：维护者公告将 `>=2.0.0 <2.4.0` 列为受影响范围，修复版本为 **2.4.0**；压缩请求正文尾随字节可能导致未捕获异常。已核对[维护者公告](https://github.com/expressjs/body-parser/security/advisories/GHSA-27r3-jxmh-p828)。
- **建议**：由后端负责人在独立依赖变更中更新到修复版本并同步锁文件，复跑正文解析、认证与接口测试；如业务不接受压缩请求，可评估公告给出的 `inflate: false` 临时措施。
- **协作**：李泉毅、曾俊涛；关欣复核审计及接口结果。
- **边界**：已确认受影响依赖版本和官方告警，**没有执行拒绝服务攻击或崩溃复现**；不能将审计告警写成实际攻击成功。
- **状态**：告警未处理；未更新依赖版本或修改锁文件。
