## 3. 风险与缺口

### 高

#### D5-01 内部模型入口仍可被非授权路径调用（P0）

- **现象**（本次实测，计数适配器）：

  | 请求形态 | 状态码 | 适配器调用次数 |
  |---|---|---|
  | 匿名（无 Cookie） | **401** | 0 |
  | 有会话 + 错误 Origin（`https://attacker.example`） | **200** | **1** |
  | 有会话 + 正确 Origin 但无 CSRF | **200** | **1** |
  | 有会话 + 正确 Origin/CSRF，但请求体无 `AI_PROCESS` 许可 | **200** | **1** |

- **根因**：`app.js:74-87` 只解析会话并要求 `accountId`，**未经过 `/api` 的 `createSecurityMiddleware`**，因此没有 Origin 校验与 CSRF 校验；模型请求契约（`model-contracts.js:48`）为严格对象且不含许可字段，用途许可无法绑定。
- **影响**：任何拿到有效会话 Cookie 的页面（含第三方页面若能触发同站请求）都可消耗模型配额并把任意文本送入模型上下文；`SEC-05`/`SEC-11` 无法验收。
- **建议**：把内部入口纳入统一安全中间件，或改为服务间鉴权（共享密钥 + 仅回环）；模型请求契约增加许可引用并由服务端注入。
- **责任**：李泉毅（入口）／程群（契约）主修，关欣复测。
- **修复后验收**：上表后三行应变为 403/403/403 或 401，且适配器调用次数全为 0；届时须把 `day5-p0-recheck.test.js` 的 D5-01 断言改为期望值。

#### D5-02 同账号跨入口可读并取消 AI 任务（P0）

- **现象**（本次实测）：WEB 会话创建的 AI 任务 `status=completed` 且 `result` 非空；用同账号的 **DESKTOP** 会话读取同一任务 → **200 且 `result` 可读**；跨入口 `cancel` → **200**。
- **根因**：`task-service.js:28` 的 `ownerKey(context)` 只取 `context.accountId`，**不含 `entryPointId`**；`task` 的 `ownerKey` 取自会话（`:111`），`getAgentTask`/`cancelAgentTask` 仅比较 `ownerKey`（`:231`、`:237`）。对照 `record-service.js:25-26` 的 `scope()` 同时含账号与入口，可见记录链路正确、任务链路缺一层。
- **影响**：入口隔离在 AI 任务上失效，`SEC-09` 与权限矩阵 `P-13` 口径被绕过；跨入口还能取消对方任务，属可观察的行为越界。
- **建议**：任务作用域改为 `accountId + entryPointId + sessionId + 双代次`；`GET`/`cancel`/`action` 统一按该作用域校验；补一条跨入口拒绝的回归用例。
- **责任**：李泉毅／程群主修，关欣复测。**注意 PR #54/#63 尚未合并**，需先评审其差异再按新 SHA 复测。
- **边界**：DESKTOP 会话由服务端夹具签发，等价于"服务端已认证的跨入口会话"，不代表原生桌面发行流程已验收。
