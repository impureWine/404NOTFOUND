## 2. 能否发布

**不能。候选版本发布判定：BLOCKED。**

三条理由，任何一条单独成立即不满足发布条件：

1. **一个 P0 仍未关闭（D5-02）**：`SEC-09`（入口隔离）无法验收，权限矩阵 `P-13` 在 AI 任务上与实现不一致。D5-01 已于 16:13 修复，不再是阻断项。
2. **发布配置未通过**：`check:release` 仍 BLOCKED，正式 PostgreSQL 16、密钥注入、迁移与恢复均未执行。
3. **REQ14 无可达 UI**：销毁流程的网络/存储/日志/重开四项运行时证据始终无法取得。

## 6. 答辩口径

**问：这两个安全问题修了吗？**
> D5-01 修了：16:13 的 PR #63 把内部模型入口改成必须携带内部令牌，未配置时直接拒绝；我复测四种请求全部 403、适配器 0 次调用。D5-02 没修——任务作用域还是只看账号、不看入口，#54 和 #63 都没动 `ownerKey`，所以我今天复测跨入口读取仍是 200 且能拿到结果。

**问：那你们凭什么叫候选版本？**
> 候选版本指"功能闭环可演示"，不等于"可发布"。我们的判定是 BLOCKED，和 PM 的结论一致；今天交付的是风险状态与未验证清单，不是通过结论。

**问：为什么之前一直说两个 P0？**
> 因为 16:13 之前确实两个都没修。#63 合并后我立即复测并更正了结论——结论会变，是因为代码变了，不是因为标准变了。
