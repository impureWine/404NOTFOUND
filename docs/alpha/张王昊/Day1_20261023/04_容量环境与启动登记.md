| 项目 | 依据与状态 | 执行人与所需证据 |

| 模型 | 厂商、型号、地区、留存、预算、额度、密钥注入位置均待程群登记 | 关欣核对外发告知；真实调用仅用合成输入 |
| 检索 | Wikipedia固定接入；真实调用失败记录已提供 | 庄剀涵检查出口，提供成功来源；不得空结果代替失败 |
| 部署 | 云主机/域名/区域/HTTPS未提供 | 曾俊涛登记授权资源；没有云资源时用可复现本机包 |

建议在完整仓库的独立工作副本执行，参考快照是节选，不能用作完整运行包。

```powershell
# 前端：进入完整仓库的prototype
npm ci
npm run build
npm run dev -- --host 127.0.0.1
# 后端：进入完整仓库的backend；仓库有pnpm-lock.yaml，先核对工具版本
pnpm install --frozen-lockfile
# 在授权隔离PG16中配置DATABASE_URL；不要在日志打印连接串
pnpm run migrate
pnpm test
pnpm start
# 另一个终端；后端默认127.0.0.1:3000
Invoke-WebRequest http://127.0.0.1:3000/health/live
Invoke-WebRequest http://127.0.0.1:3000/health/ready
```

配置文件创建前先检查是否存在，已有.env不覆盖；变量取自完整仓库.env.example，真实密钥只服务端注入。上述是交接步骤，本次未安装依赖、启动服务或重跑19项测试。
