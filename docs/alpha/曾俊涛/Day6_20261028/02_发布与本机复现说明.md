## 在本机复跑

1. 使用 PowerShell 校验归档：`(Get-FileHash -Algorithm SHA256 .\404NOTFOUND-main19ad7eb-source.zip).Hash`，应等于上面的哈希。解压归档，进入其中 `404NOTFOUND-19ad7eb6eccebdc8a68f0c3763048c91f2b4d34c` 目录。
2. 环境：Node.js 22 或更高；pnpm；npm。后端执行 `cd backend; pnpm install --frozen-lockfile; pnpm test`。本次日志显示 123/123 通过；单机 PGlite 无需正式数据库。
3. 前端执行 `cd prototype; npm ci; npm test; npm run build`。本次 6/6 通过，`dist/index.html` 和 `dist/ux-components.html` 均生成。用 `npm run preview -- --host 127.0.0.1 --port 5191`，可打开 `http://127.0.0.1:5191/` 与 `/ux-components.html?page=home&state=normal`。这两个静态入口中的业务内容是演示，不构成真实服务联调。
4. 回到本 Day 6 交付目录，运行 `node .\tests\day6-cross-layer-rerun.mjs "<解压后的仓库绝对路径>" 19ad7eb6eccebdc8a68f0c3763048c91f2b4d34c`。脚本输出 JSON，预期当前主线为 11 通过、2 未达标，退出码 1。它使用合成账号、PGlite 和计数模型替身；该退出码应保留，不要掩盖红灯。
5. 正式配置预检：`cd backend; pnpm check:release`。未设置正式环境变量时应输出 BLOCKED，至少要求 `DATABASE_URL` 与 `PROFILE_ENCRYPTION_KEY`。不得在文档、截图或 GitHub 中填入真实密钥。

浏览器脚本在 [`tests/`](tests/)；需本机 Edge 和 `PLAYWRIGHT_MODULE_PATH` 指向可用的 `playwright-core/index.mjs`。执行结果与对应截图见 [回归报告](01_最终回归报告.md)。浏览器辅助 API 测试默认使用 3012/5190 两个本机端口，可通过 `DAY6_API_PORT`、`DAY6_WEB_PORT` 调整。脚本使用合成账号、内存库，不连接正式后端。
