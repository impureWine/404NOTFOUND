## 1. 依据与目标

- [课程第四次作业原帖](https://bbs.csdn.net/topics/620563653)要求冲刺中并行测试、逐步开展自动化测试，并在独立测试随笔中说明测试安排、工具、用例、体会和项目评述。
- 组长《404烦恼未找到_Alpha冲刺7天执行计划_20261023-1029.md》将“游客体验命名卡／陪伴 → 注册登录 → 主动保存 → 查看本人记录／个人主页 → 退出或换账号后隔离”列为本轮建议核心验收链。
- 需求基线为 REQ-01～REQ-17；设计稿、原型、替身调用和真实服务结果分别记录，不混记。

本轮测试目标是为真实实现提供可重复的功能、数据归属、取消与隐私证据。每天登记“通过／失败／阻塞／未执行”，只有实际执行且能复查的结果才算通过。

## 3. 优先级与验收出口

**P0（阻塞提交）**：核心登录与本人数据闭环、未授权拒绝、A/B 账号隔离、默认不保存、退出和改密后的会话失效、文字销毁不外发／不持久化、取消后旧响应不回填、真实检索结果的来源对应。具体用例见[核心测试用例清单](03_核心测试用例清单.md)。

**P1（本轮重要）**：训练暂停／继续／退出、无结果与超时提示、资料编辑校验、Electron 最小能力、错误状态和可复现启动。

**阶段出口**：

1. 运行版本、依赖与配置可复现；每个测试结果绑定版本、环境、执行人、时间和证据。
2. P0 用例均有实际执行结论；失败或阻塞项列明影响、负责人和处理决定，不能默认为通过。
3. 自动化和人工测试的通过／失败／阻塞／未执行数量分别汇总；替身结果与真实集成结果分别列示。
4. 候选版和最终版分别回归；报告中明确原型、未实现、云资源不可用等限制。

## 5. 执行规范

- 使用合成账号与合成敏感文本；测试账号 A/B 分开，清理仅限隔离测试实例，真实用户数据不参与。
- 每条用例记录：用例号、REQ/AT、版本 SHA、环境、执行人、执行时间、步骤、预期、实际、状态、截图／日志链接、缺陷号。
- 缺陷分级：S1＝数据越权、敏感正文外发或核心流程中断；S2＝主要功能错误但有可行绕行；S3＝局部体验或文案问题。安全和数据问题先由对应开发负责人修复，关欣复核，曾俊涛回归。
- 变更后至少回归受影响模块及 P0 主链；对取消、重复保存、失效会话和跨账号检查并发与旧响应。
- AI 可辅助起草用例、归纳失败日志和查漏；实际执行、判断和发布结论由成员核验。测试随笔仅记录真实发生的 AI 使用与人工修正。
