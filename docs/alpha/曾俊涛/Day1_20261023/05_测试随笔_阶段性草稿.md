今日实际使用 Git、Node/npm、Vite、PowerShell 的 HTTP 请求和系统已安装的 Chrome 无头截图。已对临时克隆的 `main@7303507` 执行 `npm ci`、`npm run build`、Vite 启动及三个 HTTP GET。正常权限重试后安装和构建成功、GET 均为 200；初次在沙箱中的网络与目录读取失败也保留了日志。完整环境和结果见[启动记录](01_启动与构建核验记录.md)。

当晚仓库更新后，我又核对 `main@523584c` 的新增后端源码，使用 pnpm 锁文件安装并运行 `pnpm test`。受限环境的健康检查遇到本机端口 `EACCES`，正常本机权限下 25 项测试全部通过、0 失败；两次输出和版本见[新增后端独立复核](08_新增后端独立复核记录.md)。这些是 PGlite 隔离测试与 Express 健康检查，不是正式 PostgreSQL、真实检索或业务 HTTP 的通过结论。

在 Day 1 较早版本 `main@7303507`，`prototype/package.json` 尚没有测试脚本。后续修订的[前端 CI 草稿](ci/ci-prototype.yml)检查依赖安装、适配器单测、生产构建及构建产物；新增 `backend/package.json` 已有 `test` 脚本，[后端 CI 草稿](ci/ci-backend.yml)运行全量离线测试。两份草稿尚未进入 `.github/workflows/`，不能写成 GitHub Actions 已运行。10 月 24 日的新版本已有前端适配器单测，见[后续修订](11_Day1材料后续修订_20261024.md)。后续业务测试工具必须随真实代码选用并实际执行，不能把“构建通过”或“仓储测试通过”写为完整功能通过。
