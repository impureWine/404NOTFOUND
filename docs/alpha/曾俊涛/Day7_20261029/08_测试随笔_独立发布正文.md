## 一、学习资料怎样影响测试安排

课程要求结合《构建之法》第 2、13 章开展测试。我在线核对了作者公开的章节配套资料、参考和练习，**未取得教材全文**，因此不引述未核对的正文和页码。第 2 章相关材料让我把单元测试、回归和可重复执行的质量门槛放在每天开发旁边；第 13 章相关材料提醒我同时检查“实现是否按合同运行”和“用户能否完成真正目标”。

Day1 固定启动、构建与账号基线；Day2 建立首批自动化；Day3 扩展陪伴、训练、查询；Day4 逐项检查保存、隔离、清除与模型许可；Day5、Day6 随主线变化回归；Day7 在精确提交上做最终冒烟与缺陷交接。每轮保留提交 SHA、命令、退出码、机器 JSON 和截图。这样能看出某项失败是新改动，还是先前就存在。

## 二、工具与用例

| 层次 | 工具 | 验证重点与限制 |
|---|---|---|
| 模块 | Node.js 内置测试运行器 | 后端服务、前端 API 客户端合同及错误路径；绿色测试可能只锁定了既存缺陷签名 |
| 跨层 | PGlite 内存库＋本地 HTTP | 许可、保存、列表、A/B 隔离、详情、清除；不能替代正式 PostgreSQL 16 |
| 构建 | Vite | 首页与 UX 展示双入口产物；构建成功不证明业务闭环 |
| 浏览器 | Playwright＋Edge | 页面控件、真实 API 模式、账号、记录库流程与截图；使用合成账户和本地服务 |
| 发布预检 | check:release | 数据库地址、加密密钥等配置；预检不等于部署 |

模型安全测试使用合成输入与**计数模型替身**，测的是请求是否到达适配器，不证明真实模型的回答质量。截图也不能单独证明隔离；相应状态需要 JSON、HTTP 与数据库探针支持。

## 三、最新执行结果

在按 Git blob SHA 核对的本地可执行重构树上，后端 **141/141**、前端 **7/7**、双入口构建通过。Edge 静态首页与 UX 展示页均 HTTP 200，页面错误 0。这两页静态冒烟没有发出业务 API 请求。

我又通过真实页面操作新记录库：输入临时文字后点击销毁，当前界面清空；注册并登录 A，空列表可见；页面审核文字、签发单次 SAVE 许可后保存，列表出现 1 条；点击详情能看元数据；执行两步清除后列表回到空；退出 A，再登录 B，B 的列表为空。页面错误 0。对应本地 JSON 记录注册、登录、保存、详情、清除的 HTTP 状态和 9 张新截图。**“销毁”仅证明当前界面清空**，未覆盖网络、存储、日志、重开四项隐私核验。

13 项跨层记录／许可检查为 **12 通过、1 失败**。D4-12 现已通过：无内部令牌且 Origin/CSRF 错误、缺 AI_PROCESS 许可的探针返回 403，计数适配器调用 0。D4-07 仍失败：本人记录详情无法恢复可展示正文，API 响应含密文字段。页面详情因此只能展示元数据，不能算“保存后完整回看”。后端另一个 D5-02 缺陷签名仍可复现：同账号 DESKTOP 会话可读取及取消 WEB 任务。后端 141 项全绿含有这类缺陷签名测试，通过的含义是问题稳定复现。

发布配置预检仍 **BLOCKED**，缺 DATABASE_URL 和 PROFILE_ENCRYPTION_KEY。正式 PostgreSQL 16、真实模型、云端部署与恢复未获得本轮通过证据。因此我的发布判定仍是**不通过**。

## 四、自动化带来的收益与盲区

连续回归能快速发现新提交改变了什么。例如 722bc92 时后端 130 项、前端 6 项；加入最新记录 UI 与 AI 安全改动后，本轮是 141 项、7 项。跨层 D4-12 从失败转为通过，说明某个关键阻断已改变；但 D4-07 依旧失败，D5-02 也未关闭。若只报“141/141”，团队会误以为发布门槛都已达到。

浏览器层补上了单元测试看不到的产品路径：本轮保存和清除是点击记录库页面控件完成，而不再只是 QA 脚本直接发 API。不过，A/B 各自空列表的截图不能独立证明越权拒绝，详情界面也不能掩盖正文不可读。下一轮应先修 D4-07 与 D5-02，改写仍锁定缺陷签名的断言，再在新提交上重跑跨层和浏览器流程。正式配置齐备后还需要 PostgreSQL 16、真实模型与部署回滚专项。

## 五、AI 技术员的作用与我的核验

AI 帮我梳理 GitHub 差异、维护测试脚本、整理日志和截图图注，并提醒我把“测试通过”与“需求通过”分开。结论和数值以实际命令、HTTP 响应、JSON 为准；我还检查了截图是否确实显示所说的状态。AI 不能替代真实站会、正式环境授权或人工判断，也不能凭推测写已发布博客 URL。

这次冲刺让我认识到，测试交付物的价值在于让团队看到可复现的进展与剩余风险。当前已有可演示、可回归的基础，但记录正文回看、跨入口任务隔离和正式发布条件尚未满足。
