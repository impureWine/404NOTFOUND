## 测试与开发并行

Day 1 建立启动、构建和用例基线；Day 2 检查账号、资料与授权；Day 3 扩展陪伴、训练和查询正常/异常路径；Day 4 验游客、登录、主动保存、A/B 隔离、两步清除、模型许可及文字销毁；Day 5 在固定提交上集中回归并形成候选证据。每轮记录 SHA、命令、退出码和原始输出；开发修复后用新合并提交复跑。测试将模块遵守契约的**验证**与用户从正式页面完成目标的**确认**分开。

## 工具与用例

- **Node.js 测试运行器、PGlite 隔离库**：合成数据下重复检查归属、许可、记录、清除、查询与训练。正式 PostgreSQL 16 的权限、并发、迁移与恢复需要授权环境单独验收。
- **前端 Node 用例、Vite**：检查同源/CSRF/身份切换的 API 适配器并确认双入口可构建；构建不代表页面已调用后端。
- **Edge + Playwright**：读取实际页面、记录页面错误和网络请求、保留截图。真账号 UI 操作与 QA 脚本直调记录 API 分开标注。
- **13 项跨层探针**：用 HTTP、PGlite 和计数模型替身检查“本人历史可读”“模型调用前许可”等门槛，不调用真实模型。
- **发布配置门禁**：先发现缺失或占位配置；即使配置满足，仍需正式数据库、HTTPS 和恢复冒烟。

## Day 5 实测与评述

在精确主线 `34d751c` 上，本人复跑后端 **120/120**、前端 **6/6** 通过，Vite 双入口构建成功；Edge 静态页面 **2/2 HTTP 200**、无页面异常，但业务 API 请求为 0。13 项跨层探针 **11 通过、2 未达标**：D4-07 历史正文不可读且公开响应含密文字段；D4-12 在受测错误 Origin/CSRF、无 AI_PROCESS 许可时仍返回 200，计数替身调用 1 次。本机 `check:release` 因缺正式数据库地址和加密密钥 **BLOCKED**。

浏览器真实注册、登录与退出 UI 配合 QA 直接调用同源记录 API：A 保存 201、退出后记录接口 401；B 列表 0、读取 A 记录 404。受测 API 隔离成立，但记录动作没有正式页面绑定，详情正文仍不可读，不能说产品用户闭环通过。郭昱祺当日交互修订及 UX PPT 已进入主线，其 36 组走查和 77 组组件回归是作者自查、使用 mock/固定或内存数据；不计入本人独立回归，也不当作真实后端验收。

**120 条后端用例全绿，仍可能缺少用户真正需要的可读历史和模型调用前许可。** 因此模块自动化、跨层场景、页面操作和发布环境必须分别给结论。截图只能证明截图里出现的运行状态：静态首页和组件展示无业务 API；账号 A/B 截图要与同次机器 JSON 一起使用，才能说明 QA 直接请求的结果。不同层次的分母不能相加成“全系统通过率”。

本机候选 `0.1.0-rc.local.20261027+34d751c` 可复现，尚不能作为正式发布版。先修复 `T8-D5-01` 和 `T8-D5-02`，再接正式保存/历史/文字销毁入口，并在授权环境验 PG16/HTTPS、真实来源、备份与删除任务。
