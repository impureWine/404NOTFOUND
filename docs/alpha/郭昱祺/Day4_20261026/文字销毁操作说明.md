# 文字销毁操作说明

2026-10-26 · UX 操作交接 · 依据 REQ-14。本文提供目标操作说明及现有源码对照，不作为销毁效果已上线或已通过实测的证明。

## 使用场景

用户想通过一个短暂的仪式表达并放下当前想法，且不希望这段输入进入聊天、历史记录或 AI 处理。销毁页使用独立输入区，不读取历史正文；销毁临时输入不能代替清除已保存记录。

## 操作步骤与反馈

1. 从正式接入的工具入口进入“文字销毁”。页面应明确提示“仅当前页临时输入，不保存、不上传、不交给 AI”。本次保存／历史展示入口仅提供区别说明。
2. 在独立输入框输入文字。正文上限按 4000 Unicode 码点校验，不能把聊天或历史内容自动带入；超限时提示缩小范围，不静默改变用户表达。
3. 点击“销毁文本”。立即清空本页输入及私有缓冲，再显示销毁效果或完成反馈。空输入时禁用操作；动画失败或用户选择跳过，仍应清空。
4. 只想撤回输入时点“清空”；离开、关闭或结束页面时也丢弃临时输入。再次进入时不恢复原正文。
5. 完成反馈使用“已从当前界面清除”。不使用“系统绝对无痕”“服务器数据全部删除”等无法由该功能证明的描述。

## 与已保存记录清除的区别

| 项目 | 文字销毁 | 已保存记录清除 |
| --- | --- | --- |
| 对象 | 销毁页独立输入的临时文字 | 本人当前入口中明确保存的一条记录 |
| 操作入口 | 独立文字销毁页 | 本人历史 → 主动打开详情 → 清除确认 |
| 本次展示能力 | 操作说明及页内区别提示 | 可演示确认、取消、内存移除及状态变化 |
| HTTP／AI | 不需要，也不应上传正文 | 正式接入使用 clear-confirmations 和 clear 接口；不需 AI |
| 影响范围 | 只清空该页临时缓冲 | 正式实现清除对应记录及关联；本地展示只移除页面内存样例 |
| 反馈 | 当前输入已清空 | 只有确认服务端成功后，才可告知已清除保存记录 |

## 现有源码与接入注意

[DestroyPage](../../../../prototype/src/pages/Tools.jsx) 已有独立输入、销毁、清空、离开和合成示例按钮；[useTextDestructionState](../../../../prototype/src/req14/useTextDestructionState.js) 提供 `setBuffer/destroy/clear/dispose` 及页面退出清理。但当前 React 首页入口没有挂载该页，本次未更改它或对其运行效果作验收。

正式接入时需注意：现有 `DestroyPage` 文本框使用 HTML `maxLength=4000`，与接口规范的 Unicode 码点语义不同；hook 对超限内容直接截断，也与目标的明确超限反馈存在差异。请在端侧销毁交付中修正并验证 emoji 等边界。当前 `destroy()` 是即时清空与阶段反馈，不能据此宣称已提供碎纸、燃烧、黑洞三种实际动画。
