## 1. 阅读规则与覆盖范围

下表描述 **正式接入的目标状态**，并逐行注明原型证据及缺口。基于 `523584c` 静态阅读，不代表已运行、已联调或已验收。LG／HP／CH／SR 分别指登录、首页、聊天、查询来源；N／L／E／F 分别指正常、加载、空、失败。

“正常”表示当前区域可用，不必等于业务刚刚成功；“空”须说明是初始未输入、未查询，还是服务成功返回无内容。输入校验错误、权限错误、任务失败与无资料不能互换。异步请求按分区显示，不用整页遮罩阻断所有可用入口。

这些分支不能统一塞进“空”或用 Toast 假装完成。

## 7. 状态转换与实现交接约束

```text
登录：空表单 → 可编辑 → 登录中 → 成功跳转／失败可重试／结果待核实
首页：分区读取中 → 正常有数据／确认空列表／局部失败
聊天：空会话 → 编辑 → 授权 → pending/running → completed／failed／cancelled／expired
查询：未查询 → 授权 → pending/running → SUCCESS／EMPTY／failed／cancelled／expired
```

- completed 是任务终态，查询还需看 searchState；HTTP 200 不能单独决定显示“成功”。
- 网络等待超时可能发生在服务已受理后，应核实同一个操作；服务明确失败后才以新 requestId 手动重试。普通 API 5 秒、外部任务 30 秒、结果临时可取 5 分钟均为当前设计初值，不是性能实测。
- 每个任务每客户端 1 秒一次轮询、最多一个在途请求，终态／卸载／身份切换时停轮询。仅停止 fetch 不等于服务端停止执行。
- 每次回填匹配当前身份与入口、sessionId、activityId、requestId、sessionGeneration、activityGeneration；与当前活动不符的结果直接丢弃。
- 保存与结束分别有自己的真实回执；结束不自动保存，退出不清除已保存记录。保存未知状态不能先加入首页再悄悄回滚。
- 展示状态组件只接收区域 status 和事件，不把用户正文写日志、URL 或持久浏览器存储；服务端授权不能靠前端禁用按钮替代。
