## 4. 页面操作到接口的交接

下表均为 **09 号规范中的设计契约，待前后端接入**。不新增 `/api/chat`、`/api/home` 或 `/api/search` 等未定义路径。成功数据解包、错误解析和 CSRF 由适配层统一处理，展示组件不直接发请求。

| 操作／区域 | 契约与关键字段 | 界面交接要求 |
| --- | --- | --- |
| 进入应用／登录前 | `GET /api/auth/context` → `authenticated/csrfToken/expiresAt?`；`GET /api/capabilities` → `entry/features` | 读取中显示“正在确认身份”；身份未知不能先显示其他账号资料；入口能力分为 AVAILABLE／SIMULATED／UNAVAILABLE |
| 登录 | `POST /api/auth/login`，`{loginName,password,target}` → `profile/target/expiresAt` + Cookie | 登录名 NFKC 后 3～64 个 ASCII 字母／数字／下划线，索引小写；密码不 trim、不规范化，登录只检验非空及最多 128 码点；`target` 仅允许固定页面键 |
| 密码显隐／表单编辑／访客继续 | 本地交互，无登录提交 | 切换显隐不清输入、不触发表单；注册入口进入关联页；“忘记密码”和“记住我”不作为本次正式要求继承 |
| 首页身份与记录 | 需资料时 `GET /api/profile`；已登录时 `GET /api/records` → `items/nextCursor`；展示计数时 `GET /api/profile/summary` | 游客不调用私密记录接口；记录列表仅用元数据，详情再读 `GET /api/records/:id`；摘要接口非零／空判断的替代品，503 不能显示全零 |
| 进入聊天／查询 | `POST /api/sessions`，`{requestId,mode}`；聊天 LISTEN／ORGANIZE，查询 SEARCH | 接收 `sessionId/activityId` 及两类 generation；入口导航不等于任务已创建成功 |
| 聊天发送前授权 | `POST /api/consents`，purpose=`AI_PROCESS`，绑定本次 operation／payload／活动与代次 | 展示本次发送正文和所选上下文范围；允许取消；保存偏好不能代替此次外发授权 |
| 发送／读取／停止回复 | `POST /api/agent/tasks`；`GET /api/agent/tasks/:requestId`；`POST /api/agent/tasks/:requestId/cancel` | 输入含 mode、operation、selectedText、selectedContextIds、consentId 和会话双代次；202 只表示受理；任务 completed 后再显示正式回复 |
| 查询／读取／取消 | `POST /api/search/tasks`；`GET /api/search/tasks/:requestId`；`POST /api/search/tasks/:requestId/cancel` | 输入含 question、所选上下文、会话双代次及 SEARCH_PROCESS consentId；使用模型整理时还需 AI_PROCESS 的 aiConsentId |
| 来源展开／定位／打开链接 | 摘要 `claims[].sourceIds` 关联 `sources[].id`；点击展开与定位为本地交互 | 展示 title、url、publishedAt、retrievedAt、quality；只打开合法 http(s) 外链；UI 不自行抓取未知 URL、不伪造链接 |
| 切换倾听／梳理／查询 | `POST /api/sessions/:id/switch`，带 targetMode、expectedSessionGeneration、selectedContextIds、requestId | 有草稿或活动任务时显示影响与携带范围确认；默认不携带正文；失败显示真实状态，切换本身不等于新外发授权 |
| 结束 | `POST /api/sessions/:id/actions`，action=`END`，带 expectedSessionGeneration／expectedActivityGeneration／requestId | 确认后等待回执；立即阻断旧结果回填；失败可重试结束，不假称后台已清理；结束不等于清除已保存记录 |
| 主动保存聊天／查询 | 先取得 SAVE 许可，再 `POST /api/records` | 聊天 `kind=CONVERSATION`，payload 为 title、sessionId、selectedMessageIds；查询 `kind=QUERY`，payload **仅** `{searchRequestId}`，证据链由服务复制 |
| 退出登录／换账号 | `POST /api/auth/logout` → 204；随后刷新身份上下文 | 立即隐藏当前身份私密内容，清理组件内存、取消轮询；服务回执失败不能说已退出成功；已保存记录不会因此被删除 |

任务统一状态为 pending／running／completed／cancelled／failed／expired；普通接口约 5 秒、外部任务总时限 30 秒是设计初值。轮询每任务每客户端 1 秒一次、最多一个在途请求，终态即停。网络断开导致结果未知时先核实同一 requestId，不立即创建重复任务；服务明确 failed 后手动重试才使用新 requestId。

| D03 | React 聊天 500 字、查询 200 字，使用 JS length | 正文／问题按正式非空文本契约及最多 4000 Unicode 码点；上下文合计最多 12000 码点，选择消息 ID 最多 20 个；不静默截断 |
| D04 | 开启演示会话设置后，结束时可能保存整段模拟对话 | 默认临时；偏好只提示保存；逐次选择内容、预览并取得 SAVE 许可；1～20 条消息且快照总正文不超 12000 码点 |
| D05 | 来源按钮只发 Toast，摘要没有 claim→sourceIds 绑定 | 逐摘要引用、可核查外链、未知时间／过时／冲突／部分成功分别标识；不把全局提示替代逐条依据 |
| D06 | React 为绿色主题，HTML 默认柔粉；HTML 包含预设打卡／历史 | 组件规范记录柔粉目标 tokens 与 React 迁移差异；正式页面仅展示当前身份真实读取或用户主动保存的数据 |
| D07 | 首页含担忧瓶演示等额外工具 | 入口组件按正式 REQ 与 capabilities 取数；演示功能标记为模拟，不能自动计入 17 项业务范围 |
| D08 | HTML 的失败草稿文案和示例记录为固定内容 | 正式组件只能描述实际的当前页内存状态，不承诺持久草稿、真实上传或系统级清除 |

## 6. 交接完成条件与复核记录

以下是后续实现的可观察验收点，本次未执行产品测试：

- 登录：空字段不提交；等待时不重复提交；凭据错误统一提示；合法 Unicode 密码不被 trim 或截断。
