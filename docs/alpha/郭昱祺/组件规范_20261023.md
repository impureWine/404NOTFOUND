## 1. 组件边界与命名

本规范描述可从现有原型复用或提取的组件及其目标交互，**不代表本次已经实现组件**。采用 JavaScript／React；以下 props 是设计交接契约，可用 JSDoc 描述，由前端接入时与共享 Schema 对齐，不要求另行迁移 TypeScript。

组件使用 PascalCase；事件使用 `onXxx`；展示组件接受经适配的数据，向容器发出用户意图，不直接读 Cookie、发 HTTP 或维护跨账号业务缓存。会话代次、授权、任务轮询、幂等和取消由容器／适配层处理。

```text
页面容器（程杰按既有分工组织）
 ├─ LoginPage → AuthForm → FormField / PasswordField / Button
 ├─ HomePage → FeatureEntryCard / RecentRecordList
 ├─ CompanionPage → SessionToolbar / MessageList / MessageComposer
 └─ SearchPage → SearchBar / ClaimItem / SourceList → SourceCard
公共：AppShell、StatusBadge、InfoNotice、AsyncState、ConfirmDialog、ConsentDialog
```

页面结构现状见 [App.jsx](../../../prototype/src/App.jsx#L13)。`AuthLayout`、`PasswordField` 在 [Account.jsx](../../../prototype/src/pages/Account.jsx#L5) 中为局部组件；聊天、查询和来源多数仍在 [Workspace.jsx](../../../prototype/src/pages/Workspace.jsx#L20) 内联。

登录名使用 `loginName`，昵称为 `nickname`，二者不混用。正式登录名按 NFKC 后 3～64 个 ASCII 字母／数字／下划线校验，统一小写索引；密码不 trim、不规范化，登录校验非空和最多 128 Unicode 码点。**注册／新密码 12～128 的下限不适用于登录校验。**

HTML 登录页中的示例邮箱、“记住我”“忘记密码”不纳入本次正式组件契约。组件不得自行将凭据写入浏览器持久存储。`target` 为上层验证过的页面键，不接受任意 URL。

### 2.3 聊天

| ID／组件 | 原型依据及现状 | 目标 props／事件 | 行为与约束 |
| --- | --- | --- | --- |
| C08 `SessionToolbar` | [CompanionPage 顶部](../../../prototype/src/pages/Workspace.jsx#L24)，拟提取 | mode、activityState、retentionLabel、busy；onSwitch、onEnd、onCancelTask、onManagePrivacy | 显示倾听／梳理等当前模式；结束、停止本次生成和清除记录含义分开；有草稿／任务时切换说明影响与可携带范围 |
| C09 `MessageList` | chat-messages，拟提取 | messages、status、pendingLabel；onRetryMessage、onUseDraft | role=log／aria-live=polite，仅读出新增反馈；用户接近底部时滚动，否则给“有新回复”；初始引导与真实 AI 消息区分 |
| C10 `MessageBubble` | message／bubble，拟提取 | message={id,role,text,deliveryState}、selected、selectable；onRetry、onSelect | role=`user/assistant`；本地初始引导单独渲染；deliveryState 为视图模型，如 pending／sent／failed；不把本地 ID 当服务消息 ID 保存 |
| C11 `MessageComposer` | [chat-composer](../../../prototype/src/pages/Workspace.jsx#L25)，拟提取 | value、codePointLimit、busy、disabled、error、submittedDraft；onChange、onSend、onClear、onCancel | 正文最大 4000 码点；Enter 发送、Shift+Enter 换行，输入法组合时不发送；空／超限／等待时不能重复发送；失败可恢复本次提交快照 |

发送前保留本次正文快照在当前页内存；展示授权范围后才创建任务。等待时允许编辑下一条草稿但禁止并发发送；当前页退出、身份或入口切换时清理草稿、快照及回复。失败时可编辑并重试，不自动补发。正常成功不把“回复已生成”写成“会话已保存”。

`selectedContextIds` 仅使用服务返回的有效消息 ID，最多 20 个，展开正文及所选文本合计最多 12000 码点；组件不私自拼接全历史、账号资料或其他入口内容。当前原型的 500 字限制与模拟消息索引不能作为正式约束或 ID。

`notices` 为适配后的 UI 提示，**不是新增 HTTP 字段**。`sourceIndex`、`expandedIds`、消息 deliveryState 等同样是视图模型。不得向后端强加未定义字段，也不得把持久查询的额外字段当作临时任务返回值。

### 2.5 事件参数与适配约定

以下为目标调用签名；当前 `PasswordField` 等局部实现仍接收 DOM event，提取时由包装层转成值，不能将 DOM event 存进业务状态。

| 事件 | 组件交给上层的数据 | 上层责任 |
| --- | --- | --- |
| PasswordField／MessageComposer／SearchBar 的 `onChange(nextValue)` | 新字符串 | 更新受控 value；按用途校验，不记录正文 |
| AuthForm 的 `onChange(nextValues)`／`onSubmit(values)` | `{loginName,password}` | 执行正式字段校验和登录适配；密码不进入日志与持久状态 |
| MessageComposer 的 `onSend({text})` | 当前提交正文快照 | 加入服务活动／有效 selectedContextIds，取得许可，生成 requestId；组件不自造后台消息 ID |
| SearchBar 的 `onSearch({question})` | 本次问题快照 | 绑定 SEARCH 活动、授权及任务；与随后编辑的草稿分开 |
| FeatureEntryCard 的 `onActivate(targetPage)`／RecentRecordList 的 `onOpen(recordId)` | 受控页面键／记录 ID | 校验入口能力或读取本人记录，不接收任意跳转 URL |
| ClaimItem 的 `onLocateSource(sourceId)`／SourceCard 的 `onToggle(sourceId)`、`onOpen(sourceId)` | 当前结果中的来源 ID | 按当前 sourceIndex 定位、展开或打开对应合法 URL，不信任事件携带的任意外链 |
| MessageBubble 的 `onRetry(messageId)`／`onSelect(messageId,selected)` | 视图消息 ID／选择值 | 重试时核实对应请求；保存选择时映射到真实服务消息 ID |
| ConfirmDialog／ConsentDialog 的 `onConfirm()`、`onCancel()`，通用 `onRetry()` | 针对当前受控视图的明确意图 | 读取冻结的确认范围，处理请求及回执；范围变化先更新预览与许可，不能使用旧确认 |

## 3. 来源与不确定性的逐条展示

正式查询任务的 `result` 以 [09 号规范第 5 节](../../第三次作业_张王昊/09_全功能接口与限制规范.md#5-req03-信息查询) 为准：

```js
// 目标 HTTP result 的结构示意，省略任务信封；不是演示数据或已接通接口。
{
  searchState: 'SUCCESS', // 或 EMPTY
  claims: [{ id, summary, sourceIds }],
  sources: [{ id, title, url, publishedAt, retrievedAt, quality }],
  hasConflict: false,
  partial: false
}
```

1. 先以 sources 顺序建立当前结果的 `[1]...[n]` 编号，再按 claim.sourceIds 建立引用；不同结果之间不沿用编号或来源缓存。每条摘要最多 1000 码点，最多 10 条摘要、10 个来源。
2. 摘要下提供“依据：[1] [2]”；选中编号后展开并定位相应来源卡，给予短暂边框强调和可达焦点。移动端来源卡放在摘要之后，不强制左右双栏。
3. 每张来源卡显示标题、可核查链接、发布时间和获取时间。publishedAt=null 显示“发布时间未知”；retrievedAt 标为“获取时间”，不能写成更新时间。无机构名字段时不虚构“发布机构”。
4. quality 为 CURRENT／STALE／UNKNOWN，对应“时效正常／可能过时／时效未知”；它不代表事实真伪或权威评分。来源过时／未知时，在该卡及引用它的摘要旁提示相应限制。
5. hasConflict=true 时显示结果级“资料存在冲突，请分别核对来源”；partial=true 时显示“部分检索未完成，当前仅展示已取得资料”。当前 DTO 不提供冲突来源 ID 或对立主张对，不能随意把某两条来源标成相互矛盾。需要更细粒度提示时先由接口负责人扩展契约。
6. 缺失引用、重复／未知来源 ID、非法链接或字段不符时，适配层登记为脱敏契约问题；有问题的摘要不得冒充已核验。若没有可核查来源，显示资料不足或异常并禁用保存；sources 为空时结果只能是 EMPTY，执行失败不能变成 EMPTY。
7. URL 格式可在本地校验，但不能凭格式合法推断链接可访问。真实不可访问信息须来自可核对的服务结果或用户反馈，当前 DTO 无可访问性字段时不自行制造检测结论。
8. 保存按钮仅在 SUCCESS、至少一项可核查来源、结果仍有效且具备登录／SAVE 许可时允许提交。客户端只交 `{searchRequestId}`，不上传自造 claims／sources；失败保持当前临时结果，不新增“已保存”记录。

## 4. 视觉、布局与可访问性

### 4.1 颜色与样式目标

HTML 默认 [theme.css](../../../web-prototype/theme.css#L1) 为柔粉主题，React [style.css](../../../prototype/src/style.css#L1) 仍为绿色。下表记录组件交接目标，尚未迁移 React 样式；不表示全局主题已统一。

| token | 目标值／用途 | 使用要求 |
| --- | --- | --- |
| brand | `#C86B8C`，品牌强调 | 主要用于图标、选中边框与装饰；不默认用于白字小号正文背景 |
| brandStrong | `#984762`，主操作与深色强调 | 主按钮候选；对比度须在实际字号、状态和背景下核对后验收 |
| brandSoft／brandLine | `#F9EAF0`／`#EBCBD8` | 少量选中／提示与边界，避免所有卡片都铺粉色底 |
| pageBg／surface | `#FDF5F8`／`#FFFFFF` | 页面与卡片底色，优先用间距区分区域 |
| textPrimary／textSecondary | `#243B39`／`#526361`，交接建议 | 保证长文可读；灰色说明同样需检查对比度 |
| focus | 深粉实线 3px，offset 2px，交接目标 | 不仅用淡粉阴影提示焦点；错误、焦点与选中各有文字／形状辅助 |

字号与尺寸为目标规格：页面标题 28～32px，区域标题 20～24px，正文 16px，辅助说明 14px；正文行高 1.5～1.7。间距采用 4／8／12／16／24／32px，卡片圆角 12px、控件 8px；按钮和输入建议最小高度 44px，图标 20～24px。沿用 React 的 lucide-react 图标，语义统一，不混用两套风格图标。

这些值用于接入后的可读性核对，未宣称当前演示已满足 WCAG 或完成对比度测量。目标为普通文字至少 4.5:1、控件边界／焦点等关键非文字至少 3:1，并在实现后核对。

### 4.2 响应式与键盘

- 沿用现有 React 760px 移动断点作为接入参考：窄屏隐藏固定侧栏、提供可达的菜单；核心卡片、来源与表单改为单列，正文不横向裁切。
- 不继承聊天区固定 330px 作为所有设备的最终高度；输入区保持可见，兼顾屏幕键盘，长消息可换行，来源 URL 可断行。
- 所有表单有显式 label；错误文字与字段关联；状态更新用 status／alert 的合适优先级，避免每秒轮询都重复播报。
- 对话框进入后聚焦有效控制，Tab 不逃出，关闭后恢复触发位置；取消不触发保存、结束或授权。确认进行中可阻止重复提交；若请求结果未知，不通过关闭弹窗假称已经取消服务操作。
- 消息选择使用可访问的复选框；来源引用与展开有 aria-controls／aria-expanded；装饰性图标对读屏隐藏。
- 支持减少动态效果；加载骨架不闪烁；查看旧消息时不强制跳到底部；模式切换后的标题或状态可被键盘用户定位。

## 5. 四类状态与数据约定

1. `normal/loading/empty/error` 是区域展示状态，分别代表可用、处理中、确认无内容和处理失败；初始未查询可作为 empty 的 idle 子态，但不得当作服务已返回 EMPTY。
2. API 任务状态单独保存：pending／running 映射 loading；completed 后按结果映射 normal 或 empty；failed 映射 error；cancelled／expired 使用明确文案与恢复操作，不塞进“无结果”。HTTP 200 轮询到 failed 仍是任务失败。
3. 错误视图模型建议为 `{kind,message,fieldErrors?,retryAfterSeconds?,retryable}`；它由正式错误信封映射而来，不渲染供应商异常、堆栈、凭据、SQL 或用户正文。
4. 所有正文计数用 `Array.from(text).length` 的 Unicode 码点语义；原生 maxLength 的 UTF-16 计数不能作为唯一约束。不得静默截断密码、认可表达或上下文。
5. 草稿与任务结果仅保存在当前身份、入口、会话／活动的内存范围；不写 URL、localStorage、sessionStorage、分析日志或崩溃附件。退出、换账号或结束时清理引用与轮询，服务端仍须独立校验归属。
6. AbortController 只停止客户端等待，不能证明服务端取消；取消有明确接口回执，回执前先阻断旧结果渲染。接入容器按 requestId、sessionId、activityId 及双代次核对回填。
7. 保存偏好不是 SAVE 许可；用户同意外发也不代表同意保存。来源默认临时，历史列表只来自主动保存的记录。
