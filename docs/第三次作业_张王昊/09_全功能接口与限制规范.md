# 全功能接口与限制规范

版本：v1.0；日期：2026-10-19；统筹：张王昊；接口整合：李泉毅。依据功能总览v0.3、UML v1.1和本包03号最新基线。本文件是本轮可交接的设计契约，不表示已经存在API、数据库迁移或Electron客户端。17项需求全部覆盖，开发人员按职责实施并复核。

## 1. 全局协议与技术约束

### 1.1 调用与存储

Web/桌宠适配→Express应用API→应用服务→受限Agent/LangChain或pg仓储。JavaScript ESM；前后端复用`shared/contracts/*.js`中的Zod规则，服务端采用严格对象Schema拒绝未知字段。校验成功仅表示结构合法，仍须检查身份、归属、入口、用途及版本。SQL参数使用pg参数化查询；事务内操作使用同一连接，禁止用连接池的多次随机连接拼接事务。

本规范路径统一以`/api`开头；前端同源访问。第一阶段实际开放WEB适配，DESKTOP/WECHAT在相应身份与入口绑定验证前标SIMULATED/UNAVAILABLE，不能通过`entry`请求字段或`X-Entry`头启用。入口由受控接入适配及其签发会话确定，服务检查会话绑定，不把User-Agent、Origin或设备自报值当成可信平台证明。Electron验证阶段只使用合成数据和本地演示。

登录会话、账号、资料、主动保存记录存PostgreSQL。业务会话、当前消息、AI任务、临时授权默认仅进程内存，服务重启后失效，客户端显示“临时会话已失效，请重新开始”，不得自动重发正文。当前采用单实例应用服务；扩容前另行设计任务归属、取消广播和共享限额。

### 1.2 通用类型与限制

| 类型/参数 | 本轮采用的限制 | 校验与行为 |
|---|---|---|
| id / requestId | 合法非全零UUID | requestId为客户端操作幂等标识，业务实体ID由服务端分配；知道ID不等于有访问权 |
| loginName | NFKC后3～64个ASCII字母/数字/下划线，统一小写索引 | 页面使用同一标准化规则；昵称与登录标识分开 |
| password / newPassword | 12～128个Unicode码点 | 不trim、不做Unicode规范化；注册/改密使用此限制；登录只校验非空及上限，账户验证后续如支持旧密码须单列迁移策略 |
| nickname / bio / title | 1～32 / 0～200 / 1～80码点 | 文本字段可trim；标题不能全空；bio纯文本，不接受HTML |
| selectedText / event / body | 每字段最多4000码点 | selectedText可空仅限还有有效选定上下文；寄存body非空；计数用`Array.from(text).length`的码点语义 |
| selectedContextIds | 0～20个当前任务消息ID，不重复 | 消息+选定正文/物件/场景合计最多12000码点；包括服务端展开内容；凭据/system提示不计作用户字段但仍计入模型窗口预算 |
| expectedVersion | 正整数 | 更新/清除与当前版本一致才提交；生成代次用非负整数，两个字段不得混用 |
| emotionWords / intensity | 1～5个不重复情绪词，每词1～20码点；强度整数1～5 | 是记录标尺，不作诊断评分 |
| date / instant | YYYY-MM-DD / 带偏移ISO8601时刻 | 严格校验真实日期；时刻存UTC，用户时区单独指定；不按浏览器UTC日期替代用户日历日 |
| 分页 | limit默认20，最大50；cursor为不透明游标 | 固定按createdAt与id排序；游标绑定账号、入口、类型及过滤条件，禁止跨范围复用 |
| HTTP正文 | application/json，最大128 KiB | 超出413；请求URL只含非正文参数，问题/聊天不放URL；禁止上传任意文件/自定义头像 |

4000码点是字段限制，不能替代模型token预算。模型适配层还须检查实际模型窗口，必要时返回参数错误并请用户缩小选择，不擅自裁掉用户认可表达或跨入口找补上下文。所有数字是初始设计配置，非实测性能。

### 1.3 鉴权、错误与缓存

会话Cookie：`__Host-session`，HttpOnly、Secure、SameSite=Lax、Path=/、不设置Domain；仅保存原始随机凭据。服务端保存其摘要。游客建立短时匿名上下文，登录后轮换，游客临时内容不自动迁移。

GET `/api/auth/context`创建/读取匿名或登录上下文并返回CSRF token，响应no-store；不能返回Cookie原始凭据。所有POST/PUT/PATCH/DELETE都校验会话绑定的CSRF token和允许的Origin；登出/登录后刷新CSRF token。缺少有效登录返回401，游客允许的路径仍须有效匿名上下文。

成功响应统一`{data, meta:{requestId}}`，204没有正文；错误统一`{error:{code,message,fields?,retryAfterSeconds?},meta:{requestId}}`。字段错误只含字段路径和规则，不回显密码、Cookie、选定正文、模型提示或原始堆栈。

| HTTP | 业务code/含义 | 适用处理 |
|---|---|---|
| 400 | INVALID_INPUT | 格式、字段、范围错误；不调用模型/不提交DB |
| 401 | AUTH_REQUIRED | 登录缺失/过期，隐藏私密视图；不把正文放登录跳转 |
| 403 | ACCESS_DENIED | CSRF、用途或明确可告知的权限失败 |
| 404 | NOT_FOUND | 对象不存在或属于他人/其他入口时统一安全响应，服务内部区分原因但不泄露对象存在性 |
| 409 | CONFLICT / INVALID_STATE | 版本不匹配、幂等键不同载荷，或当前状态不允许操作 |
| 413 | INVALID_INPUT | HTTP正文超上限 |
| 429 | RATE_LIMITED | 带Retry-After；不得无限自动重试 |
| 503 | SERVICE_UNAVAILABLE | DB、供应商或服务不可用；不能以空历史代替 |

NOT_FOUND/RATE_LIMITED是对旧六项DomainError枚举的本轮扩展，需同步UML。取消/超时不再增加CANCELLED/TIMEOUT业务错误枚举：已登记任务使用`status=cancelled`或`status=failed,failureReason=TIMEOUT`，GET正常返回状态；尚未登记就失败的请求返回上述HTTP错误。

全部私密及临时任务响应`Cache-Control: no-store`；前端查询缓存仅内存，切换身份/入口/结束时清空；Service Worker和CDN不缓存API正文。禁记请求/响应正文、Cookie、密码及SQL参数；只观测脱敏操作ID、状态、耗时、用量。SQL错误不给客户端回显。

### 1.4 幂等、时限与资源限制

创建/保存/业务动作在body带requestId；同身份+入口+操作+requestId+同规范化载荷重试返回原操作结果，不重新执行；载荷不同409。限速先于昂贵哈希/外部调用执行。AI任务幂等元数据仅内存，进程重启不承诺跨重启幂等。持久记录操作在同一DB事务记录幂等元数据和版本，元数据仅含作用域、载荷摘要、结果ID/版本与状态，不重复保存正文；保留24小时，超过后返回现有记录真实状态，不能复活已清除正文。登录不缓存含令牌响应，退出/改密靠会话撤销与事务保证。

普通API总时限5秒、DB语句初始2秒、事务初始3秒；超时必须取消/回滚或等待已提交事实核实，不以客户端超时断言写入失败，客户端用同requestId核实后显示实际状态。AI/检索总时限30秒，模型maxRetries=0、工具最多3轮；先输入/授权/限额校验再登记。每个登录账号跨会话最多1个运行或排队的外部任务，游客按匿名上下文与IP限额；单实例最多4个并发外部任务、等待队列最多8个；超出429，排队计入30秒。每身份外部任务创建最多10次/分钟（游客另按IP10次/分钟），初始每日成功受理任务上限登录100次、游客20次，服务侧费用硬上限单独配置；拒绝不计费重试循环。轮询每任务每客户端1秒一次、最多1个在途请求，服务端每身份轮询总量最多120次/分钟；结束即停。取消和退出不受AI创建额度阻断，仍做防滥用限频。

## 2. 共享会话、授权和Agent契约

### 2.1 临时业务会话

| 方法/路径 | 输入 | 返回与副作用 | 归属/限制 |
|---|---|---|---|
| POST /api/sessions | {requestId, mode}；mode=LISTEN/ORGANIZE/REHEARSE/SEARCH | 201 {sessionId,activityId,sessionGeneration:0,activityGeneration:0,mode,state:ready} | 游客/登录均可；服务端分配ID，仅当前身份入口可用；无正文持久化 |
| POST /api/sessions/:id/switch | {requestId,targetMode,expectedSessionGeneration,selectedContextIds} | 200 新活动ID及双代次；先校验目标能力，再停止旧活动，按用户选择复制内容 | 跨模式复制不自动外发；新AI任务需新授权；不存在/越权404，代次不符409 |
| POST /api/sessions/:id/actions | {requestId,action,expectedSessionGeneration,expectedActivityGeneration}；action=PAUSE/RESUME/RESTART/FINISH_REHEARSAL/END | 200 当前state和双代次；PAUSE/RESTART/FINISH_REHEARSAL/END失效原请求；RESUME不重放旧请求 | END释放正文及临时授权；RESTART建立新活动；FINISH_REHEARSAL进入仅供选表达的reviewing；本地训练/互动无需逐步请求服务器 |

无活动30分钟过期，业务会话绝对寿命2小时（初始配置），结束/过期立即清理正文；单条任务完成不等于业务会话结束。登录/换账号/改密撤销使旧身份相关业务会话失效。临时状态中允许同业务会话持有多条消息，单次上下文仍受20条/12000码点限制。

### 2.2 用途授权

POST `/api/consents`：`{requestId,purpose,sessionId?,activityId?,sessionGeneration?,activityGeneration?,operation,payload}`。purpose为AI_PROCESS、SEARCH_PROCESS或SAVE；operation限定任务生成、记录创建/更新等白名单。payload采用对应操作的同一严格Schema，不接收任意messages/system；授权界面提交前明确展示外发或保存范围。服务在内存计算规范化载荷摘要，绑定身份、入口、双代次、记录ID及版本，返回201 `{consentId,purpose,expiresAt}`。初始5分钟有效，执行时再校验；载荷或版本变化必须重新取得许可。AI/SEARCH授权可供同一逻辑操作的幂等重试使用，不能用于另一任务。

临时正文仅授权计算时内存使用，授权元数据不含正文；游客授权不落库。SAVE要求有效登录；保存时将必要授权元数据与记录同事务提交。POST `/api/consents/:id/revoke`带requestId，200返回revoked，取消相关在途任务并使未提交的保存许可失效；已保存记录不会因撤销许可隐式清除，用户另行确认清除。

### 2.3 Agent任务（仅LISTEN/ORGANIZE/REHEARSE）

POST `/api/agent/tasks`完整请求：

```json
{
  "requestId": "2f74a372-2e54-4fe7-945a-a7992cf4a06b",
  "sessionId": "53763668-4b04-4e47-a477-2e35c74df1fd",
  "activityId": "8b45a7a2-651b-4d7e-9906-7e3c2bed45b2",
  "sessionGeneration": 0,
  "activityGeneration": 0,
  "mode": "LISTEN",
  "operation": "REPLY",
  "selectedText": "最近小组沟通有些困难，我想先说一说。",
  "selectedContextIds": [],
  "consentId": "791bf819-e50c-4d19-845b-a3e529614abb"
}
```

operation：REPLY、OBJECT_ORGANIZE、REHEARSAL_REPLY、REHEARSAL_SUMMARIZE；与mode严格对应。OBJECT_ORGANIZE限ORGANIZE，指定已保存物件时增加resourceId/resourceVersion；未保存物件使用`objectDraft:{shape,title,description}`，不得同时给两种来源。REHEARSE必须给`simulation:{scene,counterpart,goal,style}`（场景/对象为Title、goal为非空正文、style为Text）；整理时还需`recognizedMessageIds`（当前轮次本人消息ID，1～20个）。REHEARSAL_REPLY/SUMMARIZE均要求REHEARSE；普通REPLY只限LISTEN/ORGANIZE。以上展开的全部文本同受12000码点预算。

201式创建不用于外部生成任务：受理返回202 `{requestId,status:pending,sessionId,activityId,sessionGeneration,activityGeneration}`；客户端轮询GET `/api/agent/tasks/:requestId`。pending/running/completed/cancelled/failed/expired为任务状态；running可内部映射等待/执行，不新增持久表。完成返回200：

```json
{
  "data": {
    "requestId": "2f74a372-2e54-4fe7-945a-a7992cf4a06b",
    "sessionId": "53763668-4b04-4e47-a477-2e35c74df1fd",
    "activityId": "8b45a7a2-651b-4d7e-9906-7e3c2bed45b2",
    "sessionGeneration": 0,
    "activityGeneration": 0,
    "status": "completed",
    "result": {"text": "可以先从最让你为难的那次沟通说起。", "userMessageId": "0eb60921-e60e-4877-bd07-ebcd6597a18b", "replyMessageId": "47451468-4a55-471f-b9fd-e055f4c17c11"}
  },
  "meta": {"requestId": "2f74a372-2e54-4fe7-945a-a7992cf4a06b"}
}
```

生成正文最大4000码点，供应商输出预算另按选定模型配置，结果非字符串、空白、截断或超限均进入失败，不盲目展示。POST `/api/agent/tasks/:requestId/cancel`输入`{requestId:本次取消操作ID}`，200返回目标任务cancelled；已取消重复调用幂等，已完成仍可撤销可取结果并清理任务副本，不撤回已向用户展示的内容。取消服务接受后结果端点不再返回正文；底层未能终止也不得回填。

完成结果可在当前有效业务活动中临时取5分钟；之后状态expired且不含结果，当前会话消息在业务会话结束前可供用户选定保存。明确结束、暂停/重来、换模式、撤销、退出/改密时按受影响代次立即禁止旧任务读取。失败返回`status:failed,failureReason:TIMEOUT/PROVIDER_UNAVAILABLE/OUTPUT_INVALID`，不含供应商原始异常；手动重试用新requestId并重新核验授权与额度。

## 3. REQ01 陪伴交流

使用§2临时会话、授权和Agent任务；mode=LISTEN/ORGANIZE、operation=REPLY。先明确用户希望倾听或整理，输入不明确不强制训练。只传当前有效活动选定消息，无自动读取历史；服务端分配消息ID。未选保存不写聊天表。空输入且无有效上下文400，活动已停止409，未许可外发403，任务故障按§2.3显示失败。验收AT-01：只倾听、拒绝外发、超时和退出后迟到回复四类。主责程群，API李泉毅，UI程杰。

## 4. REQ02 压力缓解小训练

训练定义是随包发布的审阅静态资源`training-definitions.json`，每项有id、title、steps、durationHint、contentVersion；不设置每一步AI接口。端侧`TrainingController.start(id)`、`pause()`、`resume()`、`stop()`、`reset()`返回`{state,stepIndex,elapsedMs}`；仅状态转换有效才推进，不适时立即停止。暂停不累计运行时长，页面隐藏可自动暂停，退出清除定时器。任务拆分如用户需要生成建议，另用ORGANIZE+REPLY并取得AI许可；没有模型不影响固定训练。AT-02：未开始零推进，暂停冻结，退出零新事件。程群内容/路由，程杰实现。

## 5. REQ03 信息查询

查询独立于旧AIRequest三种mode：SEARCH业务会话调用POST `/api/search/tasks`，输入`{requestId,sessionId,activityId,sessionGeneration,activityGeneration,question,selectedContextIds,consentId}`；question为NonEmptyText，需SEARCH_PROCESS许可，明确其中是否包含模型整理外发（使用模型时同时要求AI_PROCESS许可，通过另加aiConsentId引用）。受理202，GET `/api/search/tasks/:requestId`和POST同路径`/cancel`沿用任务状态/取消/30秒与额度规则。不把SEARCH塞入原AIClient mode枚举。

完成`result:{searchState,claims,sources,hasConflict}`；searchState为SUCCESS或EMPTY；claims每项`{id,summary,sourceIds}`，sources每项`{id,title,url,publishedAt:null或instant,retrievedAt,quality}`，quality=CURRENT/STALE/UNKNOWN。最多10个来源、10条摘要，每条摘要最多1000码点。sources为空时只能EMPTY并说明资料不足；来源不可访问、时间不明或冲突明确标记，不伪造时间和链接；检索执行失败是failed，不能EMPTY。

SearchProvider只调用固定供应商端点；用户输入的URL当查询材料，不允许工具任意访问内网/本机/云元数据地址；对必要抓取的URL及每次重定向重新校验协议、解析IP和允许范围。网页文本不改系统规则。查询结果临时使用，本轮不提供独立查询历史保存接口，避免擅自扩展旧SavePayload类型。AT-03逐事实来源核查及空/错/冲突路径。庄剀涵主责、程群整理。

## 6. REQ04 模式切换

网络任务使用§2.1 switch；前端独立`ModeController.switchTo(target,{selectedContextIds})`先校验能力、提示携带范围、停旧训练/音频/物理活动，再切换网络业务会话。服务代次不符409时读取实际状态，不能在失败后复活旧请求。切向纯端侧功能只结束旧网络任务，不把本地正文自动创建为消息。切离REQ14直接清空独立buffer，不提供携带内容选项。AT-04验证未选择不迁移、旧回复丢弃、资源释放、切换失败实际状态。张王昊规则统筹，程杰/程群/李泉毅实现。

## 7. REQ05 会话和记录控制

| 方法/路径 | 输入/返回 | 校验、幂等与副作用 |
|---|---|---|
| POST /api/records | {requestId,kind,payload,consentId}→201 Record | 仅有效登录+SAVE；payload与许可摘要一致；保存主表、子表、授权、幂等元数据同事务 |
| GET /api/records | kind、cursor、limit及类别过滤条件→200 {items,nextCursor} | 本人当前入口；列表只含id/kind/title/createdAt/updatedAt/version及必要非正文状态，不返回全文 |
| GET /api/records/:id | 无body→200 Record | 本人当前入口；不属于当前范围安全404；DB失败503不能假空 |
| PATCH /api/records/:id | {requestId,expectedVersion,payload,consentId}→200 新Record | 不能改kind/owner/entry；SAVE绑定新载荷及原版本；更新版本+1；旧AI授权失效 |
| POST /api/records/:id/clear-confirmations | {requestId,expectedVersion}→201 {confirmationId,expiresAt,recordId,version,kind} | 本人、范围、版本匹配；只签发确认，不清除；2分钟有效 |
| POST /api/records/:id/clear | {requestId,expectedVersion,confirmationId,confirmed:true}→200 {cleared:true,recordId} | 单次确认绑定身份/入口/版本；在事务内清主从数据、关联、授权及清除标记；取消时不发本请求 |

Record=`{id,kind,title,payload,createdAt,updatedAt,version}`；owner/entry由服务使用，不接受客户端指定。kind只有CONVERSATION、EMOTION、WORRY_OBJECT、REHEARSAL_DRAFT、DEPOSIT。CONVERSATION payload=`{title,sessionId,selectedMessageIds}`，1～20条当前身份当前活动消息，快照展开总正文最多12000码点；保存后返回载荷是消息快照，不把请求中的引用当持久消息；首版快照只读，PATCH此类型409。其他payload见各REQ章节。

保存失败保留页面输入；清除失败不显示成功；成功清除后使该对象相关任务、选择引用和前端缓存失效，后续上下文不再访问。用户结束临时会话走§2.1 END，不等于清除已保存记录。AT-05覆盖取消、幂等、跨账号/入口、清除冲突及恢复后不复活。庄剀涵数据、李泉毅API。

## 8. REQ06 多入口及桌宠

GET `/api/capabilities`读取当前可信入口，200 `{entry,features:[{reqId,status,reason?,fallback?}]}`；status=AVAILABLE/SIMULATED/UNAVAILABLE。请求不接受任意entry查询作为授权依据；前端隐藏按钮不能替代服务拒绝。首发WEB全业务页面，REQ13为页面画布；Electron原生桌面浮层必须经验证才AVAILABLE；微信文字销毁只可跳独立本地页面，不能把销毁正文放聊天或跳转参数。

Electron只向渲染层暴露白名单preload桥：`petWindow.move({x,y})`、`setAlwaysOnTop(boolean)`、`setClickThrough(boolean)`、`close()`、`getCapabilities()`；数值为有限整数，移动限制在当前可见工作区，防止窗口拖丢；IPC主进程校验调用窗口和参数。渲染层不启用Node集成，开启contextIsolation与sandbox，不暴露通用invoke/execute/shell/文件读写；固定加载受控界面，阻止任意导航。密钥不在安装包中。点击穿透失效时有可达的退出/恢复入口；具体快捷键由交互验证确定。

Electron先验证Windows透明、置顶、拖动、穿透、缩放、多屏和退出；业务登录接入DESKTOP前单列可信入口/凭据绑定方案并复核，不能复用WEB会话后改个header冒充桌面身份。AT-06包括跨入口不可读和伪造入口拒绝。程杰主责，曾俊涛/关欣复核。

## 9. REQ07 安全与隐私

授权/撤销接口见§2.2；其余为全局服务拦截规则，不额外创建“安全正文上传”接口。普通输入统一参数/归属/入口/用途校验；权限矩阵涵盖游客、本人、他人、同账号其他入口、失效会话。SafetyPolicy检查输入和模型回复；明显危机场景停止常规引导，给出经维护的现实支持文案，不称自动救援；具体资源在部署地区核验。

REQ14页面禁止接入通用会话Context、日志、错误上报和分析SDK；所有用户文本以文本渲染，检索摘要不直接插入任意HTML。Cookie/CSRF、输出转义、SQL参数化、限流、CSP及敏感日志关闭必须在受控部署验证。AT-07用合成越权、注入、会话过期、授权撤销输入；不得使用真实私密数据测试。关欣主责。

## 10. REQ08 情绪与事件日历

复用records，kind=EMOTION，payload=`{date,emotionWords,intensity,event,timeZone}`；event可空，timeZone为服务允许的IANA时区。GET `/api/records?kind=EMOTION&from=YYYY-MM-DD&to=YYYY-MM-DD&...`，单次日期跨度最多366天并分页；返回列表可带date/emotionWords/intensity，不含event正文。允许同日多条，按createdAt排序；不额外创建“每日唯一”约束。详情/修改/清除走通用路径。

游客可本地填写，保存前登录后必须重新主动提交，不自动迁移。保存不能触发AI或趋势分析；无记录为空，失败走错误。AT-08检测保存和回看无模型调用、同日多条和取消不写库。庄剀涵主责。

## 11. REQ09 情绪命名卡

端侧`NamingCard.select({emotionWords,need})`；need=LISTEN/ORGANIZE/SEARCH，返回`{targetMode,emotionWords,requiresQuestion}`，未选need不路由。命名选择不单独上传/落库；需要进入AI或查询时才经§2/§5许可传必要选词。SEARCH缺具体问题先在页面澄清，不能直接把“烦躁”当事实问题去检索。另选“写入日历”进入REQ08编辑页，再主动保存。AT-09无自动日历/历史/分析。程群/郭昱祺负责。

## 12. REQ10 烦恼物件化

端侧形状枚举TANGLE/STONE/NOTE；draft=`{shape,title,description?}`，description允许不填。放旁边仅显示外观，不创建AI任务。保存kind=WORRY_OBJECT，payload=`{shape,title,description?}`；只保存外观时省略description，不能把隐藏文本随包提交。

GET `/api/room`→200 `{id:null或UUID,version:0或正整数,objects:[{recordId,shape,x,y}]}`；要求有效登录，仅本人当前入口；游客只用本地临时房间，不调用持久化接口。无持久房间返回空，失败不能假空。PUT `/api/room`输入`{requestId,expectedVersion,objects}`，200新版本；创建expectedVersion=0、修改匹配现版。objects最多30个，各recordId不得重复且均为本人本入口已保存物件，x/y归一化0～1；清除物件时同事务去除房间关联。移出房间只是取消关联，不清正文。

梳理走OBJECT_ORGANIZE，读取已保存物件必须resourceId+resourceVersion并获AI许可，或使用已授权objectDraft；不可从形状推断原因，不带其他物件。AT-10验证放旁边零模型调用、正文选择、外观与正文分离。程群/程杰、庄剀涵协作。

## 13. REQ11 平行宇宙排练

REHEARSE会话+REHEARSAL_REPLY，必须simulation且清楚展示AI模拟。暂停/继续/重来走§2.1动作；重来建立新活动代次，清掉上轮可选表达。用户点击“结束模拟并整理”执行FINISH_REHEARSAL：停止角色回复、递增活动代次并撤销旧任务/许可，进入reviewing，暂保留本轮本人消息供选择；这不同于END清空会话。reviewing仅允许认可表达选择、REHEARSAL_SUMMARIZE、主动保存、重来或END，不允许继续角色回复。服务端将本人消息与AI消息分别标角色，客户端提交recognizedMessageIds不能包含AI生成但未经本人表达的消息；首版认可范围为本人当前轮次消息。

REHEARSAL_SUMMARIZE只把选定认可表达及必要场景发给模型，不发送整轮对话。生成整理稿是预览，用户可编辑后主动保存；保存kind=REHEARSAL_DRAFT，payload=`{scene,sessionId,activityId,recognizedMessageIds,expressions}`，expressions 1～20条非空文本、总计最多12000码点。服务检查当前认可选择和用户提交确认，不允许自动把未认可建议加入稿件；若改写偏离原意，用户修改/取消，不把模型输出直接当本人认可。

普通记录PATCH编辑稿件需SAVE，不能扩大AI用途；完整排练对话不持久化。AT-11覆盖pause/restart迟到回复、跨轮选ID拒绝、未认可内容不入稿。程群主责、程杰UI。

## 14. REQ12 烦恼寄存

kind=DEPOSIT，payload=`{title,body,reopenAt}`；reopenAt严格晚于当前时刻；records列表只含标题/到期时间/state，不返回body。到期仅STORED→AVAILABLE并递增version，在事务/读取时校正；GET不能把正文放到到期提示中。进程重启按DB时刻重新计算，不依赖浏览器计时。

POST `/api/deposits/:id/retrieve`输入`{requestId,expectedVersion}`→200 `{id,state:RETRIEVED,version,body}`，必须到期且本人主动；未到期409。POST `/api/deposits/:id/postpone`输入`{requestId,expectedVersion,reopenAt}`→200 `{id,state:STORED,version,reopenAt}`，未来时间、乐观锁更新；GET详情对尚未主动取出的条目不返回body（编辑未到期正文首版不开放）；通用records PATCH对DEPOSIT首版拒绝，延期只用postpone；已取出可看正文但不自动发AI。清除仍需确认。AT-12到期不展开、不催促、不AI，延期冲突不覆盖。庄剀涵主责。

## 15. REQ13 屏幕无损发泄

无HTTP敲击事件接口。端侧`ImpactController.start({effect,muted,volume})`、`hit({x,y,strength})`、`pause/resume/reset/stop()`；effect限定预置枚举，volume/strength为0～1，坐标限制视图，最多同时100个视觉粒子、8个音效声部（初始待测上限），达到上限丢弃额外效果而非阻塞事件循环。Web仅画布区域；Electron浮层依REQ06能力验证。退出/Escape释放点击捕获、动画帧、音频和监听，静音立即停止现有声音。AT-13检查系统应用不受影响及退出零新效果。程杰主责。

## 16. REQ14 文字销毁

无HTTP/Agent/仓储接口，也没有“远程销毁”“恢复草稿”“上传正文校验”路径。独立组件内`setBuffer(text)`（最多4000码点）、`destroy(effect)`、`clear()`、`dispose()`；effect=SHRED/BURN/BLACK_HOLE。正文只在视图私有内存，不带账号ID；切换/结束/关闭时清空，跳过动画也清空。销毁页资源本地打包，不依赖第三方脚本/字体/CDN或远程遥测；禁止任何包含正文的请求、日志、URL、持久存储或崩溃附件。

这里的产品功能清空是用户主动操作，不涉及删除工作区文件。仅保证产品控制的数据通路，不承诺操作系统交换文件、输入法或恶意扩展绝对无痕。AT-14使用唯一合成标记检查请求、存储、日志和退出后可访问状态，不将测试正文写入真实业务记录。程杰实现、关欣专项、曾俊涛取证。

## 17. REQ15 禅意编曲弹珠机

无HTTP轨迹/碰撞/音符接口。端侧`MarbleController.configure(layout)`、`release(ball)`、`pause/resume/reset/stop()`和`setMuted(boolean)`；构件类型与音阶仅选预置；layout最多30构件，运行最多10球、同时8音频声部，数值必须有限，碰撞发声同声部间隔至少50ms（初始待测配置）。坐标在画布内；物理单位、质量与速度范围由程杰在统一配置定义并测稳定性，不将UI像素直接声称真实物理单位。暂停停物理和新音符，静音停止现有声音，重置清球，退出销毁循环和音频节点。布局首版临时，不默认保存或跨入口同步。AT-15与设备帧率、CPU、内存条件一起报告，不凭上限数字宣称性能通过。程杰主责。

## 18. REQ16 注册、登录与改密

| 方法/路径 | 输入 | 返回/限制 |
|---|---|---|
| GET /api/auth/context | 无body | 200 {authenticated,csrfToken,expiresAt?}；建立匿名上下文或读取当前身份，不返回原始Cookie |
| POST /api/auth/register | {requestId,loginName,password,confirmPassword} | 201 {accountId}，不自动登录；标准化唯一索引原子检查；密码一致且12～128 |
| POST /api/auth/login | {loginName,password,target} | 200 {profile,target,expiresAt} + Set-Cookie；target为固定页面键，禁止任意跳转URL；凭据错误统一反馈 |
| POST /api/auth/logout | 无正文；CSRF头必需 | 204，撤销当前会话、清Cookie、取消相关临时任务；已退出再次请求安全清Cookie |
| POST /api/auth/change-password | {currentPassword,newPassword,confirmPassword} | 204，校验旧摘要并原子更新；撤销所有旧登录会话和任务，清Cookie；成功后重新登录 |

登录名唯一冲突409，但登录错误不区分不存在账号/错误密码；失败提示不回显凭据。账号和IP分别5次失败/15分钟限速，窗口到期再试，不永久锁账号；注册按IP初始10次/小时，改密按账号5次失败/15分钟。登录成功轮换匿名/旧会话，失效并清理旧临时内容；需要保存游客内容时先由用户在客户端保留选择，登录后再次明确提交，不把旧匿名会话自动认领给账号。

login_sessions字段至少id/account_id/token_digest/entry/device_id/issued_at/last_seen_at/expires_at/revoked_at；token_digest唯一索引，必要account_id与有效状态索引。用node:crypto生成至少32随机字节凭据，存SHA-256摘要，凭据不入JSON、日志和URL；密码Argon2id初始19MiB、迭代2、并行度1及独立随机盐。空闲30分钟、绝对7天，last_seen在服务端校验并按短间隔批量更新，不能依靠客户端延长。批量更新策略不能跳过本次请求的超时判断。

不引入另一套并行express-session状态；AuthService/IdentityRepository统一负责会话。退出记录不清业务记录；备份恢复后所有旧登录会话强制失效，不能将备份里的有效会话直接恢复上线。AT-16覆盖到期、退出、改密、并发改密、错误凭据、数据库重启和旧会话拒绝。李泉毅主责、庄剀涵DDL、关欣审查。

## 20. 实施映射、数据库与验证交接

共享Schema按account、session、agent-task、search-task、consent、record、profile、errors拆文件，前后端都import，Zod严格校验；Schema中不得引入Node专用模块或密钥，凭据摘要和权限核查仅服务端。TypeScript不是前置要求，JS项目使用JSDoc和推断文档辅助开发。

UML更新点：PasswordInput注册/新密码12～128；LocalRecordRepository由PostgresRecordRepository实现替换当前基线；加入AgentApplicationService、LangChainModelAdapter及HTTP DTO映射；PendingRequest保持双代次；业务错误枚举增加NOT_FOUND/RATE_LIMITED；REHEARSE增加FINISH_REHEARSAL→reviewing的应用状态映射（停止模拟但保留当前轮次选择，END才清空）；AIResponse内部仍requestId+text，HTTP任务信封在应用门面包装，不把轮询状态强塞给模型适配器。SEARCH走SearchProvider，引用模型整理时用独立受控模型调用，不改旧AIRequest mode边界。

所有持久业务主表必须带owner与entry（或通过不可绕过的外键归属链确定），查询/更新/清除SQL附带两条件；以id+owner+entry+version原子更新，影响行数不符则安全查明未找到/冲突。保存事务包括主从表、授权和幂等；清除物件包括房间关联。数据库DDL、ER和索引由庄剀涵专业稿定稿，此文件不冒充已执行建表。

仅备份已持久化记录，备份加密保留7天；清除事务生成不含正文的标记，通过事务outbox可靠复制到独立于业务备份的清除日志，至少保留8天且不早于全部受影响备份退出恢复窗口。复制未完成不将旧备份标为可直接恢复；全库恢复后先重放清除日志、校验无遗漏、失效所有旧登录会话再开放。日志缺失/连续性不明时暂停恢复发布。7/8天是设计参数，需要验证备份实际清理及日志容灾，不能只在同一备份里保存清除标记。
