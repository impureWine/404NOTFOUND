| 部署 | 本机开发；交付采用Web静态资源 + Node.js应用API + 私网PostgreSQL；Web/API同源发布，HTTPS接入 | 开发环境便于联调；同源发布简化Cookie和跨域配置；数据库只对应用服务开放。按单实例应用服务部署，与内存任务注册表一致，后续横向扩容须另行设计共享取消状态和任务归属。云资源、域名与区域在部署清单落定。 |

| 备份与恢复 | 仅备份已持久化数据；备份加密，保留7天；恢复前重放备份后清除标记 | 在误操作恢复与保留最小化之间选定短期窗口。清除标记避免恢复时让已清除记录重新可见；恢复验证通过前不向用户开放服务。标记仅保留重放所需的对象标识和时间，不含正文。 |
| 共享契约 | Zod + JavaScript ESM/JSDoc；前后端同源Schema | 统一长度、枚举、请求和响应字段，减少原型与API规则分叉；服务仍独立校验权限，类型验证不替代归属判断。 |
| 数据库驱动与会话 | node-postgres（pg）+ SQL迁移；AuthService统一管理PostgreSQL登录会话 | 与数据库课程设计的SQL/约束/事务对应；复用现有LoginSession，不额外维护一套express-session状态；事务使用同一连接。 |
| 桌宠工程 | Electron主进程 + preload白名单 + React渲染层；W2先做能力验证 | 复用JS/React界面并验证原生窗口；能力验证不等于全部桌宠功能已开发，真实DESKTOP认证接入另列门槛。 |

本轮按上述方案推进，不再将MySQL、SQLite、浏览器直连模型、默认多模型路由或独立微服务作为并列待选项。桌宠采用Electron验证原生浮层能力；微信首轮标明适配/模拟。未验证的能力不标AVAILABLE，不能通过客户端自报entry绕过入口限制。

## 1. 已确定的三项约束与分层

1. 编程语言采用 JavaScript，AI模块使用JS，不引入Python服务作为默认实现；领域类型可通过JSDoc和运行时Schema表达。
2. 使用 LangChain JS 管理模型的初始化、统一调用及供应商适配；不自行训练基础大模型。
3. Agent 接在应用层 API。客户端调用受控应用API，由应用服务调用Agent；模型密钥不下发浏览器。

调用关系：`Web/桌宠/微信适配器 → 应用层API → AgentApplicationService → AIProcessingService/任务编排 → LangChainModelAdapter（实现AIClient）→ 模型供应商`。

其中应用API边界包含可信入口识别、身份/匿名临时会话、输入验证和请求归属绑定。应用服务向下调用授权策略、任务协调器和受控检索接口。数据服务另走 `应用API → RecordService/ProfileService → Repository → 选定存储`。REQ14只有本地TextDestructionView，不接这两条链路。

AgentApplicationService是应用层的AI任务入口；现有AIProcessingService继续承担上下文、安全和响应编排职责。两者在同一应用服务内组织门面与处理器职责，避免重复路由。LangChainModelAdapter确定为现有AIClient的具体实现，新增名称须同步UML图五。

LangChain官方JS文档提供统一模型接口和initChatModel；Agent可组织模型与工具调用。这里仅据此确定模型适配方式，不推定每个业务任务都必须使用自主工具循环。[模型文档](https://docs.langchain.com/oss/javascript/langchain/models)、[Agent文档](https://docs.langchain.com/oss/javascript/langchain/agents)（2026-10-19查阅）。具体包版本、超时单位、可用参数须在供应商确定后按对应版本核验并锁定。

## 2. 功能路由与职责

| 入口任务 | 执行方式 | 可用上下文/能力 | 不得发生 |
|---|---|---|---|
| 倾听/梳理 | 应用服务调用受限Agent任务和LangChain模型 | 当前有效会话内用户选定文本、必要历史、用户选择的目标 | 读取其他入口历史、自动保存、强制训练 |
| 命名卡 | 本地选择加确定性路由；有生成需要才调用模型 | 情绪词及倾听/梳理/查询选择 | 将选词自动当作日历/诊断 |
| 固定训练 | 审阅内容+端侧状态机 | 静态训练定义、开始/暂停/继续 | 每一步强制调用模型 |
| 物件梳理 | 用户主动选中物件并开始后调用AI | 选定物件的必要描述；无描述先询问 | 放旁边自动分析或推断其他物件 |
| 排练/整理 | 明示模拟的独立任务；整理只提交认可表达 | 当前场景、对方角色、当前轮次选定对话；整理仅勾选表达 | 重来混入上轮、保存全量排练 |
| 查资料 | 受控SearchProvider检索，可调用模型整理 | 当前问题、应用层提供的来源对象及sourceId | 伪造来源、把网页指令作为系统规则、任意URL抓取 |
| 日历/寄存/个人资料 | 普通应用服务CRUD | 本人当前入口授权对象 | 默认向模型发送、寄存到期展开分析 |
| 文字销毁/敲击/弹珠 | 纯端侧组件 | 本地输入、动画、物理和音频状态 | REQ14正文进入任何网络/仓储/模型/遥测 |

本轮不授予Agent直接执行SQL、清除记录、改密码、跨入口查询或任意网络请求的工具。若后续确需工具，工具固定调用受控应用服务，服务端重新校验身份与用途；不能以提示词替代授权。

## 3. 应用契约与任务失效规则

以下HTTP路径作为本轮设计契约，由李泉毅、程群、程杰据此实现，不表示线上接口已经存在：

| 接口 | 用途/输入 | 返回/控制 |
|---|---|---|
| POST /api/agent/tasks | {requestId,sessionId,activityId,sessionGeneration,activityGeneration,mode,operation,selectedText,selectedContextIds,consentId}；按操作补simulation、recognizedMessageIds、resourceId/resourceVersion或objectDraft | 202及pending/双代次；模式限定LISTEN/ORGANIZE/REHEARSE；同范围同requestId同载荷幂等，不同载荷冲突 |
| GET /api/agent/tasks/:requestId | 检查当前身份/入口、会话/活动、双代次和授权 | pending/running/completed/cancelled/failed/expired；完成返回双代次及result.text和消息ID |
| POST /api/agent/tasks/:requestId/cancel | {requestId:本次取消操作ID}；校验目标请求归属 | 幂等置cancelled，不再提供正文；底层返回也不得展示 |
| POST /api/search/tasks | SEARCH会话、明确问题、双代次、SEARCH_PROCESS许可；模型整理另需AI_PROCESS许可 | 202；使用独立查询轮询/取消端点；不将SEARCH加入旧AIRequest三模式 |

异步任务注册表仅为服务内存临时状态，服务重启后失效，不为轮询自动落库或缓存正文；登录会话单独存PostgreSQL。游客仅有短时匿名上下文；持久保存必须登录。客户端传来的会话/活动、双代次、消息引用和许可全部待校验，不能据此建立所有权；授权绑定身份、入口、用途、载荷摘要及资源版本。[09号全功能规范](09_全功能接口与限制规范.md)是详细字段/路由/状态的统一来源。

采用的初始限值：单条selectedText最多4000个Unicode码点，最多20条选定上下文、合计12000码点；应用层总时限30秒、模型自动重试0次，工具循环最多3轮；任务结果完成后最多保留5分钟临时可取，退出、撤销或任务失效即不可读取。以上是当前配置基线，非实测性能；程群/曾俊涛须核对模型窗口、预算、并发和内存，发现不适用时记录验证结果并修订配置。计时覆盖检索、工具和模型全过程。失败重试由用户发新requestId，不能叠加多层默认重试。

客户端不自行构造system消息，也不指定模型名、供应商地址或密钥。服务侧固定系统规则，按可信身份和许可构造最小上下文。错误沿用六类并扩展NOT_FOUND/RATE_LIMITED；取消用status=cancelled，超时用status=failed及failureReason=TIMEOUT，不再增加CANCELLED/TIMEOUT业务错误码。HTTP/内部模型返回通过门面映射，具体见09号§1/§2。

每次请求捕获账号/匿名身份、登录会话、入口、业务会话、活动、sessionGeneration、activityGeneration和requestId。暂停、重来、切换模式、退出、改密撤销或换账号时，TaskCoordinator失效相关请求并尝试AbortSignal取消模型/检索；回复、任务读取和每个流片段（若后续采用流式）都重新匹配并校验登录与授权。只在界面忽略旧回复不足以保护数据。

GET结果只对当前有效活动开放；单个任务completed不等于业务会话END，完成结果最多取5分钟，业务结束/暂停/重来/切换/撤销时立即失效。客户端检查双代次；轮询1秒一次、同任务最多1个在途，终态/离开后停止。每账号最多1个外部任务，实例并发4、等待8，超限429；限额/时限/重试及消息临时存续以09号§1/§2为准。后续流式须另补片段授权和中途错误设计。

## 4. 数据、授权与模型管理边界

- 用户选择任务、允许AI外发、允许保存是三种独立动作。选定记录时再次检查owner+entry+对象版本；已保存不等于允许发给模型。
- 默认会话和模型结果在当前任务临时内存中，未主动保存不写DB、浏览器持久存储或模型追踪平台。主动保存走RecordService及单独SAVE许可，不能由Agent推断同意。
- 禁止将密码、令牌、其他记录正文、未选物件、日历、寄存和文字销毁内容混入上下文。排练整理仅取当前轮次用户勾选认可的表达。
- 供应商可替换配置包括模型标识、适配包、凭据、超时、重试、输出上限、费用/并发上限；只从受控服务环境读取。具体供应商、模型、预算、留存政策和外发告知文本待确认，禁止写入真实密钥。
- 默认不启用会收集正文的LangSmith/第三方追踪、持久记忆或checkpointer。观测只记脱敏请求编号、状态、耗时、错误类别及必要用量，不记正文和认证信息。
- 来源由SearchProvider提供并按sourceId绑定，生成内容引用不存在的sourceId时返回校验失败/资料不足，不伪造URL。外部文本作为不可信资料，不能修改权限或系统规则。
- 模型不可用时提示当前服务失败，可返回到固定训练/继续本地输入；预设演示明确标为模拟，不冒充实时回复。
