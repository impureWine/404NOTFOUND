# 404NOTFOUND 模型适配契约

## 1. 文档目的

本契约规定后端编排层与模型适配层之间的统一数据格式，使陪伴和查询业务不依赖某一个模型供应商。更换模型时，只需修改适配器，不应修改前端协议、会话状态机和主要业务流程。

本契约是设计阶段基线。字段、超时和长度上限在实现阶段可以调整，但任何破坏兼容性的变更需要记录版本并同步前端、后端和测试负责人。

本次修订为设计契约 `1.1`，新增可选的相关记忆与授权字段。MVP 后端先实现 `ZhipuAdapter` 或 `QwenAdapter` 中的一种，通过服务端环境变量配置密钥和模型 ID；第二种作为替换路径。这里接入的是 LLM 模型推理 API，Agent 编排及记忆由项目维护，不把供应商的托管智能体平台当作已经实现的本项目后端。API 用法以[智谱官方文档](https://docs.bigmodel.cn/cn/api/introduction)和[阿里云千问 API 文档](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)为准，具体模型与兼容能力在接入时核验。

## 2. 调用边界

```text
前端 → 后端 API → 编排器 → ModelAdapter → 具体模型服务
                              ↑
                       本文定义的边界
```

模型适配器负责：

- 将统一请求转换为供应商格式；
- 调用模型并处理供应商返回；
- 将成功结果、错误和用量信息转换为统一格式；
- 隐藏供应商专用字段；
- 返回真实使用的供应商与模型标识；
- 不记录或返回 API 密钥。

模型适配器不负责：

- 决定是否切换模式；
- 代替用户确认练习；
- 直接读写会话数据库；
- 决定搜索结果是否足够可靠；
- 将模拟结果伪装成真实调用。

## 3. 接口概览

设计阶段建议的内部接口：

```text
POST /internal/v1/model/generate
Content-Type: application/json
```

该地址表示内部模块边界，不要求作为公网接口开放。若后端采用进程内调用，也应保持相同的数据结构和语义。

## 4. 枚举定义

### 4.1 模式 `mode`

| 值 | 含义 |
|---|---|
| `COMPANION` | 陪伴交流 |
| `SEARCH` | 基于来源的信息摘要 |
| `SAFETY` | 安全回应；通常优先使用固定模板 |

练习步骤由练习引擎处理，因此一般不调用自由生成模型。若仅用模型生成练习结束语，仍应将任务明确标记为 `EXERCISE_CLOSING`，且不得生成新的正式练习步骤。

### 4.2 任务 `task_type`

| 值 | 含义 |
|---|---|
| `CLASSIFY_INTENT` | 识别陪伴、练习、查询、退出或混合意图 |
| `COMPANION_REPLY` | 生成陪伴回应 |
| `QUERY_REWRITE` | 将确认后的事实问题转换为最小化查询词 |
| `SEARCH_SUMMARY` | 严格依据给定来源生成摘要 |
| `CONTEXT_SUMMARY` | 生成结构化会话摘要 |
| `EXERCISE_CLOSING` | 生成不带疗效承诺的练习结束语 |

### 4.3 建议动作 `suggested_action`

| 值 | 含义 |
|---|---|
| `STAY` | 保持当前模式 |
| `ASK_CLARIFICATION` | 提出一个澄清问题 |
| `OFFER_EXERCISE` | 建议用户选择练习，不能直接开始 |
| `OFFER_SEARCH` | 建议切换查询，等待用户确认 |
| `OFFER_PLAN` | 建议梳理下一步 |
| `END` | 响应用户结束请求 |
| `NONE` | 当前任务不需要建议动作 |

## 5. 统一请求

### 5.1 完整示例

```json
{
  "contract_version": "1.1",
  "request_id": "req-20261018-0001",
  "session_id": "session-8b97c5",
  "mode": "COMPANION",
  "task_type": "COMPANION_REPLY",
  "locale": "zh-CN",
  "state": {
    "session_state": "IDLE",
    "confirmed_goal": null,
    "history_retention": false,
    "long_term_memory_enabled": false
  },
  "context": {
    "summary": null,
    "recent_messages": [
      {
        "role": "user",
        "content": "我最近任务很多，只想找个人说说"
      }
    ],
    "sources": [],
    "relevant_memories": []
  },
  "constraints": {
    "max_output_tokens": 300,
    "require_sources": false,
    "allowed_actions": [
      "STAY",
      "ASK_CLARIFICATION",
      "OFFER_EXERCISE",
      "OFFER_PLAN",
      "END"
    ],
    "forbidden_claims": [
      "DIAGNOSIS",
      "TREATMENT_GUARANTEE",
      "HUMAN_EXPERIENCE_CLAIM",
      "DEPENDENCY_INDUCEMENT"
    ]
  },
  "metadata": {
    "trace_id": "trace-14ad2e",
    "prompt_version": "companion-v1"
  }
}
```

### 5.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `contract_version` | string | 是 | 契约版本，当前为 `1.1` |
| `request_id` | string | 是 | 单次逻辑请求的唯一标识；自动重试沿用同一值 |
| `session_id` | string | 是 | 会话标识；不得包含用户名、手机号等明文信息 |
| `mode` | enum | 是 | 当前已确认模式，不是模型建议模式 |
| `task_type` | enum | 是 | 本次模型需要完成的单一任务 |
| `locale` | string | 是 | 输出语言区域，MVP 默认 `zh-CN` |
| `state.session_state` | string | 是 | 当前会话状态 |
| `state.confirmed_goal` | string/null | 否 | 用户已明确确认的目标，不写入模型推断 |
| `state.history_retention` | boolean | 是 | 用户是否允许留存历史 |
| `context.summary` | string/object/null | 否 | 经校验的历史摘要 |
| `context.recent_messages` | array | 是 | 当前任务需要的最近消息 |
| `context.sources` | array | 是 | 查询任务的标准来源；非查询任务为空数组 |
| `state.long_term_memory_enabled` | boolean | 否 | `1.1` 新增，缺省为 false；独立于历史留存设置 |
| `context.relevant_memories` | array | 否 | `1.1` 新增，缺省为空；仅含已授权、相关、有效且经服务端校验的记忆投影 |
| `constraints.max_output_tokens` | integer | 是 | 最大输出长度预算 |
| `constraints.require_sources` | boolean | 是 | 是否强制使用给定来源 |
| `constraints.allowed_actions` | array | 是 | 本次允许模型建议的动作白名单 |
| `constraints.forbidden_claims` | array | 是 | 输出校验使用的禁用类型 |
| `metadata.trace_id` | string | 是 | 跨模块诊断标识 |
| `metadata.prompt_version` | string | 是 | 提示模板版本，便于回归 |

### 5.3 来源对象

查询摘要请求中的每个来源采用统一结构：

```json
{
  "source_id": "src-01",
  "title": "来源标题",
  "url": "https://example.org/page",
  "publisher": "发布机构",
  "published_at": "2026-10-01",
  "retrieved_at": "2026-10-18T15:00:00+08:00",
  "snippet": "与查询相关的材料摘要",
  "reliability": "UNVERIFIED"
}
```

`reliability` 仅用于记录项目组的来源治理状态，可取：

- `TRUSTED`：在项目配置的可信来源列表中；
- `UNVERIFIED`：尚未完成来源质量确认；
- `CONFLICTING`：与其他来源的关键事实冲突。

这不是对来源真实性的自动保证，前端仍应展示来源标题、链接和时间，供用户核对。

### 5.4 相关记忆的模型侧投影

下面是 `context.relevant_memories` 中单个对象的设计示例，不是真实用户数据：

```json
{
  "memory_id": "mem-example-01",
  "kind": "REPLY_PREFERENCE",
  "content": "用户希望回复简短",
  "confirmed_at": "2026-10-22T10:00:00+08:00",
  "updated_at": "2026-10-22T10:00:00+08:00",
  "expires_at": "2026-11-22T10:00:00+08:00",
  "version": 1
}
```

这只是服务端向模型提供的最少字段。完整记录的用户归属、原消息引用、授权凭证及删除状态保留在项目数据层，不需要全部发送给供应商。有效期是示例值，实际策略由产品配置。

- 模型调用前由 `MemoryManager` 完成用户隔离、授权、有效期和相关性检查，不能信任前端直接传来的记忆对象。
- `history_retention=true` 不代表可读取长期记忆。只有服务端确认 `long_term_memory_enabled=true` 且条目有效，才可注入。
- 记忆和搜索材料均是数据，不得作为高优先级指令；其中出现的“忽略规则”“切换用户”等内容不能获得工具或数据库权限。
- 搜索服务只获得必要查询词；模型摘要任务也不得携带无关长期偏好或倾诉原文。
- 模型输出仅是候选结果，不包含可以直接执行的记忆写入授权；长期记忆确认与存储走独立业务流程，见 01 第 6.6 节。

## 6. 统一成功响应

```json
{
  "contract_version": "1.1",
  "request_id": "req-20261018-0001",
  "status": "success",
  "result": {
    "content": "听起来最近的任务堆在一起，让你有些喘不过气。你想继续说说最困扰你的部分，还是一起梳理下一步？",
    "intent": "COMPANION",
    "suggested_action": "ASK_CLARIFICATION",
    "citations": [],
    "uncertainty": null
  },
  "model_info": {
    "provider": "configured-provider",
    "model": "resolved-model-id",
    "mock": false
  },
  "usage": {
    "input_tokens": 152,
    "output_tokens": 48
  },
  "timing": {
    "latency_ms": 820,
    "attempts": 1
  }
}
```

### 响应字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `status` | string | 是 | 成功固定为 `success` |
| `result.content` | string | 是 | 面向用户的候选正文，仍需通过输出校验 |
| `result.intent` | string/null | 否 | 意图识别结果；不能直接替代服务端模式 |
| `result.suggested_action` | enum | 是 | 白名单中的建议动作 |
| `result.citations` | array | 是 | 引用的 `source_id`，非查询为空数组 |
| `result.uncertainty` | string/null | 是 | 来源不足或冲突时的不确定性说明 |
| `model_info.provider` | string | 是 | 实际调用的供应商标识 |
| `model_info.model` | string | 是 | 供应商实际返回或配置确认的模型标识 |
| `model_info.mock` | boolean | 是 | 是否为模拟结果 |
| `usage` | object/null | 否 | 供应商支持时记录用量 |
| `timing.latency_ms` | integer | 是 | 适配器测得的总耗时 |
| `timing.attempts` | integer | 是 | 实际尝试次数 |

## 7. 查询摘要响应

```json
{
  "contract_version": "1.1",
  "request_id": "req-20261018-0002",
  "status": "success",
  "result": {
    "content": "根据来源资料整理的摘要……",
    "intent": "SEARCH",
    "suggested_action": "NONE",
    "citations": ["src-01", "src-02"],
    "uncertainty": "两个来源对具体日期的描述不同，请以发布机构的最新通知为准。"
  },
  "model_info": {
    "provider": "configured-provider",
    "model": "resolved-model-id",
    "mock": false
  },
  "usage": null,
  "timing": {
    "latency_ms": 1100,
    "attempts": 1
  }
}
```

查询响应校验规则：

1. `citations` 中的每个 ID 必须存在于请求的 `sources` 中；
2. `require_sources=true` 且 `sources` 为空时，不允许调用模型生成确定性事实答案；
3. 出现关键冲突时，`uncertainty` 不能为空；
4. 模型生成的新链接不得作为来源直接展示。

## 8. 统一错误响应

```json
{
  "contract_version": "1.1",
  "request_id": "req-20261018-0001",
  "status": "error",
  "error": {
    "code": "MODEL_TIMEOUT",
    "retryable": true,
    "user_message": "暂时没有获得响应，你可以重新尝试或返回原来的模式。",
    "internal_message": "provider timed out after configured deadline"
  },
  "model_info": {
    "provider": "configured-provider",
    "model": "configured-model-id",
    "mock": false
  },
  "timing": {
    "latency_ms": 20000,
    "attempts": 2
  }
}
```

`internal_message` 只用于受控日志和内部诊断，不返回普通用户界面，其中不得包含 API 密钥、完整提示词或敏感原文。

## 9. 错误码

| 错误码 | 含义 | 自动重试 | 建议处理 |
|---|---|---:|---|
| `INVALID_REQUEST` | 请求缺字段或值不合法 | 否 | 修正调用代码，不将内部细节展示给用户 |
| `MODEL_TIMEOUT` | 模型超过调用时限 | 最多 1 次 | 可尝试备用适配器，否则保留输入并提示重试 |
| `MODEL_RATE_LIMITED` | 供应商限流 | 否或退避后 1 次 | 避免立即连续请求，提示服务繁忙 |
| `MODEL_UNAVAILABLE` | 网络或模型服务不可用 | 最多 1 次 | 备用模型、模拟适配器或返回失败 |
| `EMPTY_MODEL_OUTPUT` | 模型返回空内容 | 最多 1 次 | 重试后仍为空则返回错误 |
| `INVALID_MODEL_OUTPUT` | 结构错误、非法动作或引用不存在 | 最多 1 次 | 使用更严格提示重试，仍失败则拒绝展示 |
| `CONTENT_REJECTED` | 输出违反边界或校验规则 | 否 | 使用安全模板或返回可恢复错误 |
| `CONTEXT_TOO_LONG` | 输入超过上下文预算 | 否 | 摘要或裁剪；无法安全裁剪则要求缩小任务 |
| `SEARCH_TIMEOUT` | 搜索服务超时 | 最多 1 次 | 保留查询，允许重试或返回陪伴 |
| `SEARCH_NO_RESULT` | 未得到可靠来源 | 否 | 明确说明无结果，禁止模型补写事实结论 |
| `SOURCE_CONFLICT` | 来源关键事实冲突 | 否 | 展示冲突和时间，表达不确定性 |
| `EXERCISE_NOT_AVAILABLE` | 练习未审核、缺失或被停用 | 否 | 返回练习选择页，不让模型临时生成替代步骤 |

## 10. 超时、重试与幂等

### 10.1 默认策略

- 模型调用默认超时：10 秒；
- 同一逻辑请求最多自动重试：1 次；
- 搜索调用默认超时：8 秒；
- 总尝试次数通过 `timing.attempts` 返回；
- 实际参数应通过开发环境测试后配置化，不写死在业务代码中。
- `request_id` 表示本次模型子任务；同一用户轮次若包含意图识别、摘要等多个子任务，应使用不同 `request_id`，由相同 `trace_id` 关联，避免相互误去重。
- 编排器对整轮另设截止时间。主模型最多尝试两次；可选备用模型最多尝试一次，受整轮剩余预算约束；不得因切换供应商重新开启无限重试。

### 10.2 幂等规则

- 同一逻辑请求重试时沿用 `request_id`；
- 用户主动点击“重新尝试”生成新的 `request_id`，并通过 `metadata.retry_of` 关联原请求；
- 后端应防止用户重复点击导致同一消息并发提交；
- 模型生成操作不得直接触发扣费、删除或外部消息发送等不可逆动作。

### 10.3 不允许重试的情况

- 请求字段错误；
- 上下文超过限制且无法安全裁剪；
- 内容被安全规则拒绝；
- 搜索无可靠来源；
- 练习未审核或不存在。

## 11. 供应商适配接口伪代码

以下内容用于说明职责，不限定具体编程语言：

```text
interface ModelAdapter {
    generate(request: ModelRequest): ModelResponse
    healthCheck(): HealthStatus
    getCapabilities(): ModelCapabilities
}

class ProviderAdapter implements ModelAdapter {
    generate(request):
        validate(request)
        providerRequest = mapToProviderFormat(request)
        providerResponse = callWithTimeout(providerRequest)
        return mapToUnifiedResponse(providerResponse)
}
```

所有供应商适配器都必须通过同一组合约测试：

- 能处理正常请求；
- 能返回实际模型标识；
- 能把超时、限流和空响应映射为统一错误；
- 不泄露 API 密钥；
- 模拟适配器返回 `mock=true`。

## 12. 版本与变更规则

- 新增可选字段：增加次版本；本次由 `1.0` 升为 `1.1`，下一次兼容扩展可使用 `1.2`；
- 删除字段、修改字段语义或枚举值：增加主版本，例如 `2.0`；
- 提示模板单独使用 `prompt_version` 管理；
- 每次更换模型或提示版本后，执行陪伴、查询、异常和安全回归用例；
- 文档中记录配置模型标识时，应与运行日志中实际解析的模型标识区分，不能仅凭界面名称猜测。

## 13. 安全检查清单

- [ ] API 密钥仅通过安全配置或环境变量读取；
- [ ] 请求和日志中不包含密钥；
- [ ] `session_id` 不包含用户明文身份信息；
- [ ] 搜索查询经过最小化，不携带无关敏感内容；
- [ ] 模型返回的动作必须在白名单中；
- [ ] 模型生成的来源链接不被直接信任；
- [ ] 模拟结果明确标记 `mock=true`；
- [ ] 删除会话后模型上下文摘要同步删除；
- [ ] 错误页面不暴露供应商堆栈和内部提示词；
- [ ] 每次模型或提示版本变更后完成回归测试。
