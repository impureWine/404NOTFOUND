## 关键设计结论

1. 大语言模型负责语言理解与生成，不直接控制关键业务状态。
2. 当前模式、练习进度、用户确认、安全路径和失败回退由确定性程序控制。
3. 系统不在无提示的情况下切换模式；混合意图先让用户选择优先处理方向。
4. 查询模式只携带完成查询所需的信息，不把无关敏感对话发送给搜索服务。
5. 练习内容来自项目组审核后的配置，不由模型临时自由生成。
6. 明显危机表达优先进入固定安全路径；系统不作诊断、风险评分或救援承诺。
7. 无可靠来源、接口超时或结果冲突时明确表达不确定性，不伪造成功结果。
8. 模型调用使用统一适配契约，后端业务不绑定单一供应商。
9. 基础语言能力由智谱或通义千问 API 提供；团队实现任务编排、记忆、工具执行、校验与评测。提示词、RAG 和记忆管理均不等于训练模型参数。
10. 项目差异体现在日常支持场景的完整业务流程及可测试约束，不能用“其他产品没有记忆或搜索”作为差异化依据。
