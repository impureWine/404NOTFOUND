## 5. 模块职责与领域结构

- `AuthService` / `ProfileService`：注册、登录、退出、改密、资料与偏好。
- `TaskCoordinator`：创建会话、切换活动、登记请求、取消并拦截迟到结果。
- `AgentApplicationService`：承接 HTTP 任务信封，统一受理、轮询和取消。
- `AIProcessingService`：按许可构造最小上下文，执行安全策略并调用 `AIClient`。
- `RecordService` / `RoomService`：保存、读取、更新、清除及房间关联。
- `AuthorizationPolicy` / `SafetyPolicy`：校验账号、入口、对象版本、用途许可与回复边界。
- `IdempotencyService`：登记持久写请求、比对载荷摘要并返回已提交结果。

## 6. 临时态、授权与持久化边界

陪伴、训练、排练、检索中间态和互动默认临时。只有用户主动确认且 SAVE 许可仍有效时，服务才持久化允许的记录。SAVE、AI_PROCESS 与 SEARCH_PROCESS 相互独立；登录、偏好或已保存记录不能隐式扩大用途。

所有权判定为账号 + 入口 + 对象版本 + 用途授权。客户端不能自报可信账号或入口。查询结果只有 `SUCCESS` 且至少一项可核查来源时才可保存为 QUERY；REQ14 永不持久化。

**关联专业稿与图号：** 数据分类与生命周期见数据库稿第 2、7 章；授权对象见图 4、图 6；端侧清理见前端关键状态图。

## 7. 关键状态与一致性

### 7.1 Agent 与 Search

任务结果必须同时匹配身份、入口、会话、活动和双代次。PAUSE、RESTART、FINISH_REHEARSAL、END、切换、撤销、退出或改密会使旧结果失效。取消成功后任务端点不再返回正文，即使供应商后来返回也不得回填。

### 7.2 排练阶段映射（R03）

图 8 为排练阶段映射，详细状态图见[前端关键状态与时序图](../../../第三次作业_程杰/03_关键状态与时序图.md)。阶段为 `setup → ready → running ↔ paused → reviewing ↔ preview → saved → ended`。FINISH_REHEARSAL 从 running/paused 进入 reviewing，停止角色回复、递增活动代次并仅保留本轮本人消息供选择；REHEARSAL_SUMMARIZE 成功后进入 preview；只有经 SAVE 许可且写结果已核实才进入 saved；END 才清理整轮临时内容。

### 7.3 冲突状态读取（R02）

Agent/Search 使用任务 GET；记录、房间、资料和偏好使用已有 GET 端点读取权威状态。会话动作 409 返回非正文 `error.fields.current`，包含当前 state、mode、活动 ID 与双代次。若无法取得权威状态，客户端保持安全停止，不猜测、不重放旧任务。

**关联专业稿与图号：** 完整阶段表和错误映射见[接口目录](../../../第三次作业_李泉毅/04_接口目录.md)第 4～5 节；排练实体见图 3、图 7；前端动作和资源清理见图 8。

## 8. HTTP 接口设计

系统共有 32 个唯一 HTTP 方法/路径；日历查询是 `GET /api/records` 的筛选形式，不重复计数。目录和跨专业约束见[接口目录](../../../第三次作业_李泉毅/04_接口目录.md)，全套字段只引用[09号规范](../../../第三次作业_张王昊/09_全功能接口与限制规范.md)。本稿不另创平行路径或复制 DTO。

写请求使用 `X-CSRF-Token` 并校验 Origin。错误映射限定为 400、401、403、404、409、413、429、503；原稿中的 422 已删除。任务超时和供应商失败使用任务 `failureReason`，不混入 HTTP 业务码。

**关联专业稿与图号：** 前端请求与页面动作见前端接口表；应用服务依赖见图 6；数据类型见图 7；字段权威源始终为 09 号。

## 9. 数据设计与持久幂等（R04）

PostgreSQL 承载账号、密码摘要、资料、偏好、登录会话、授权、保存记录及子类、房间、检索证据、幂等元数据和清除 outbox。所有持久业务查询绑定 owner 与 entry；更新和清除再绑定 version。图 9 为数据库 ER 图，源文件见[数据库 ER 图](../../../../database-design/diagrams/404NOTFOUND_database_er.mmd)。

持久写以 `(accountId, entryPointId, operation, requestId)` 唯一，对规范化载荷保存 `payloadDigest`。首次请求与业务写在同一事务登记结果；同 requestId 同摘要返回原结果，不同摘要返回 409。客户端超时后必须用原 requestId 和相同载荷重放核实，不得换新 ID。幂等记录只保存作用域、摘要、状态、结果 ID/版本、HTTP 状态和期限，不保存正文；保留 24 小时。`saved_records` 与 `deletion_jobs` 的入口作用域唯一约束是业务表第二道保护。

数据库专业稿当前已实现 `saved_records`、`deletion_jobs` 的入口作用域 requestId 唯一约束；通用 `idempotency_records` 及其 ER/DDL 同步列入变更表，完成同步和静态复核后才宣称 R04 跨稿关闭。AI/Search 任务幂等保留在内存，不承诺跨重启。

备份只覆盖持久化记录，加密保留 7 天；不含正文的删除日志至少保留 8 天。恢复须先重放删除日志、核对连续性并失效所有旧登录会话。

**关联专业稿与图号：** 表、字段、索引和生命周期见数据库稿及 DDL；应用仓储关系见图 6；幂等调用流程见接口目录第 6 节。

## 10. 安全与隐私

安全控制落在具体边界：接入层校验 Cookie、CSRF、Origin、请求体和限流；应用层校验身份、入口、对象版本和用途；Repository 使用参数化 SQL 与作用域条件；模型/搜索适配器只接受许可后的最小载荷；日志仅记录请求 ID、非正文状态、耗时和错误码。

REQ14 使用独立组件和私有内存，不接通用会话 Context、Repository、AI、搜索、日志、分析 SDK 或崩溃正文附件。关闭、切换、销毁或跳过动画均清空 buffer。

**关联专业稿与图号：** 安全组件见图 1、图 6；权限数据见图 4；数据库敏感等级和恢复规则见数据库稿；端侧隔离见前端稿 REQ14 专节。

## 11. 错误、超时与可观测性

统一业务码为 `AUTH_REQUIRED`、`ACCESS_DENIED`、`INVALID_INPUT`、`INVALID_STATE`、`SERVICE_UNAVAILABLE`、`CONFLICT`、`NOT_FOUND`、`RATE_LIMITED`。持久写超时进入“待确认”，按原 requestId 核实；外部任务失败后只允许用户主动创建新任务，并重新校验许可和额度。数据库、模型或搜索失败不得伪装为空结果或成功。

**关联专业稿与图号：** HTTP 映射见接口目录第 2.1 节；前端恢复动作见前端接口表第 8 节；数据库失败与审计范围见数据库稿第 6、8 章。

## 12. 部署与运行边界

Web 为首发形态，同源托管静态资源与 API，PostgreSQL 位于私网。Electron 透明、置顶、拖动、穿透、多屏和退出能力必须实机验证后才标为 AVAILABLE；渲染层关闭 Node 集成，启用 contextIsolation 与 sandbox。微信首轮只做适配或模拟。密钥仅由服务端配置注入。

**关联专业稿与图号：** 部署组件见图 1；Electron 白名单桥见图 5和前端入口能力矩阵；数据库恢复见数据库稿第 8 章。


### 12.1 基线与部署状态

已采纳的设计方向是 Web 首发、React/Vite 前端、Node.js/Express 模块化单体、PostgreSQL 私网存储、`pg` 与 SQL 迁移、Zod 共享契约、LangChain JS 模型适配。开发在本机进行，目标交付拓扑为 HTTPS 同源 Web/API 加私网 PostgreSQL；先按**单实例应用服务**设计，因为异步任务与取消状态仅在进程内存中。Electron 按原生能力验证范围描述，微信按适配或模拟入口描述。所查仓库快照含 React/Vite 与 HTML 演示原型；服务、数据库、模型及目标拓扑的实际运行状态以团队正式部署记录为准。

AI 专业设计已完成（团队确认），提出接入智谱或通义千问推理 API、由项目维护 Agent 编排和可选长期记忆。供应商适配应与 `LangChainModelAdapter` 技术决策及共享接口契约保持一致；长期记忆的持久对象、独立授权、到期和删除传播以团队正式合稿为准。部署时仅启用正式版列入范围、具备相应存储与清除规则的功能。

### 12.2 组件位置与访问边界

| 组件 | 目标运行位置 | 允许的连接 | 不允许的连接或数据 |
|---|---|---|---|
| Web 静态资源 | 与 API 同源的 HTTPS 入口 | 浏览器请求本域静态资源和受控 API | 不含数据库/模型密钥；REQ14 正文不调用 API |
| Express 接入与应用服务 | 单实例服务端；与数据库处于受控网络 | 接收 HTTPS 代理转发；访问私网 PostgreSQL 与受控模型/检索适配 | 浏览器不得直连数据库或模型；日志不得记录正文/凭据 |
| PostgreSQL | 仅服务端可访问的私网 | 应用账号执行限定 DML；迁移账号单独执行结构变更 | 不对公网、浏览器、Electron 渲染进程开放 |
| 外部模型与检索 | 经服务端适配器调用 | 仅发送本次用途许可允许的最小载荷 | 不接受客户端自设供应商地址、密钥或跨入口历史 |
| Electron 验证工程 | 用户设备的主进程、白名单 preload、受限渲染层 | 只暴露受审查的窗口能力；业务 API 仍经可信入口绑定 | 关闭 Node 集成；不得用客户端自报 `DESKTOP` 获得数据权限 |
| REQ14 文字销毁视图 | 独立端侧内存 | 输入、动画、清空与退出均在组件内部 | 无网络、仓储、通用聊天状态、分析/崩溃正文附件 |

同源发布仍需在反向代理处检查 TLS、Cookie `Secure`、Origin 和 CSRF 令牌；服务端从已验证的会话推导账号与入口，不能信任请求头自报入口。实例扩容前必须把任务归属、取消与临时结果转移到可审查的共享机制，重新验证失效规则，不能把单实例设计直接复制为多实例部署。

### 12.3 配置、密钥与启动

启动配置按环境分层管理：公开的前端构建参数只允许存 API 基址、功能可用状态等非秘密值；服务端配置包含数据库连接、会话与 CSRF 参数、正文加密密钥引用、模型/检索凭据、超时与限额；迁移凭据和备份凭据分别保管。模型供应商、模型 ID 与密钥引用须以实际接入结果记录，演示模拟适配器必须明确标记。所有真实密钥由受控运行环境注入，不放进 Git、构建产物、浏览器存储、日志、演示截图或数据库业务表。

部署时先核对配置完整性与权限，再执行数据库连接和迁移前检查；迁移由独立账号执行，应用账号不持有 DDL 权限。启动后先检查进程、数据库连接、受控适配器可用性和基础健康端点，再开放入口。数据库或模型不可用时不得把服务错误伪装成空结果或成功保存。具体域名、机器、区域、端口、版本和供应商写入实际环境清单，未配置时不填虚构值。

### 12.4 发布、回退与版本控制

1. 冻结同一提交的 Web 构建、服务端代码、共享 Schema、数据库迁移和两份设计文档，记录提交哈希、依赖锁文件及操作人。
2. 发布前静态检查 REQ01～REQ17 追踪、接口 09 号规范、DDL/ER、权限矩阵和变更表；运行环境具备后执行迁移演练、关键链路与回归用例。
3. 对持久数据做加密备份并验证可读取，确认独立清除日志连续；仅在这些前提具备时执行迁移和发布。
4. 应用回退优先部署上一兼容版本；迁移若不可逆，先停止写入并按经验证的恢复流程恢复到隔离环境，重放清除日志、核对对象与撤销会话后才考虑切换。不得为了回退直接把旧备份覆盖在线库。
5. 发布记录包括版本、迁移编号、验证结果、异常、回退决定及执行人与复核人。首次真实部署前，回退步骤须在目标环境演练，不能仅凭本文判断可恢复。

### 12.5 日志、监测与故障行为

可观测字段限定为请求 ID、可信入口代码、非正文的操作类别与状态、耗时、错误码、资源使用量及必要的异常类型。日志和告警不得包含密码、Cookie、原始会话令牌、聊天/排练/查询正文、用户私密记录、REQ14 输入、模型完整上下文或数据库 SQL 参数。数据库慢查询与错误日志需配置为不记录敏感参数；外部追踪默认关闭正文采集。

| 故障 | 用户可见行为 | 服务端及运维动作 |
|---|---|---|
| 模型或检索超时 | 明确显示失败或超时，停止轮询；不显示“无结果” | 使任务失效并尝试取消；旧返回不回填；记录非正文错误码和耗时 |
| 网络中断或客户端退出 | 本地互动可安全停止；持久写超时显示结果未核实 | 以原 `requestId` 和相同载荷查询/重试核实；不能换新 ID 重复写 |
| 数据库不可用 | 保存、读取与删除明确失败；不把失败当空列表或成功 | 停止持久写；检查连接、迁移与存储；恢复后复核幂等和版本冲突 |
| 并发或版本冲突 | 409 后读取权威当前状态；不覆盖用户旧内容 | 按账号、入口、对象版本和用途复核；保留冲突证据但不记录正文 |
| 账号退出、改密、切换 | 私密内容立即隐藏；旧任务停止 | 撤销会话，拒绝迟到结果；改密撤销全部旧会话 |
| Electron 浮层/音频异常 | 允许退出并恢复普通桌面操作 | 主进程兜底销毁窗口和捕获；能力未实测前标模拟/不可用 |
| 备份或清除日志异常 | 暂停对外宣称可恢复；清除结果按真实状态反馈 | 非正文告警；修复备份或复制链路，连续性不合格禁止恢复发布 |

### 12.6 备份、删除传播与恢复

备份仅包含主动保存的持久数据及必需治理元数据。备份加密，保留 **7 天**；删除事务写入 `deletion_outbox`，由可靠复制流程形成**独立于业务备份**的 `deletion_log_entries`，至少保留 **8 天**，并确保覆盖全部尚可恢复的备份。删除记录在线主库立即不可见；缓存、索引、派生物与备份窗口按删除任务传播。文字销毁正文和其他未保存临时态不进入备份。

恢复操作先在隔离环境校验备份与密钥可用性、完整性、版本和迁移兼容性，再核对删除日志从备份时间点至恢复点的连续性并重放；无法证明连续时不得开放服务。重放后核查已清除对象不复活、记录归属和入口隔离仍成立，并撤销恢复出的旧 `login_sessions`。由授权人员复核后才切换流量，保留非正文审计记录。RPO/RTO 需通过目标环境的备份恢复演练记录实测值，当前不填写未经测量的数字。

数据库 v0.2 §6.3 采用上述备份与独立删除日志规则。关欣历史安全章节中的 `clear_tombstone` 单表建议及“可随备份保留”属于旧版表述；关欣和庄剀涵的正式交接材料均已完成（团队确认），最终结构以团队正式合稿为准。
