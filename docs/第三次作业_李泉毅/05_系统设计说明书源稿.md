# 404NOTFOUND 系统设计说明书源稿

版本：V1.0（第三次团队作业）

日期：2026-10-19

文档状态：设计稿，非实现完成声明

## 1. 编写目的与依据

本文面向 404NOTFOUND 第三次团队作业，说明系统架构、模块职责、领域类、接口契约、数据与安全设计。依据优先级为：需求规格说明书 v1.3、UML 设计 v1.1、需求范围 v0.3、03 技术决策与 Agent 接入基线、09 全功能接口与限制规范、当前任务分工；原型源码仅用于核对交互现状。若历史材料冲突，以前述较新、较高优先级材料为准。

## 2. 设计状态与范围

仓库当前以 React/Vite 交互原型和设计材料为主。本文中的 Node.js/Express、PostgreSQL、LangChain、REST 路径和安全措施均是本轮冻结的目标设计契约，不表示线上服务已实现、部署或验收。系统覆盖 REQ01～REQ17；不纳入漂流瓶、公开主页、社交关系、账号注销、忘记/重置密码或默认跨入口同步。

## 3. 总体架构

系统采用模块化单体：Web、Electron 与微信适配层经 Express 接入；接入层执行安全 Cookie、CSRF、Origin、限流及 Zod 校验；应用层包含认证、资料、记录、房间、任务协调及 Agent 门面；领域层维护账号、会话、活动、记录、授权和策略；端口连接 PostgreSQL、LangChain 模型适配器及固定检索供应商。

架构源图见 `01_404NOTFOUND_系统架构图.mmd`。REQ14 采用独立端侧旁路，其正文不得进入认证上下文、业务会话、网络、数据库、模型、搜索、日志、遥测或崩溃附件。

## 4. 技术选型

|层次|选型|决定|
|---|---|---|
|Web|React + Vite + JavaScript/JSX|沿用仓库现状；共享 Schema 使用 JSDoc 辅助推断|
|服务端|Node.js + Express|模块化单体，统一 REST 接入和安全中间件|
|校验|Zod|前后端共享严格 Schema，拒绝未知字段|
|数据库|PostgreSQL + pg + SQL migration|登录会话、主动保存记录、授权和幂等元数据持久化|
|Agent|LangChain JS|通过 `LangChainModelAdapter` 实现既有 `AIClient`|
|客户端形态|Web 首发；Electron 验证；微信适配/模拟|能力状态必须真实标为 AVAILABLE/SIMULATED/UNAVAILABLE|

## 5. 模块职责

- `AuthService`/`ProfileService`：注册、登录、退出、改密、私密资料与偏好。
- `TaskCoordinator`：创建业务会话、切换活动、登记请求、取消及迟到回复拦截。
- `AgentApplicationService`：承接 HTTP 任务信封，统一受理、轮询和取消。
- `AIProcessingService`：组织被许可的上下文，执行安全策略并调用 AIClient。
- `RecordService`/`RoomService`：本人当前入口记录的保存、读取、更新、清除及房间关联。
- `AuthorizationPolicy`/`SafetyPolicy`：所有权、入口、对象版本、用途许可与安全回复边界。

## 6. 领域模型与类图

完整模型沿用 UML v1.1 的六张分图和原有模型体系，在其上完成 v1.2 增量。详见 `02_404NOTFOUND_完整设计类图_V1.2.md` 与 `03_设计类图增量修改说明.md`。核心原则是：临时业务活动默认不落库；只有用户主动保存且持有效 SAVE 许可时持久化；保存许可、AI 外发许可、搜索许可彼此独立。

## 7. 关键时序与一致性

### 7.1 Agent 任务

客户端先创建临时业务会话并取得 AI_PROCESS 许可，再调用 `POST /api/agent/tasks`。服务以 202 接受任务，客户端通过 requestId 轮询。结果必须同时匹配身份、入口、业务会话、活动、sessionGeneration 与 activityGeneration；任何取消、退出、改密、切换、暂停、重来或结束引起的不匹配都会使迟到结果被丢弃。

### 7.2 主动保存和清除

保存前展示载荷范围并创建 SAVE 许可，记录、子表、授权和幂等信息在同一事务提交。更新使用 expectedVersion。清除先签发两分钟有效、绑定身份/入口/对象版本的一次性确认，再在事务内清理主从数据、授权和房间关联。数据库失败不得伪装为空或成功。

### 7.3 寄存和排练

寄存到期只改变可取状态，不展开正文、不催促、不调用模型；必须本人主动取回。排练结束模拟后进入 reviewing，只允许选择本轮用户明确认可的表达；AI 回复和未认可建议不能自动进入整理稿。

## 8. 接口设计

完整目录见 `04_接口目录.md`，详细字段和限制以仓库 09 号规范为准。核心接口为 `POST /api/agent/tasks`、`GET /api/agent/tasks/:requestId`、`POST /api/agent/tasks/:requestId/cancel` 及独立的 `/api/search/tasks` 系列；不得另创平行路径。线上 DTO 映射到应用服务，不把 HTTP 轮询状态强塞入 AIClient。

## 9. 数据设计

PostgreSQL 至少承载账号、密码摘要、资料、账号偏好、登录会话、保存记录及子类、授权、房间关联、任务幂等和清除 outbox。所有持久业务查询必须包含 owner 与 entry；更新/清除再包含 version。密码采用 Argon2id（初始参数 19 MiB、迭代 2、并行度 1及独立随机盐）；会话随机凭据至少 32 字节，仅存 SHA-256 摘要。默认临时正文不写库。

备份仅覆盖已持久化记录，加密保留 7 天；不含正文的清除日志独立保存至少 8 天。全库恢复须先重放清除日志、核对连续性并失效所有旧登录会话。

## 10. 安全与隐私

系统采用 HttpOnly/Secure/SameSite Cookie、CSRF token、Origin 白名单、参数化 SQL、CSP、输出转义、账号/IP 双维限流和最小化日志。权限判定为账号 + 入口 + 对象版本 + 用途授权。用户提供的 URL 和检索网页均是不可信输入，禁止访问内网、本机和云元数据地址，并逐次校验重定向。

REQ14 是最高等级隔离项：独立组件、私有内存、本地打包资源，不接第三方脚本/字体/CDN，不记录正文；关闭、切换、销毁或跳过动画均清空 buffer。

## 11. 异常、配额与可观测性

统一错误码包括 AUTH_REQUIRED、ACCESS_DENIED、INVALID_INPUT、INVALID_STATE、SERVICE_UNAVAILABLE、CONFLICT、NOT_FOUND、RATE_LIMITED。日志只记录请求标识、状态、耗时和非正文诊断字段；密码、Cookie、token、临时正文、授权载荷正文及 REQ14 内容不得进入日志。模型与检索失败必须显式失败，不能伪装成空结果。

## 12. 部署与运行边界

Web 是首发形态。Electron 透明、置顶、拖动、穿透、多屏和退出能力须验证后才能标 AVAILABLE；渲染层关闭 Node 集成并启用 contextIsolation 与 sandbox。微信首轮只做适配或模拟，不能冒充已具备原生能力。密钥仅在服务端受控环境注入。

## 13. 测试与验收

按 AT-01～AT-17 验收，重点覆盖：跨账号/跨入口越权、CSRF/Origin、代次冲突、取消与迟到回复、幂等、乐观锁、数据库重启、模型/检索失败、寄存不自动展开、排练认可边界、REQ14 合成标记零外泄，以及 Electron 能力实机验证。未实现、未测试或模拟能力不得写成生产可用。

## 14. 追踪与变更控制

需求、UML、HTTP Schema、数据库迁移、实现和 AT 用例必须保持可追踪。修改字段、路径、枚举、配额或状态机时，同时更新共享 Schema、接口目录、UML、需求设计追踪表和验收用例。本文不替代专业 DDL/ER 稿，也不冒充已执行建表。
