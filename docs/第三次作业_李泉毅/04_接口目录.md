## 1. 使用边界与权威来源

本目录只负责导航、调用约束和跨专业闭环，不复制全套 HTTP 字段。HTTP 方法、路径、请求与响应字段、限额、错误和任务状态的唯一权威来源是[09号全功能接口与限制规范](../第三次作业_张王昊/09_全功能接口与限制规范.md)。前端消费方式参见[前端所需接口表](../第三次作业_程杰/05_前端所需接口表.md)，持久化约束参见[数据库设计说明书](../../database-design/404NOTFOUND_数据库设计说明书_庄剀涵_v0.2.md)与[PostgreSQL DDL](../../database-design/sql/404notfound_postgresql.sql)。新增或修订契约先登记于本文第 8 节变更表，再同步 09 号、共享 Zod Schema、前端表、数据库稿和验收用例。

## 2. 通用调用约束

- 同源 `/api`、JSON、UTF-8；共享 Zod Schema 严格校验并拒绝未知字段。
- 服务端从 `__Host-session` 安全 Cookie 与可信适配器解析身份和入口；客户端不得提交可信 `ownerId` 或 `entry`。
- `POST`、`PUT`、`PATCH`、`DELETE` 使用 `X-CSRF-Token` 请求头，并校验会话绑定 token 与允许的 Origin。token 从 `GET /api/auth/context` 获得，登录、退出和换账号后必须刷新。
- 错误统一为 `{error:{code,message,fields?,retryAfterSeconds?},meta:{requestId}}`，不得回显凭据、正文、提示词、堆栈或对象存在性。
- 异步任务绑定身份、入口、`sessionId`、`activityId`、`sessionGeneration`、`activityGeneration`；任一绑定失效即拒绝迟到结果。
- 普通 API 初始总时限 5 秒，外部任务含排队 30 秒。超时不等于写失败；持久写必须按第 6 节核实。

### 2.1 错误映射（R02）

| HTTP | 业务码 | 语义与客户端动作 |
|---:|---|---|
| 400 | `INVALID_INPUT` | 字段或状态输入无效；修正后再提交，不调用模型或写库 |
| 401 | `AUTH_REQUIRED` | 登录缺失或过期；遮蔽正文并失效旧身份代次、授权、缓存和任务 |
| 403 | `ACCESS_DENIED` | CSRF、用途许可或明确权限失败；不得循环授权重试 |
| 404 | `NOT_FOUND` | 不存在、他人或其他入口对象统一安全 404；清除本地失效引用 |
| 409 | `CONFLICT` / `INVALID_STATE` | 版本、幂等载荷或状态冲突；读取权威当前状态后由用户决定 |
| 413 | `INVALID_INPUT` | 请求体或正文超限；缩减后重新取得相关许可 |
| 429 | `RATE_LIMITED` | 遵守 `Retry-After` / `retryAfterSeconds`，停止自动重复创建 |
| 503 | `SERVICE_UNAVAILABLE` | 服务或依赖不可用；不得伪装为空列表、EMPTY、全零或写入成功 |

本轮删除原目录中未由 09 号定义的 422。`TIMEOUT`、`PROVIDER_UNAVAILABLE`、`OUTPUT_INVALID` 是任务 `failureReason`，`cancelled` 是任务状态，不新增同名 HTTP 业务码。

## 5. 冲突后的权威状态读取（R02）

- Agent / Search：使用既有任务 GET 端点读取终态；身份、入口或代次失效时不得返回正文。
- 记录：使用 `GET /api/records/:id` 核对版本和内容；房间使用 `GET /api/room`；资料与偏好分别使用对应 GET 端点。
- 会话动作：409 响应的 `error.fields.current` 返回 `{sessionId,activityId,mode,state,sessionGeneration,activityGeneration,rehearsalStage?}`，只含非正文状态。客户端以此刷新控制面；没有该字段时保持安全停止，不猜测或复活旧活动。

## 6. 持久写结果核实与数据库幂等（R02 / R04）

1. 写请求以 `(accountId, entryPointId, operation, requestId)` 作为幂等作用域，对规范化载荷计算 `payloadDigest`。
2. 首次请求在同一数据库事务登记 `IN_PROGRESS`；业务写、版本变更、授权消耗和幂等结果一起提交为 `COMPLETED`。元数据只保存摘要、结果类型、结果 ID/版本、HTTP 状态和期限，不复制正文。
3. 同作用域、同 requestId、同摘要的重试返回原结果；摘要不同返回 409 `CONFLICT`；仍在执行返回 409 `INVALID_STATE`。
4. 网络断开或 5 秒超时后，客户端以原 requestId 与完全相同载荷重放核实，不得换新 ID 重复写。取得结果 ID 后再调用既有 GET 端点核对。
5. SAVE 许可过期不影响读取已提交的幂等结果；若事务未提交且许可已过期，服务不得继续写入，应要求用户重新确认。不得复活已清除正文。
6. 持久幂等元数据保留 24 小时；AI / Search 任务幂等仍为进程内临时态，不承诺跨重启。

数据库落地采用 `idempotency_records`（或数据库专业稿批准的等价表），唯一键覆盖账号、入口、操作和 requestId；`saved_records` 与 `deletion_jobs` 现有入口作用域唯一约束继续作为业务表第二道保护。DDL、ER、数据字典必须按第 8 节变更项同步后才视为跨稿闭环。
