# 404NOTFOUND 设计类图增量修改说明

## 基线与原则

本次不是重画简化类图，而是在仓库 `docs/UML设计_v1.1.md` 的六张 Mermaid 类图及原有 74 个模型元素基础上完善。需求规格说明书 v1.3 为需求权威来源，第三次作业 03、09 号文件用于补充技术落地与 HTTP 契约。

## 变更清单

|类别|处理|
|---|---|
|保留|六张分图、原有实体/值对象/服务/端口、继承/组合/聚合/依赖关系|
|修改|`LocalRecordRepository` → `PostgresRecordRepository`；密码新建/修改 12～128 Unicode 码点；活动与业务会话代次分别命名 `activityGeneration`、`sessionGeneration`|
|新增|`AgentApplicationService`（应用层 AI/Agent 门面）；`LangChainModelAdapter`（实现 `AIClient`）；错误码 `NOT_FOUND`、`RATE_LIMITED`|
|删除|不删除既有领域类；仅淘汰 LocalRecordRepository 这一基础设施实现名|
|隔离|`TextDestructionView` 保持端侧独立，与认证、业务会话、Repository、AI、搜索、日志及遥测无连接|

## 关键关系说明

- `AgentApplicationService` 负责 HTTP 任务信封、受理/查询/取消；`AIProcessingService` 继续负责上下文、安全和响应编排。
- `LangChainModelAdapter` 是 `AIClient` 的实现，领域与应用层不直接依赖供应商 SDK。
- `PendingRequest` 同时携带两个代次以及身份/入口/设备信息；迟到响应仅在所有绑定项仍匹配时可接纳。
- Repository 查询和写入必须绑定 owner + entry；写操作再绑定 version，客户端不得自报可信 owner 或 entry。
- SAVE、AI_PROCESS、SEARCH_PROCESS 是相互独立的用途许可，不因偏好或登录而合并。
