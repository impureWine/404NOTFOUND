## 3. 总体架构

系统采用模块化单体。Web、Electron 与微信适配层进入 Express 接入与安全层；应用层包含认证、资料、记录、房间、任务协调和 Agent 门面；领域层维护账号、会话、活动、记录、授权和策略；端口连接 PostgreSQL、LangChain 模型适配器和固定检索供应商。

图 1 为总体系统架构，源文件见[系统架构图](01_系统架构图.mmd)。REQ14 是独立端侧旁路，正文不得进入认证上下文、业务会话、网络、数据库、模型、搜索、日志、遥测或崩溃附件。

**关联专业稿与图号：** 前端组件关系见前端《组件关系图》；数据边界见数据库稿第 2～3 章；安全边界见本稿第 10 章。

## 5. 模块职责与领域结构

- `AuthService` / `ProfileService`：注册、登录、退出、改密、资料与偏好。
- `TaskCoordinator`：创建会话、切换活动、登记请求、取消并拦截迟到结果。
- `AgentApplicationService`：承接 HTTP 任务信封，统一受理、轮询和取消。
- `AIProcessingService`：按许可构造最小上下文，执行安全策略并调用 `AIClient`。
- `RecordService` / `RoomService`：保存、读取、更新、清除及房间关联。
- `AuthorizationPolicy` / `SafetyPolicy`：校验账号、入口、对象版本、用途许可与回复边界。
- `IdempotencyService`：登记持久写请求、比对载荷摘要并返回已提交结果。

领域结构以[完整设计类图 v1.2](02_完整设计类图_V1.2.md)为准：图 2 账号与入口；图 3 业务活动；图 4 保存记录与授权；图 5 端侧互动；图 6 服务、端口与基础设施；图 7 接口数据类型。v1.1 只作为六张原图的历史来源。

## 6. 临时态、授权与持久化边界

陪伴、训练、排练、检索中间态和互动默认临时。只有用户主动确认且 SAVE 许可仍有效时，服务才持久化允许的记录。SAVE、AI_PROCESS 与 SEARCH_PROCESS 相互独立；登录、偏好或已保存记录不能隐式扩大用途。

所有权判定为账号 + 入口 + 对象版本 + 用途授权。客户端不能自报可信账号或入口。查询结果只有 `SUCCESS` 且至少一项可核查来源时才可保存为 QUERY；REQ14 永不持久化。

**关联专业稿与图号：** 数据分类与生命周期见数据库稿第 2、7 章；授权对象见图 4、图 6；端侧清理见前端关键状态图。

## 7. 关键状态与一致性

### 7.1 Agent 与 Search

任务结果必须同时匹配身份、入口、会话、活动和双代次。PAUSE、RESTART、FINISH_REHEARSAL、END、切换、撤销、退出或改密会使旧结果失效。取消成功后任务端点不再返回正文，即使供应商后来返回也不得回填。

### 7.2 排练阶段映射（R03）

图 8 为排练阶段映射，详细状态图见[前端关键状态与时序图](../第三次作业_程杰/03_关键状态与时序图.md)。阶段为 `setup → ready → running ↔ paused → reviewing ↔ preview → saved → ended`。FINISH_REHEARSAL 从 running/paused 进入 reviewing，停止角色回复、递增活动代次并仅保留本轮本人消息供选择；REHEARSAL_SUMMARIZE 成功后进入 preview；只有经 SAVE 许可且写结果已核实才进入 saved；END 才清理整轮临时内容。

### 7.3 冲突状态读取（R02）

Agent/Search 使用任务 GET；记录、房间、资料和偏好使用已有 GET 端点读取权威状态。会话动作 409 返回非正文 `error.fields.current`，包含当前 state、mode、活动 ID 与双代次。若无法取得权威状态，客户端保持安全停止，不猜测、不重放旧任务。

**关联专业稿与图号：** 完整阶段表和错误映射见[接口目录](04_接口目录.md)第 4～5 节；排练实体见图 3、图 7；前端动作和资源清理见图 8。

## 8. HTTP 接口设计

系统共有 32 个唯一 HTTP 方法/路径；日历查询是 `GET /api/records` 的筛选形式，不重复计数。目录和跨专业约束见[接口目录](04_接口目录.md)，全套字段只引用[09号规范](../第三次作业_张王昊/09_全功能接口与限制规范.md)。本稿不另创平行路径或复制 DTO。

写请求使用 `X-CSRF-Token` 并校验 Origin。错误映射限定为 400、401、403、404、409、413、429、503；原稿中的 422 已删除。任务超时和供应商失败使用任务 `failureReason`，不混入 HTTP 业务码。

**关联专业稿与图号：** 前端请求与页面动作见前端接口表；应用服务依赖见图 6；数据类型见图 7；字段权威源始终为 09 号。

## 9. 数据设计与持久幂等（R04）

PostgreSQL 承载账号、密码摘要、资料、偏好、登录会话、授权、保存记录及子类、房间、检索证据、幂等元数据和清除 outbox。所有持久业务查询绑定 owner 与 entry；更新和清除再绑定 version。图 9 为数据库 ER 图，源文件见[数据库 ER 图](../../database-design/diagrams/404NOTFOUND_database_er.mmd)。

持久写以 `(accountId, entryPointId, operation, requestId)` 唯一，对规范化载荷保存 `payloadDigest`。首次请求与业务写在同一事务登记结果；同 requestId 同摘要返回原结果，不同摘要返回 409。客户端超时后必须用原 requestId 和相同载荷重放核实，不得换新 ID。幂等记录只保存作用域、摘要、状态、结果 ID/版本、HTTP 状态和期限，不保存正文；保留 24 小时。`saved_records` 与 `deletion_jobs` 的入口作用域唯一约束是业务表第二道保护。

数据库专业稿当前已实现 `saved_records`、`deletion_jobs` 的入口作用域 requestId 唯一约束；通用 `idempotency_records` 及其 ER/DDL 同步列入变更表，完成同步和静态复核后才宣称 R04 跨稿关闭。AI/Search 任务幂等保留在内存，不承诺跨重启。

备份只覆盖持久化记录，加密保留 7 天；不含正文的删除日志至少保留 8 天。恢复须先重放删除日志、核对连续性并失效所有旧登录会话。

**关联专业稿与图号：** 表、字段、索引和生命周期见数据库稿及 DDL；应用仓储关系见图 6；幂等调用流程见接口目录第 6 节。

## 10. 安全与隐私

安全控制落在具体边界：接入层校验 Cookie、CSRF、Origin、请求体和限流；应用层校验身份、入口、对象版本和用途；Repository 使用参数化 SQL 与作用域条件；模型/搜索适配器只接受许可后的最小载荷；日志仅记录请求 ID、非正文状态、耗时和错误码。

REQ14 使用独立组件和私有内存，不接通用会话 Context、Repository、AI、搜索、日志、分析 SDK 或崩溃正文附件。关闭、切换、销毁或跳过动画均清空 buffer。

**关联专业稿与图号：** 安全组件见图 1、图 6；权限数据见图 4；数据库敏感等级和恢复规则见数据库稿；端侧隔离见前端稿 REQ14 专节。

## 11. 错误、超时与可观测性

统一业务码为 `AUTH_REQUIRED`、`ACCESS_DENIED`、`INVALID_INPUT`、`INVALID_STATE`、`SERVICE_UNAVAILABLE`、`CONFLICT`、`NOT_FOUND`、`RATE_LIMITED`。持久写超时进入“待确认”，按原 requestId 核实；外部任务失败后只允许用户主动创建新任务，并重新校验许可和额度。数据库、模型或搜索失败不得伪装为空结果或成功。

**关联专业稿与图号：** HTTP 映射见接口目录第 2.1 节；前端恢复动作见前端接口表第 8 节；数据库失败与审计范围见数据库稿第 6、8 章。

## 12. 部署与运行边界

Web 为首发形态，同源托管静态资源与 API，PostgreSQL 位于私网。Electron 透明、置顶、拖动、穿透、多屏和退出能力必须实机验证后才标为 AVAILABLE；渲染层关闭 Node 集成，启用 contextIsolation 与 sandbox。微信首轮只做适配或模拟。密钥仅由服务端配置注入。

**关联专业稿与图号：** 部署组件见图 1；Electron 白名单桥见图 5和前端入口能力矩阵；数据库恢复见数据库稿第 8 章。
