# 404NOTFOUND 部署与运维设计

编写：曾俊涛（T08）  
版本：个人初稿 v0.2，2026-10-22  
用途：供《系统设计说明书》部署与运行章节整合，并与《数据库设计说明书》备份恢复章节交叉核对。

## 1. 基线与部署状态

已采纳的设计方向是 Web 首发、React/Vite 前端、Node.js/Express 模块化单体、PostgreSQL 私网存储、`pg` 与 SQL 迁移、Zod 共享契约、LangChain JS 模型适配。开发在本机进行，目标交付拓扑为 HTTPS 同源 Web/API 加私网 PostgreSQL；先按**单实例应用服务**设计，因为异步任务与取消状态仅在进程内存中。Electron 按原生能力验证范围描述，微信按适配或模拟入口描述。所查仓库快照含 React/Vite 与 HTML 演示原型；服务、数据库、模型及目标拓扑的实际运行状态以团队正式部署记录为准。

AI 专业设计已完成（团队确认），提出接入智谱或通义千问推理 API、由项目维护 Agent 编排和可选长期记忆。供应商适配应与 `LangChainModelAdapter` 技术决策及共享接口契约保持一致；长期记忆的持久对象、独立授权、到期和删除传播以团队正式合稿为准。部署时仅启用正式版列入范围、具备相应存储与清除规则的功能。

## 2. 组件位置与访问边界

| 组件 | 目标运行位置 | 允许的连接 | 不允许的连接或数据 |
|---|---|---|---|
| Web 静态资源 | 与 API 同源的 HTTPS 入口 | 浏览器请求本域静态资源和受控 API | 不含数据库/模型密钥；REQ14 正文不调用 API |
| Express 接入与应用服务 | 单实例服务端；与数据库处于受控网络 | 接收 HTTPS 代理转发；访问私网 PostgreSQL 与受控模型/检索适配 | 浏览器不得直连数据库或模型；日志不得记录正文/凭据 |
| PostgreSQL | 仅服务端可访问的私网 | 应用账号执行限定 DML；迁移账号单独执行结构变更 | 不对公网、浏览器、Electron 渲染进程开放 |
| 外部模型与检索 | 经服务端适配器调用 | 仅发送本次用途许可允许的最小载荷 | 不接受客户端自设供应商地址、密钥或跨入口历史 |
| Electron 验证工程 | 用户设备的主进程、白名单 preload、受限渲染层 | 只暴露受审查的窗口能力；业务 API 仍经可信入口绑定 | 关闭 Node 集成；不得用客户端自报 `DESKTOP` 获得数据权限 |
| REQ14 文字销毁视图 | 独立端侧内存 | 输入、动画、清空与退出均在组件内部 | 无网络、仓储、通用聊天状态、分析/崩溃正文附件 |

同源发布仍需在反向代理处检查 TLS、Cookie `Secure`、Origin 和 CSRF 令牌；服务端从已验证的会话推导账号与入口，不能信任请求头自报入口。实例扩容前必须把任务归属、取消与临时结果转移到可审查的共享机制，重新验证失效规则，不能把单实例设计直接复制为多实例部署。

## 3. 配置、密钥与启动

启动配置按环境分层管理：公开的前端构建参数只允许存 API 基址、功能可用状态等非秘密值；服务端配置包含数据库连接、会话与 CSRF 参数、正文加密密钥引用、模型/检索凭据、超时与限额；迁移凭据和备份凭据分别保管。模型供应商、模型 ID 与密钥引用须以实际接入结果记录，演示模拟适配器必须明确标记。所有真实密钥由受控运行环境注入，不放进 Git、构建产物、浏览器存储、日志、演示截图或数据库业务表。

部署时先核对配置完整性与权限，再执行数据库连接和迁移前检查；迁移由独立账号执行，应用账号不持有 DDL 权限。启动后先检查进程、数据库连接、受控适配器可用性和基础健康端点，再开放入口。数据库或模型不可用时不得把服务错误伪装成空结果或成功保存。具体域名、机器、区域、端口、版本和供应商写入实际环境清单，未配置时不填虚构值。

## 4. 发布、回退与版本控制

1. 冻结同一提交的 Web 构建、服务端代码、共享 Schema、数据库迁移和两份设计文档，记录提交哈希、依赖锁文件及操作人。
2. 发布前静态检查 REQ01～REQ17 追踪、接口 09 号规范、DDL/ER、权限矩阵和变更表；运行环境具备后执行迁移演练、关键链路与回归用例。
3. 对持久数据做加密备份并验证可读取，确认独立清除日志连续；仅在这些前提具备时执行迁移和发布。
4. 应用回退优先部署上一兼容版本；迁移若不可逆，先停止写入并按经验证的恢复流程恢复到隔离环境，重放清除日志、核对对象与撤销会话后才考虑切换。不得为了回退直接把旧备份覆盖在线库。
5. 发布记录包括版本、迁移编号、验证结果、异常、回退决定及执行人与复核人。首次真实部署前，回退步骤须在目标环境演练，不能仅凭本文判断可恢复。

## 5. 日志、监测与故障行为

可观测字段限定为请求 ID、可信入口代码、非正文的操作类别与状态、耗时、错误码、资源使用量及必要的异常类型。日志和告警不得包含密码、Cookie、原始会话令牌、聊天/排练/查询正文、用户私密记录、REQ14 输入、模型完整上下文或数据库 SQL 参数。数据库慢查询与错误日志需配置为不记录敏感参数；外部追踪默认关闭正文采集。

| 故障 | 用户可见行为 | 服务端及运维动作 |
|---|---|---|
| 模型或检索超时 | 明确显示失败或超时，停止轮询；不显示“无结果” | 使任务失效并尝试取消；旧返回不回填；记录非正文错误码和耗时 |
| 网络中断或客户端退出 | 本地互动可安全停止；持久写超时显示结果未核实 | 以原 `requestId` 和相同载荷查询/重试核实；不能换新 ID 重复写 |
| 数据库不可用 | 保存、读取与删除明确失败；不把失败当空列表或成功 | 停止持久写；检查连接、迁移与存储；恢复后复核幂等和版本冲突 |
| 并发或版本冲突 | 409 后读取权威当前状态；不覆盖用户旧内容 | 按账号、入口、对象版本和用途复核；保留冲突证据但不记录正文 |
| 账号退出、改密、切换 | 私密内容立即隐藏；旧任务停止 | 撤销会话，拒绝迟到结果；改密撤销全部旧会话 |
| Electron 浮层/音频异常 | 允许退出并恢复普通桌面操作 | 主进程兜底销毁窗口和捕获；能力未实测前标模拟/不可用 |
| 备份或清除日志异常 | 暂停对外宣称可恢复；清除结果按真实状态反馈 | 非正文告警；修复备份或复制链路，连续性不合格禁止恢复发布 |

## 6. 备份、删除传播与恢复

备份仅包含主动保存的持久数据及必需治理元数据。备份加密，保留 **7 天**；删除事务写入 `deletion_outbox`，由可靠复制流程形成**独立于业务备份**的 `deletion_log_entries`，至少保留 **8 天**，并确保覆盖全部尚可恢复的备份。删除记录在线主库立即不可见；缓存、索引、派生物与备份窗口按删除任务传播。文字销毁正文和其他未保存临时态不进入备份。

恢复操作先在隔离环境校验备份与密钥可用性、完整性、版本和迁移兼容性，再核对删除日志从备份时间点至恢复点的连续性并重放；无法证明连续时不得开放服务。重放后核查已清除对象不复活、记录归属和入口隔离仍成立，并撤销恢复出的旧 `login_sessions`。由授权人员复核后才切换流量，保留非正文审计记录。RPO/RTO 需通过目标环境的备份恢复演练记录实测值，当前不填写未经测量的数字。

数据库 v0.2 §6.3 采用上述备份与独立删除日志规则。关欣历史安全章节中的 `clear_tombstone` 单表建议及“可随备份保留”属于旧版表述；关欣和庄剀涵的正式交接材料均已完成（团队确认），最终结构以团队正式合稿为准。
