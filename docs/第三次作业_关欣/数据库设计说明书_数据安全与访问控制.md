# 404烦恼未找到——数据安全与访问控制

## 1 数据分级与敏感字段

数据库侧的敏感分级与系统设计一致，按 L4 凭据类、L3 私密正文、L2 业务元数据、L1 运行状态划分。L1 不落库，因此数据库中只有 L2～L4 三类。分级的作用是让「哪些字段不能进日志、不能进备份导出、不能给只读账号看」变成可核对的表。

表1 逻辑对象、敏感级别与保护措施

| 逻辑对象 | 建议表名 | 级别 | 关键敏感字段 | 数据库侧保护措施 | 可访问主体 |
|---|---|---|---|---|---|
| 账号 | user_account | L4 | login_name、state | 登录名标准化后唯一；不存密码 | 应用账号、迁移账号 |
| 凭据 | auth_credential | L4 | password_digest、salt、params | 只存不可逆摘要与参数；列级权限收敛；禁止导出 | 应用账号（仅校验路径） |
| 登录会话 | login_session | L4 | token_digest、device、expires_at | 只存摘要；过期与撤销状态可查；无原文令牌列 | 应用账号 |
| 个人资料 | user_profile | L2 | nickname、bio | 仅本人读写；不用于鉴权 | 应用账号 |
| 账号偏好 | account_preference | L2 | offer_history_save 等 | 不承载正文；与设备偏好分表 | 应用账号 |
| 情绪记录 | emotion_record | L3 | event、intensity | 归属本人当前入口；正文不进日志 | 应用账号 |
| 烦恼物件 | worry_object | L3 | title、description | 同上；外观关联与正文分离存储 | 应用账号 |
| 排练整理稿 | rehearsal_draft | L3 | expressions | 仅用户认可表达；不含完整对话 | 应用账号 |
| 寄存条目 | worry_deposit | L3 | title、body、reopen_at | 正文与状态同表；到期只改状态 | 应用账号 |
| 会话快照 | conversation_snapshot | L3 | 消息副本 | 归属组合唯一；首版只读 | 应用账号 |
| 保存授权 | consent_grant | L2 | purpose、resource_version | 按对象与版本；可撤销 | 应用账号 |
| 房间外观 | room_appearance | L2 | layout | 解除外观不清除正文 | 应用账号 |
| 清除台账 | clear_tombstone（建议） | L2 | record_id、cleared_at | 只记编号与时间，不含正文 | 应用账号、恢复流程 |

## 2 归属与隔离约束

业务表的归属由三列约束表达：`owner_id`（账号）、`entry`（WEB、DESKTOP、WECHAT）、`version`（正整数）。这三列共同构成访问过滤条件，任何仅有 `id` 的查询都不能出现在仓储实现中。

表2 表级约束要求

| 约束 | 要求 | 理由 |
|---|---|---|
| 归属非空 | 所有业务表 owner_id 与 entry 均 NOT NULL | 杜绝「无主」记录成为越权入口 |
| 归属不可变 | 更新语句不包含 owner_id 与 entry 列，或以触发器拒绝变更 | 防止通过更新改写归属 |
| 版本控制 | version NOT NULL DEFAULT 1，更新时 +1 | 支持 expectedVersion 并发校验 |
| 唯一性 | 登录名标准化后唯一；会话快照按所有者组合唯一；幂等键 request_id 唯一 | 防重复记录与重复提交 |
| 检查约束 | version 大于 0；强度 1～5；reopen_at 晚于创建时刻；状态属于枚举集合 | 让非法值无法入库，而不是只靠前端校验 |
| 外键 | 子记录指向父记录时带 ON DELETE 限制，由应用服务在同一事务中显式删除 | 避免级联删除造成的隐式副作用 |
| 索引 | 业务查询索引必须包含 owner_id 与 entry 前缀 | 让归属过滤成为执行路径的一部分，而不是事后再筛 |
| 时间 | 时刻列存 UTC，日历日期另存本地日期列 | 到期比较与日历读取语义不同 |

约束语义示例：

```
-- 只读校验：任何读取必须带归属条件
SELECT id, version, date, emotions, intensity, event
  FROM emotion_record
 WHERE id = :id AND owner_id = :owner AND entry = :entry;

-- 更新：同时校验归属与版本，版本自增
UPDATE worry_deposit
   SET title = :title, body = :body, reopen_at = :reopen_at, version = version + 1
 WHERE id = :id AND owner_id = :owner AND entry = :entry AND version = :expected;

-- 清除：正文与关联在同一事务中物理删除
DELETE FROM worry_deposit WHERE id = :id AND owner_id = :owner AND entry = :entry AND version = :expected;
DELETE FROM room_appearance WHERE record_id = :id AND owner_id = :owner;
COMMIT;
```

## 3 访问路径与最小权限

数据库账号按职责拆分，避免一个账号既能改结构又能读全集：

表3 数据库账号与权限

| 账号类型 | 权限范围 | 用途 | 禁止 |
|---|---|---|---|
| 应用账号 | 业务表 DML；无 DDL | 应用服务读写 | 读取其他 schema、文件函数、系统表 |
| 迁移账号 | 建表与变更脚本 | 部署与升级 | 运行期在线使用 |
| 只读分析账号 | 仅聚合视图（计数、时长），不含正文列 | 运维统计 | 查询 L3 正文列 |
| 备份账号 | 备份与恢复 | 灾备 | 人工查询业务数据 |

访问路径只有一条：客户端 → 接入层 → 应用服务 → 仓储 → 数据库。数据库不直接暴露给客户端；仓储接口不提供「按编号查询」的无归属方法；应用服务不接受来自客户端的 SQL 片段或排序字段名。查询使用参数化语句，禁止字符串拼接；`ORDER BY` 与列名使用白名单枚举。

补充：① 数据库慢查询日志与错误日志默认会记录语句与参数，必须先配置为不记录参数值（或关闭语句日志），否则正文会进入日志，与 SEC-12 冲突；② 数据库的错误消息不得原样回显给界面，统一由 `DomainError` 转换，避免泄露表名与约束名。

## 4 事务、并发与删除语义

表4 关键操作的事务边界

| 操作 | 事务内包含 | 并发控制 | 失败表现 |
|---|---|---|---|
| 保存记录 | 记录行 + 保存授权行 + 幂等键 | request_id 唯一约束 | 唯一冲突返回既有结果，不重复插入 |
| 更新记录 | 条件更新 + 版本自增 | WHERE 含 expectedVersion | 影响行数为 0 时返回 CONFLICT |
| 清除记录 | 正文行 + 房间关联 + 活动引用 + 台账 | WHERE 含版本 | 任一步失败整体回滚，返回 SERVICE_UNAVAILABLE |
| 寄存到期 | 状态与版本更新 | WHERE 含状态与版本 | 冲突时重新读取，不覆盖 |
| 改密 | 摘要替换 + 全部会话撤销 | 条件含当前摘要 | 影响行数为 0 时返回 AUTH_REQUIRED 或 CONFLICT |

① 事务不得跨越外部调用（模型、检索）——外部调用在事务外完成，避免长事务与不可回滚的副作用；② 幂等键在一次成功提交后不可复用；③ 任何「先查后改」的写法都必须在同一事务或改用条件更新，否则并发下仍会覆盖。

## 5 敏感数据保护

摘要类字段的长度按算法预留（如 255 字符），与算法参数解耦，便于 D-01 决策后不改表结构。盐与参数随摘要存储，不单独建表。

静态加密、字段级加密与密钥托管取决于 D-04（存储位置）与 D-06（备份策略），本稿只固定三条要求：① 备份介质与数据库文件不得以明文散落于未受控的共享目录；② 密钥不与数据同库、不入仓库；③ 任何导出（数据迁移、问题排查、演示数据）必须使用合成数据或经脱敏，且不得扩大正文授权范围。

## 6 备份、恢复与「清除不复活」

备份必须满足两个条件：备份中不存在文字销毁正文；恢复后已清除记录不重新出现。

如果从清除操作之前的时间点恢复整库，被清除的记录会随备份一起回来。处理方式：

**重放清除台账**：维护 `clear_tombstone`（record_id、owner_id、entry、cleared_at，无正文）。恢复后按台账逐条再次物理删除。优点是精确；缺点是台账本身需要在恢复后仍然可用，因此台账必须与备份分开保存或随备份一起保留。

## 7 与系统设计安全章节的对应

表5 安全要求与数据库措施对应

| 安全要求 | 系统设计位置 | 数据库侧措施 |
|---|---|---|
| SEC-01 凭据与令牌只存摘要 | 4.3.1 | 凭据表只存摘要与盐；会话表只存 token_digest |
| SEC-02 会话撤销 | 4.3.3 | 会话状态与撤销时间可更新；改密事务批量置无效 |
| SEC-03 五要素校验 | 4.4.2 | 所有读写语句带 owner_id 与 entry；索引含归属前缀 |
| SEC-04 版本并发 | 4.4.6 | version 列与条件更新；冲突表现为影响行数 0 |
| SEC-05 用途授权 | 4.4.4 | 授权表记录 purpose 与 resource_version，可撤销 |
| SEC-06 破坏性操作 | 4.4.6 | 清除在单事务内完成；物理删除；台账不含正文 |
| SEC-07 默认不持久化 | 4.5.1 | 不设普通会话表；运行状态无对应表 |
| SEC-08 文字销毁零留存 | 4.7 | 无表、无字段、无日志参数记录 |
| SEC-12 日志最小化 | 4.5.3 | 关闭语句参数日志；错误消息不回显 |
| SEC-14 资源与并发 | 4.8.3 | 幂等键唯一；单活动约束由应用层与唯一索引共同保证 |
