## 1. 能力标记与可信入口

HTTP能力接口为 `GET /api/capabilities`，返回 `{entry,features:[{reqId,status,reason?,fallback?}]}`。实际 `status` 仅为 `AVAILABLE/SIMULATED/UNAVAILABLE`：分别表示已验证可用、模拟、不可用。“跳转／降级”是界面处理方式，不新增服务枚举。

入口由受控接入适配与会话绑定确定。客户端不能用 `entry` 参数、`X-Entry`、User-Agent或Origin自报可信平台。当前优先开放WEB；DESKTOP、WECHAT在身份与入口绑定完成前保持模拟或不可用。前端隐藏按钮不能替代服务端权限检查。

### 4.1 后续可执行方法与前置条件

本地核对只发现`prototype/package.json`的Vite脚本，没有已核实可运行的Electron验证工程，不提供虚构的`electron:test`命令。以下是W2原生初测、W4互动集成的操作方案，当前全部未执行，也不作为本次设计作业前必须实现的能力。

1. **准备环境：**程杰后续建立仅含受控本地资源、五个白名单方法和合成场景的最小验证工程，记录工程路径、启动命令、锁文件和提交哈希；缺工程时记录“前置未具备”，不把浏览器拖动原型当作Electron结果。准备单屏和双屏、100%／125%／150%DPI、有声和静音环境；穿透测试前先验证可达的恢复／关闭入口。
2. **逐项执行E01～E09：**先开普通窗口确认退出，再逐一开启透明、置顶、拖动和穿透；依次切换全屏、跨屏拖动、断开副屏、改变DPI。每项恢复初始配置后在相同环境做三次，记录每次实际结果，不把一台样机扩写为全部系统通过。
3. **故障注入：**用开发工具模拟offline和延迟，执行暂停／cancel／切任务；使用开发工具使测试渲染进程崩溃，观察主进程移除浮层。检查其他应用能点击、无残留声音；E08用有限但越界坐标、非有限值、未知方法和非受控导航验证拒绝；E09待可信入口方案实现后再用测试身份验证，未实现时保持未执行。
4. **性能采样：**固定窗口大小、设备供电与场景，预热30秒，记录空闲30秒基线，再连续运行60秒；用Chromium Performance记录帧／主线程，用任务管理器记录进程CPU、内存，用Memory快照比较资源引用。每个场景做三次并报告各次值及最差值；rAF间隔只是调度指标，不能单独当作真实绘制帧率。当前未编写或运行采样探针。
5. **清理复测：**同一进程依次做开始、暂停、继续、静音、重置、退出，共10轮；每次退出等待5秒，检查ResourceScope登记的帧、timer、监听、捕获、活动音源和物理实例归零。引擎公共AudioContext可保留，但活动音源必须停止。原生窗口关闭后由主进程检查无失效浮层；REQ14用专用合成标记检查网络、存储和关闭后可访问状态。
6. **复核：**程杰登记操作及原始记录，曾俊涛复核重现方法，郭昱祺复核反馈与退出可达性，关欣复核IPC、可信入口与REQ14隔离。无真实结果及非作者结论不标通过；问题修复后按原环境复测。

### 4.3 降级门槛与开放条件

下列数值为**建议验证基线，未测量、未获团队确认**，用于让后续实验可执行。它们不修改09号数量上限；样机试验后由程杰、曾俊涛、郭昱祺记录采纳或调整依据。清理、隐私及可退出性是硬条件，不能用平均帧率抵消。

| 触发门槛 | 降级／停止动作 | 恢复条件 |
|---|---|---|
| 连续两个5秒采样窗的帧间隔p95>33.4ms，或p99>50ms | 敲击粒子降为50；弹珠球上限降为5、关闭拖尾；不提高声部上限 | 降级配置重新执行三次采样并复核；运行中不反复自动升档 |
| 降级后仍连续两个采样窗超过上述门槛 | 暂停动态互动，提供静态／低动态页面和退出；不能把失速状态标为流畅 | 后续修复或确认更低配置后复测 |
| 退出5秒后仍有新帧、音符、捕获或活动资源登记；REQ14合成标记进入禁用通路 | 立即禁用受影响入口并登记缺陷，不能仅降低数量继续开放 | 清理／隔离缺陷修复后专项复测及非作者复核 |
| 同进程10轮中，后3轮退出后heap逐轮增长，且每轮超出预热基线的量均大于max(10MiB,基线的10%) | 作为疑似泄漏停止本轮，保留合成资源计数与快照定位；不单凭一次heap波动断言泄漏 | 排除JIT／GC波动并修复持有引用后按同环境重测 |
| 穿透／缩放／多屏／渲染崩溃导致退出不可达或失效浮层阻挡桌面 | 关闭相关选项，由主进程销毁浮层；回退普通窗口／Web画布 | 对应E项复测通过，并确认恢复入口可用 |
| 音频拒绝播放、设备不可用 | 停当前音源，切为无声可视反馈；暂停／重置／退出仍可用 | 用户手势重新启用且验证成功，不自动补播 |
| 任一能力无环境记录、结果或复核；DESKTOP／WECHAT未建立可信身份 | 相关入口保持SIMULATED或UNAVAILABLE，提供说明／Web路径 | 对应专业确认、实现与运行证据齐备后才允许AVAILABLE |

E01～E09按能力依赖验收；原生窗口验证、互动性能、可信身份、业务联调分别记录，互不替代。CPU与进程内存报告实测值及变化，不在缺少目标机预算时编造已达到的百分比。

## 5. 运行限制与异常处理

| 条件 | 产品行为 | 清理与恢复 |
|---|---|---|
| 页面隐藏／面板收起 | 本地互动暂停，网络排练先屏蔽旧结果并请求PAUSE | 停计时、物理、音源；返回由用户继续 |
| 网络不可用 | 本地训练／销毁可在已加载资源内运行，网络操作显示实际失败／待确认 | 停网络轮询；不把旧账号缓存当离线记录；重连不自动重发正文 |
| 退出／切任务 | 本地先停止，必要时发送既定动作／取消 | 释放帧、监听、捕获、音频和运行实例；REQ14立即清私有内容 |
| 渲染或音频故障 | 降低效果或静音，始终提供退出 | 故障不阻止销毁清空；浮层由主进程兜底移除 |
| 球／粒子过多或帧间隔异常 | 限制新增、降低数量或简化效果 | 不以拥塞为由阻塞退出；性能阈值须实测后确定 |
