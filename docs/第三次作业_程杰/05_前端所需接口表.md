## 1. 通用协议

同源 `/api`，JSON／UTF-8，HTTP正文最大128 KiB。前后端共同引用 `shared/contracts/*.js` 的严格Zod Schema；结构校验不替代归属、入口、用途及版本校验。共享Schema为设计基线，不宣称已有可运行实现。

成功为 `{data,meta:{requestId}}`，204无正文；错误为 `{error:{code,message,fields?,retryAfterSeconds?},meta:{requestId}}`。下表响应列表示 `data` 内容。字段错误不回显密码、Cookie、正文、提示词或堆栈。

Cookie为 `__Host-session`，HttpOnly、Secure、SameSite=Lax、Path=/且无Domain。客户端不读取Cookie原文、不持久化令牌。所有写请求校验会话CSRF及允许的Origin；CSRF头名由共享契约冻结，本文不自行命名。登录、退出后重新取得上下文和CSRF。所有私密及任务响应no-store，前端仅内存缓存；不进入Service Worker、CDN或持久化缓存。

表内“上下文”指当前有效匿名或登录上下文，仍执行会话、入口和CSRF规则。`GET /api/auth/context` 可建立匿名上下文，不能要求调用者事先已有该匿名会话。表内“登录”还要求本人、当前可信入口与相应用途；客户端不能提交可信 `ownerId/entry`。

以下为32个唯一HTTP方法／路径。日历的 `GET /api/records?kind=EMOTION&from=...&to=...` 是同一路径的筛选用法，不额外计数。所有POST／PATCH／PUT均须CSRF；只在规范要求的body中带 `requestId`，登录、退出、改密不擅自增加字段。

## 3. 会话与用途授权（5个）

| 方法与路径 | 页面／鉴权 | 请求字段 | 响应与控制 |
|---|---|---|---|
| `POST /api/sessions` | 陪伴、排练、查询；上下文 | `{requestId,mode}` | 201 `{sessionId,activityId,sessionGeneration:0,activityGeneration:0,mode,state:ready}`；mode限定LISTEN／ORGANIZE／REHEARSE／SEARCH |
| `POST /api/sessions/:id/switch` | 切换模式；上下文 | `{requestId,targetMode,expectedSessionGeneration,selectedContextIds}` | 200新activityId及双代次；先验目标能力再停旧活动，按选择携带；不自动外发 |
| `POST /api/sessions/:id/actions` | 会话控制；上下文 | `{requestId,action,expectedSessionGeneration,expectedActivityGeneration}` | 200当前state与双代次；action仅PAUSE／RESUME／RESTART／FINISH_REHEARSAL／END；409标准错误不保证有state／双代次，按R02停止旧会话 |
| `POST /api/consents` | 外发或保存确认；上下文，SAVE须登录 | `{requestId,purpose,operation,payload,sessionId?,activityId?,sessionGeneration?,activityGeneration?}` | 201 `{consentId,purpose,expiresAt}`；AI_PROCESS／SEARCH_PROCESS／SAVE，绑定身份、入口、代次与同载荷，初始5分钟 |
| `POST /api/consents/:id/revoke` | 撤销用途许可；上下文 | `{requestId}` | 200返回revoked；取消相关在途任务和未提交许可，不隐式清除已保存记录 |

PAUSE／RESTART／FINISH_REHEARSAL／END使受影响旧任务失效；RESUME不重放旧请求。RESTART建立新活动；FINISH_REHEARSAL进入reviewing并保留本轮本人消息供选择；END才清会话正文与临时授权。固定训练、画布与物理不逐步调用会话动作。

没有独立GET业务会话状态接口。409不从错误体或任务GET猜测会话状态；前端封锁旧会话，用户可用既有POST sessions新建空会话。控制超时仅在原身份／入口仍有效且没有后续冲突时，以原requestId和完全相同动作载荷核实；成功只证明原操作结果，不恢复旧任务。此安全替代方案的专业确认见§10 R02。

## 4. Agent与检索（6个）

任务请求中“双代次”均展开为准确字段 `sessionGeneration,activityGeneration`，不发送“generation”等替代字段。

| 方法与路径 | 鉴权／用途 | 请求字段 | 响应与取消规则 |
|---|---|---|---|
| `POST /api/agent/tasks` | 上下文，AI_PROCESS | `{requestId,sessionId,activityId,sessionGeneration,activityGeneration,mode,operation,selectedText,selectedContextIds,consentId}`；附加字段见下表 | 202 `{requestId,status:pending,sessionId,activityId,sessionGeneration,activityGeneration}`；仅LISTEN／ORGANIZE／REHEARSE |
| `GET /api/agent/tasks/:requestId` | 本身份本入口有效活动 | 无body | 200任务状态；completed含上述关联标识及 `result:{text,userMessageId,replyMessageId}`；代次或身份失效不显示 |
| `POST /api/agent/tasks/:requestId/cancel` | 目标任务归属；上下文 | `{requestId}`为本次取消操作的新ID，路径为目标任务ID | 200目标任务cancelled；已取消幂等；已完成任务也可撤销后续可取结果，不能撤回已展示内容 |
| `POST /api/search/tasks` | SEARCH会话，SEARCH_PROCESS；模型整理另需AI_PROCESS | `{requestId,sessionId,activityId,sessionGeneration,activityGeneration,question,selectedContextIds,consentId,aiConsentId?}` | 202任务受理，沿用任务关联与状态规则；SEARCH不发给agent接口 |
| `GET /api/search/tasks/:requestId` | 本身份本入口有效活动 | 无body | 200状态；completed的 `result:{searchState,claims,sources,hasConflict,partial}`；EMPTY是无资料，failed是执行失败 |
| `POST /api/search/tasks/:requestId/cancel` | 目标任务归属；上下文 | `{requestId}`为取消操作ID | 200目标任务cancelled；取消后不再返回正文；取消不被AI创建额度阻断，仍有限频 |

| Agent operation | mode | 附加输入与限制 |
|---|---|---|
| REPLY | LISTEN／ORGANIZE | selectedText或有效selectedContextIds；不能提交任意system／messages |
| OBJECT_ORGANIZE | ORGANIZE | 已保存物件：resourceId、resourceVersion；临时物件：`objectDraft:{shape,title,description}`；两种来源互斥，只带选定物件 |
| REHEARSAL_REPLY | REHEARSE | `simulation:{scene,counterpart,goal,style}`；明确AI模拟角色 |
| REHEARSAL_SUMMARIZE | REHEARSE，reviewing | simulation与1～20个recognizedMessageIds；只允许本人本轮消息，不带整轮对话或AI消息冒充认可 |

任务状态为 `pending/running/completed/cancelled/failed/expired`；失败原因 `TIMEOUT/PROVIDER_UNAVAILABLE/OUTPUT_INVALID`。每任务每客户端至少1秒间隔、最多1个在途轮询，终态停止。前端本地Abort不等于远程取消；服务接受取消后不得再读取正文，供应商迟到也不得回填。

Search结果的claims为 `{id,summary,sourceIds}`，sources为 `{id,title,url,publishedAt,retrievedAt,quality}`；publishedAt可null，quality为CURRENT／STALE／UNKNOWN。最多10条摘要与10个来源，每摘要最多1000码点；sources空只能EMPTY并说明资料不足，冲突／过期／部分失败如实展示。

Record为 `{id,kind,title,payload,createdAt,updatedAt,version}`。移出房间只是取消关联，不清除物件正文；清除物件才在事务中移除关联。失败不显示空房间或已清除。

| kind | 创建／可编辑payload | 前端必须保持的语义 |
|---|---|---|
| CONVERSATION | `{title,sessionId,selectedMessageIds}` | 当前活动1～20条选中消息，展开正文合计最多12000码点；保存快照只读 |
| EMOTION | `{date,emotionWords,intensity,event,timeZone}` | event可空，时区用允许的IANA值；同日多条；只保存不调用分析 |
| WORRY_OBJECT | `{shape,title,description?}` | shape=TANGLE／STONE／NOTE；无文字拟用可编辑默认title“想先放一放的事”，只保存外观时完全省略description；放旁边不自动保存或AI；文案与默认值待R03签认 |
| REHEARSAL_DRAFT | `{scene,sessionId,activityId,recognizedMessageIds,expressions}` | expressions为1～20条非空文本，总计最多12000码点；仅确认表达，整轮对话不持久化 |
| DEPOSIT | `{title,body,reopenAt}` | body非空、reopenAt未来；列表／未取出详情不含body；首版正文不可编辑 |
| QUERY | `{searchRequestId}` | 必须当前入口已完成且有来源的SUCCESS结果；服务端复制证据，客户端不提交自造claims／sources；EMPTY或failed不可保存 |

QUERY持久化状态优先级为 `CONFLICTED > PARTIAL_SUCCESS > STALE_SOURCE > SUCCESS`，区别于临时 `searchState=SUCCESS/EMPTY`。不将不同状态枚举混用。

无文字物件的拟定保存payload为`{"shape":"STONE","title":"想先放一放的事"}`，沿用现有DTO，完全省略`description`。确认页展示最终名称，SAVE绑定实际载荷；改名后需重新授权。默认名称和保存文案待郭昱祺确认，详见01号§2与本表R03。

## 8. 错误、超时与取消

| HTTP／code | 页面反馈 | 清理与恢复 |
|---|---|---|
| 400、413／INVALID_INPUT | 定位字段／体积问题；不回显敏感载荷 | 停加载，修改后再提交；不调用模型或写DB |
| 401／AUTH_REQUIRED | 登录缺失或过期 | 遮蔽正文，失效身份代次、授权、缓存及在途任务，再引导登录 |
| 403／ACCESS_DENIED | CSRF、用途或权限失败 | 停相关操作，按原因重取上下文或重新选择；不循环授权重试 |
| 404／NOT_FOUND | 内容不可用 | 清该对象失效引用；不区分他人／其他入口对象是否存在 |
| 409／CONFLICT、INVALID_STATE | 版本、幂等载荷或活动状态冲突 | 保持安全停止，核对实际版本后由用户决定；不覆盖或恢复旧任务 |
| 429／RATE_LIMITED | 显示Retry-After／retryAfterSeconds | 停止自动重复创建或无限轮询；取消／退出走既定控制通路 |
| 503／SERVICE_UNAVAILABLE | 服务暂不可用 | 保留允许保留的当前编辑；不伪装空列表、EMPTY或全零统计 |

普通API初始总时限5秒，外部任务含排队30秒；这些是设计配置。持久写超时不等于失败，以原requestId和相同载荷核实后再提示；结果无法确认则保持待确认。外部任务failed后由用户手动新请求重试，重新检查许可和额度，不叠加SDK无限重试。

暂停／切换／退出先本地失效结果接收资格，再发服务控制。断网时继续屏蔽旧结果并提示远程未确认；重连仅核实既有操作，不自动重发正文。TIMEOUT是任务failureReason，不新增同名HTTP业务code。

cancel／会话动作使用独立请求句柄，不能复用已经Abort的旧任务signal。只有匹配目标的取消接口成功明确返回cancelled，或任务GET返回cancelled，才显示服务端已取消；本地Abort、404、过期、请求发出均不是取消证据。核实返回completed也不得展示或缓存旧正文。换账号清旧任务、记录列表／详情、选择、授权和待核实操作，禁止新身份重放旧请求。

持久写核实必须保留原requestId和相同载荷，不能替换consentId后当作同载荷重试。原SAVE过期时的幂等查找顺序尚未冻结，按R05保持结果未知，不新建保存；已知recordId才可用既有详情读取核实当前事实，相似标题／条数不能证明本次写入成功。
