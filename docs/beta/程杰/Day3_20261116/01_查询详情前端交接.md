# Beta Day3｜查询详情前端交接

执行人：程杰。日期：2026-11-16。关联 [B02 / Issue #105](https://github.com/impureWine/404NOTFOUND/issues/105)。本记录描述隔离候选上的前端改动，不表示后端 DTO 已对齐、全组验收完成或已上线。

## 前端改动

- 查询详情在拿到来源快照数组时展示全部来源，而不只展示被某条摘录引用的来源；每项显示来源级别、发布时间、获取时间、核验状态及时效标签。
- 摘录中的来源引用定位到详情页内对应来源快照。旧详情 DTO 没有 `sources` 数组时，回退到 `claims[].evidence[].source` 并去重。
- 展示查询状态、不确定性说明及 `SAVED` / `LEGACY_BACKFILL` 来源标记；无法安全解析为 HTTP(S) 的链接不提供外链。

## 接口交接与限制

当前候选后端的 `RecordService.get()` 查询详情只返回问题和带证据的摘录；其 `content` 尚无 `sources`、查询状态、不确定性说明或来源快照来源标记。`SavedQueryRepository.get()` 目前通过摘录证据关联查询来源，所以没有被证据引用的来源不能由这条现有查询返回。前端回退逻辑保证旧详情仍可读，但在后端提供完整快照 DTO 前，页面无法显示被省略的来源，也无法从真实 API 展示未返回的状态与标记。

后端负责人需确认并交付查询详情 DTO：保留保存时的查询状态和不确定性说明，返回该查询全部来源快照及来源质量字段，并定义历史补录标记的持久语义。此处不直接改动后端模块，避免绕过负责人的契约调整；在接口联调完成前，相关完整快照验收保持待办。
