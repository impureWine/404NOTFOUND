## 2. C-05：REQ14 文字销毁页可达性（P0）

### 2.1 静态检查（秒级）

```powershell
# 是否存在销毁页面
Get-ChildItem web-prototype -Filter *.html | Where-Object { $_.Name -match 'destroy|burn' }

# 新外壳是否挂载旧路由与桌宠
Select-String prototype/src/App.jsx -Pattern 'ROUTES|DesktopPet'
```

预期（当前）：两条命令**都没有输出**。

判定：`web-prototype` 无销毁页 + `App.jsx` 未挂载 `ROUTES`/`DesktopPet` → **页面不可达**，四项运行时证据（Network/Storage/日志/重开）无法取得。

### 2.2 构建后探测（静态检查通过后再做，用于正式取证）

```powershell

npm run preview -- --port 5207     # 另开一个窗口保持运行
```

```powershell
# 另开窗口：五个候选地址是否出现销毁界面
foreach($p in @('/destroy','/text-destroy.html','/destroy.html','/?page=destroy','/#destroy')){
  $r = Invoke-WebRequest -Uri ("http://127.0.0.1:5207" + $p) -UseBasicParsing -TimeoutSec 10
  "  {0,-20} HTTP {1}  长度 {2}" -f $p, $r.StatusCode, $r.RawContentLength
```

判定：若全部返回与首页同长度的外壳（SPA 回退），说明无销毁 UI；若有页面返回销毁界面，再按 `docs/alpha/关欣/Day6_20261028/tests/tencent-doc-access-check.cjs` 同款思路做**无痕交互取证**。

## 3. A-02 / D5-10：失效会话的错误码（P0-02）

```powershell
cd backend
node --test test/security/day4-destroy-and-clearing.test.js
```

预期：4/4 通过；其中 D4-04 用例断言"失效会话的清除请求必须被拒绝（401 或 403）"。

要**精确复现 403 而不是 401**，看探针输出：

```powershell
node --test test/security/day5-p0-recheck.test.js 2>&1 | Select-String 'D5-10'
# [D5-10] {"staleWriteStatus":403}
```

定位（代码）：

```powershell
Select-String backend/src/http/request.js -Pattern 'resolveContext|verifyCsrf|requireAuthentication'
```

预期行号顺序：`resolveContext` → `verifyCsrf` → `requireAuthentication`。因为 CSRF 在认证之前，失效会话在 CSRF 处就抛 `ACCESS_DENIED`（403），永远走不到 401。

修复验收条件：失效会话的写请求返回 **401 `AUTH_REQUIRED`**，且记录未被清除；同时把 D5-10 的断言改为 401。
