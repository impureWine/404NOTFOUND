## 3. 缺陷与缺口

### B01-CONC：撤回许可不阻断在途任务（与 B3-INFLIGHT 同源）

| 编号 | 触发动作 | 实测 | 期望（建议） |
|---|---|---|---|
| B01-CONC | 任务在途时并发发起「撤回许可」与「读取任务」 | 并发均无 5xx；任务随后仍 `completed`，`result` 回填 | 撤回即取消在途任务并删除 `result`；迟到回复不回填 |

- **影响**：用户撤回许可后，仍在处理的正文会继续送进模型并留下结果；与 Day3 记录的 `B3-INFLIGHT` 属同一根因，不应重复计缺陷。
- **责任**：程群（`#166`）／李泉毅（`#128`）。
- **现状**：两个候选都实现了撤回失效，但都未进 main；合并后应复跑本条，期望 `finalStatus = cancelled`、`hasResultFinally = false`。
- **复现**：`beta-day5-privacy-boundary.test.js` 的 `[B5-CONC]`。

### B06-PAGE：文字销毁的受测页面与实现范围

- 可达页面是 `prototype/src/live/Games.jsx` 的 `PrivateText`，由 `App.jsx` 的 `private-text` 路由挂载，标题「文字焚化与黑洞」。
- `prototype/src/routes.jsx` 里另有 `destroy: { title: '文本销毁', page: DestroyPage }`，但整个 `prototype/src` **没有任何文件 import 该路由表**，因此该页面不可达。
- 结论：`P0-01`（REQ14 无入口）在**运行时已有可达页面**，但存在两套实现（`PrivateText` 可达 / `DestroyPage` 死代码）。对外表述应写明受测对象是 `#private-text`，不能把 `routes.jsx` 的登记当作入口证据。
- 责任：程杰（前端入口）／郭昱祺（入口与文案）。
