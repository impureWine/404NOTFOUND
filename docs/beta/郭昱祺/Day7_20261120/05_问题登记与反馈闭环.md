# 问题登记与反馈闭环

尚无真人反馈，下表是可复制模板；脚本排练结果单独见演示文档。

| 字段 | 内容 |
| --- | --- |
| 编号/发现日期/来源 | TRIAL-___ / 实际日期 / 真人观察、作者走查、测试报告之一 |
| 候选/环境 | 前后端完整SHA、URL、模式、浏览器/视口、测试账号匿名代号 |
| 关联任务/最短步骤 | U01～U08；从哪个状态开始、点击/输入什么 |
| 期望/实际/影响 | 可观察行为，不把个人感受直接写成根因 |
| 频次/提示 | 发生次数/尝试次数；是否有主持人协助 |
| 证据 | 已许可的脱敏截图/原话，不含密钥、Cookie、密码或真实烦恼 |
| 优先级/负责人 | P0隐私/越权或关键数据损失；P1主链阻断；P2可绕过交互；P3视觉建议；负责人待分派 |
| 状态/处理依据 | 待分诊→已指派→修订→待复测→关闭/结转；产品方案决策先给用户选项 |
| 复测 | 修复SHA、复现步骤、实际结果、非作者复核者、证据链接；未复测不可标关闭 |

处理建议：UX整理可观察问题→程杰核对界面；模型/训练程群、身份/接口李泉毅、数据/快照庄剀涵接续；关欣复核安全、曾俊涛复核测试，张王昊统一候选与范围。此处是交接路径，不表示已取得确认或已发送消息。

每条反馈关联实际Issue；无反馈时不创建虚假缺陷。候选变化时先判定影响场景，再补测，不用旧绿色测试关闭新版本问题。少量参与者只用于发现问题，完成率/用时/评分仅在有有效记录后统计，跳过与环境阻塞单列。
