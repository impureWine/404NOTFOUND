## 4. 静态检查补充（未执行真实 API）

- business.runTask 的取消 `.catch(() => {})` 吞掉取消错误，支持 UI04 观察；75 秒超时提示只有“已请求取消”，应继续区分取消确认。
- ConsentService.revoke 只改标记，不调用 task 取消；前端 client 无 revokeConsent 方法，不能用取消勾选代替服务端撤回。
- TaskService.action 的 END 只走默认 cancelSessionTasks；默认不包含 completed。完成结果在 END 后的可读性及清理承诺，交程群／李泉毅／关欣复核，本次未做真实 API 验证。
- 退出与换号在 App 中通过 identityEpoch 重建页面，useAuth 有本地退出及服务器撤销待确认文案；任务轮询 401 尚未向 useAuth 统一传播，不能据存在 logout 功能认定失效链路完成。
- 安全岗前日记录“文字销毁无入口”。本次候选 App 已有 `#private-text` 与减压练习入口，应由关欣在当前候选重新验证，不沿用旧结论认定仍缺入口。本次未开展文字销毁隐私专项。
- 安全岗清除提示冲突 P1-01：当前正式 RecordVault 使用两段式清除与未知结果核实；Day4Components 等旧展示代码另有模拟说明。此次未执行带真实记录的清除流程，无法关闭该问题。统一文案应以真实清除结果为准，不将旧演示“刷新恢复”带入正式入口。
