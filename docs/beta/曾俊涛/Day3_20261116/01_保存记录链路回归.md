# Beta Day3｜保存记录链路回归

执行人：曾俊涛。日期：2026-11-16。受测候选：`main@455a17c615118fcec49f1eee727a357ae3e134e5`。关联 [B02 / Issue #105](https://github.com/impureWine/404NOTFOUND/issues/105)。这是测试交付，不代表 B02 已由全组验收或已上线。

## 范围与环境

按 Day3 分工验证真实页面的“主动保存 → 列表 → 正文 → 两步清除”，以及重复提交、保存结果未知后的重试、刷新和换号。Windows、Node v24.18.0、Playwright Core 1.65.1、本机 Edge 无头模式；前端是真实 React 页面，`/api` 代理到隔离 PGlite 的后端测试服务，账号与正文均为合成数据。未接入正式 PostgreSQL、真实用户、移动端或生产环境。清除后的数据库正文子表检查由后端集成测试覆盖。

## 实测结果

| 场景 | 断言与结果 | 证据 |
| --- | --- | --- |
| 保存前确认 | 勾选独立 SAVE 许可后，`POST /api/records` 返回 **201**；本人列表由 0 变 1 | [页面保存前](evidence/01-empty-vault.png)、[保存后列表](evidence/02-saved-list.png)、[机器结果](evidence/browser-record-lifecycle.json) |
| 重复保存请求 | 同一 `requestId` 和载荷再次提交仍返回原记录，列表保持 **1** 条 | [机器结果](evidence/browser-record-lifecycle.json)；[可复跑脚本](tests/browser-record-lifecycle.mjs) |
| 列表与正文 | 页面列表只显示元数据；点击详情后本人可读合成正文 | [详情截图](evidence/03-record-detail.png) |
| 刷新 | 页面重载后列表与本人详情仍可读 | [机器结果](evidence/browser-record-lifecycle.json) |
| 换号 | A 退出、B 登录后列表为空；B 读取 A 的记录详情返回 **404** | [B 页面](evidence/04-account-b-isolated.png)、[机器结果](evidence/browser-record-lifecycle.json) |
| 两步清除 | 第一次仅取得一次性确认，记录仍在；第二次明确确认后列表为 0，旧详情 **404** | [一次性确认](evidence/05-clear-confirmation.png)、[清除后页面](evidence/06-cleared-vault.png) |
| 失败重试 | 测试代理先把创建请求转发至服务端并取得 **201**，再把页面响应替换为合成 **503**；页面保留原请求，用户点击“用同一请求重试核实”后返回同一记录，列表仍仅 **1** 条 | [待核实状态](evidence/07-save-unknown.png)、[核实后页面](evidence/08-save-retry-confirmed.png)、[机器结果](evidence/browser-record-lifecycle.json) |
| 后端聚焦回归 | 记录 API、Repository、清除安全和 Day2 新增授权矩阵合计 **26/26** 通过 | [原始输出](evidence/record-backend-tests.txt) |

后端授权矩阵中的部分用例**断言现存缺陷签名**，因此 26/26 不能解释为安全问题均已修复。Day2 新增的安全报告与交互走查已纳入 [缺陷与复测记录](02_缺陷与复测记录.md)。
