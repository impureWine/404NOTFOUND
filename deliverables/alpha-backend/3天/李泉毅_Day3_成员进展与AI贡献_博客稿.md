## 从昨日站立式会议至今的进展

今天在 Day 2 认证与资料服务的基础上，继续完成会话、查询任务、任务取消和改密撤销链路。会话服务支持创建会话以及 `PAUSE`、`RESUME`、`RESTART`、`FINISH_REHEARSAL`、`END` 等动作，并通过会话代次和活动代次判断请求是否仍然有效。会话结束或代次变化后，未完成的查询任务会被取消，已经失去资格的迟到结果不会重新写回。

查询任务已经实现 `pending`、`running`、`completed`、`failed` 和 `cancelled` 状态，支持创建、状态查询和主动取消。服务端按当前所有者隔离任务，其他账号访问同一任务编号时返回 404，避免通过错误差异确认他人的任务是否存在。`SEARCH_PROCESS` 许可同时绑定所有者、用途、操作、会话与活动代次、问题载荷摘要、有效期和撤销状态，不能把一次查询许可挪给另一段问题。

账号安全部分补充了多会话改密验证：同一账号同时存在两个活动会话时，修改密码会撤销全部旧会话，旧密码无法再次登录，新密码可以正常使用。我还为内部模型 HTTP 边界增加认证守卫，匿名请求返回 401，且不会触发模型适配器；认证上下文换发会保留原可信入口，防止桌面端会话被错误换发为 Web 入口后扩大记录读取范围。

本次新增会话与查询 HTTP 集成测试，覆盖许可与载荷绑定、任务状态查询、跨账号隔离、主动取消、会话 `END` 后旧代次创建任务返回 409，以及改密撤销多个活动会话。合并团队新增的 22 条安全专项后，修复了其中 5 项失败。最新本地完整回归为后端 84/84 通过、前端 API 适配器 6/6 通过，Vite 生产构建通过。

## 存在的问题与遇到的困难

1. 2026-10-24 使用“软件工程”、限制 3 条、超时 5000 ms 进行 Wikipedia 实网探测，结果为 `TIMEOUT`，耗时约 5.02 秒且来源数为 0。因此目前只有离线适配器测试通过，不能说真实检索成功。
2. 查询任务状态当前保存在单进程内存中，适合本地功能验证，但多实例部署时会产生状态不共享问题，后续需要迁移到数据库或共享队列。
3. 内部模型接口最初缺少认证闸门，匿名请求可能进入模型适配器；安全专项测试发现后已增加认证守卫，并验证匿名请求不会触发适配器。
4. 认证上下文换发最初会默认选择 Web 入口，存在桌面会话权限范围被改变的风险；现已改为继承原 `entryPointId` 并补充跨入口回归测试。
5. 当前自动化使用 PGlite，尚不能替代正式 PostgreSQL 16、真实浏览器、真实模型服务和部署环境验收。

## 今日心得

异步任务的关键不只是“能返回结果”，而是结果回来时是否仍属于当前账号、当前入口、当前会话和当前活动代次。取消按钮只能表达用户意图，后端还必须让旧任务失去回填资格。今天的安全专项也说明，认证成功并不代表权限链完整；会话换发、内部接口和异常路径同样需要用负向测试验证。
