## 2. 安装

当前机器没有全局 `npm`，本次使用Codex运行时附带的pnpm完成安装。普通开发机可在 `backend` 目录运行：

```powershell
npm install
```

环境变量从 `.env.example` 复制。不得提交真实数据库密码、连接串、搜索凭据或用户正文。

## 3. PostgreSQL迁移

准备PostgreSQL 16数据库并设置：

```powershell
$env:DATABASE_URL = 'postgresql://app_user:password@127.0.0.1:5432/404notfound'
$env:DATABASE_SSL = 'false'
npm run migrate
```

预期输出为本次新应用的迁移名称，例如：

```json
{"applied":["001_baseline.sql","002_data_service_support.sql","003_interface_contract_alignment.sql","004_identity_repository_support.sql"]}
```

再次执行应返回空数组。若已执行迁移的文件内容发生变化，执行器会因校验和不一致而停止；应新增迁移，不应篡改已部署历史。

本机没有 `psql`、Docker或PostgreSQL服务，因此本次只在PGlite PostgreSQL WASM隔离引擎中实际执行。正式服务仍须由团队在PostgreSQL 16环境复跑。

## 5. 仓储调用边界

仓储方法中的 `accountId`、`entryPointId` 必须来自服务端已验证会话。HTTP请求体或自定义请求头不得直接决定这两个值。

注册仓储要求调用方传入32字节 `registrationPayloadHash`。该值必须由认证应用层对规范化注册载荷使用服务端密钥执行HMAC生成，不得直接使用明文、普通无密钥摘要，也不得从带随机盐的密码摘要反推。`registration_requests.expires_at` 只记录24小时幂等窗口；当前数据层未包含定时清理任务，部署前应由运维任务按过期时间清理元数据，并保留账号真实状态。

主动保存示例调用必须传入密文字节，而不是明文：

```js
await recordRepository.create({
  accountId,
  entryPointId,
  requestId,
  kind: 'CONVERSATION',
  titleCiphertext,
  titleKeyVersion: 1,
  details: {
    messages: [
      { role: 'USER', contentCiphertext, cipherKeyVersion: 1 },
    ],
  },
});
```

当前开发应用层已提供AES-256-GCM字段加密，但仍没有正式密钥托管与轮换服务；不能把测试用的合成字节或环境变量密钥当成生产级加密验收。认证层和应用层必须在调用仓储前完成身份、用途许可和加密。

记录列表返回 `{items,nextCursor}`。游标由服务端签发并绑定账号、入口和筛选类型，不应解析、改写或跨范围复用。

`RecordRepository.get` 返回会话快照、情绪、烦恼物件和演练草稿的密文详情。QUERY 详情由 `SavedQueryRepository.get` 返回来源与证据链；DEPOSIT 详情由 `getDeposit` 按数据库时间校正状态，未主动取回前不返回正文。HTTP应用服务应按记录类型组合这些仓储结果并完成解密映射，不能把列表接口当详情接口使用。

清除必须分两步：

```js
const confirmation = await recordRepository.issueClearConfirmation({
  accountId,
  entryPointId,
  recordId,
  requestId: confirmationRequestId,
  expectedVersion,
});

await recordRepository.clear({
  accountId,
  entryPointId,
  recordId,
  requestId: clearRequestId,
  expectedVersion,
  confirmationId: confirmation.confirmationId,
  confirmed: true,
});
```

确认两分钟有效。成功清除会消费确认，并在同一事务中清理该记录的正文子表、房间关联和授权；只取消界面操作时不得调用 `clear`。

## 6. 真实检索

适配器固定调用：

```text
https://zh.wikipedia.org/w/api.php
```

不接受用户自定义上游URL。调用方式：

```js
const provider = new WikipediaSearchProvider({ timeoutMs: 5000 });
const result = await provider.search({ question, limit: 5 });
```

返回 `SUCCESS` 或 `EMPTY`；超时抛出 `TIMEOUT`，其他网络/上游问题抛出 `SERVICE_UNAVAILABLE`。适配器只返回来源，不生成未经来源支持的事实主张。

保存查询时，调用方只传账号/入口作用域、保存操作 `requestId` 和 `searchRequestId`。`SavedQueryRepository` 必须注入服务端 `resolveCompletedSearch`，并只接受同账号、同入口、状态为 `completed`、`searchState=SUCCESS` 且至少有一个来源的任务。客户端提交的 `sources`、`claims` 等额外字段会被严格Schema拒绝。

2026-10-23的两次真实网络验证分别得到超时和服务不可用，故当前不能把真实检索写成已通过；受控响应、空结果和超时分支已由自动化测试覆盖。

## 7. 备份与恢复

自动化测试使用PGlite的隔离数据目录导出和导入验证数据可恢复。正式环境必须使用团队批准的加密 `pg_dump`/`pg_restore` 流程，并满足：

1. 业务备份保留7天。
2. 独立删除日志至少保留8天。
3. 恢复后先重放独立删除日志。
4. 完成重放确认后调用恢复安全步骤撤销全部旧会话。
5. 检查待发布删除outbox，再开放服务。

`secureRestoredDatabase` 的布尔参数是应用层前置守卫，不负责证明外部删除日志本身完整；正式演练必须提供独立日志连续性和重放证据。
