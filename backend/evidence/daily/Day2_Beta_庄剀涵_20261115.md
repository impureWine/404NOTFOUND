## 今日目标

核对任务生命周期改变后，查询结果、保存记录和用途许可是否仍由同一账号、入口与会话范围约束；补齐跨账号、跨入口和重复请求的实际回归。

## 修复内容

1. `ConsentService` 将用途许可绑定到 `entryPointId`。同一账号在另一入口不能使用或撤销该许可。
2. 查询任务保存不再直接读取内存任务表。保存前通过 `TaskService.getCompletedSearchForSave` 再次检查：
   - 当前账号和入口；
   - 查询状态及来源；
   - 当前会话、活动标识与双代次；
   - 原 `SEARCH_PROCESS` 许可的载荷、有效期和撤销状态。
3. 会话 `END` 和 `RESTART` 会取消已完成的查询任务并清除结果、来源、主张和查询状态。取消查询也清除这些字段，防止旧结果在后续流程中继续使用。

## 回归范围与结果

新增 `backend/test/integration/beta-day2-data-access.test.js`，覆盖以下结果：

| 场景 | 结果 |
|---|---|
| 结束或重来后首次保存原查询 | 拒绝；没有新增记录 |
| 原查询许可被撤回或过期后保存 | 拒绝；新的 SAVE 许可不能绕过原查询许可 |
| 同账号不同入口复用或撤销 SAVE 许可 | 拒绝 |
| 同一 `requestId` 在不同账号或入口创建记录 | 分别隔离；同范围重放返回原记录，变更载荷冲突 |
| 用其他账号或入口保存、读取或取消查询任务 | 拒绝或返回未找到 |
| 已保存查询重放、清除后再重放 | 已保存快照可幂等重放；清除后拒绝恢复 |
