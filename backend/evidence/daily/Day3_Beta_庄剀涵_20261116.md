## 发现与修订

| 问题 | 修改及行为 |
| --- | --- |
| 查询历史通过共享 `sources` 表读来源，另一条保存更新同网址后会改变旧详情 | 新增 `006_saved_query_source_snapshots.sql` 和按查询归属的 `saved_query_sources`；保存时复制来源字段，回看从快照读取，保留来源原顺序 |
| 没有摘要的来源没有 claim/evidence，旧详情无法列出 | 独立保存全部来源，公开详情增加 `content.sources`，即使 `claims=[]` 也可以回看来源 |
| 记录元数据和正文分开读取，可能跨越更新/清除提交 | 普通记录和查询详情用事务读取，并对所属 `saved_records` 行加共享锁，使写入/清除与详情读取按事务顺序生效 |
| 相同清除确认请求并发可能撞唯一约束；已过期确认仍返回成功 | 先锁记录后检查/创建确认；不同记录误用同一请求号返回冲突；过期/已消费返回 409，已清除记录返回 404 |
| 查询详情缺少状态与不确定性说明 | 增加 `status`、`uncertaintyNote`、`snapshotOrigin`，保留原有 `question`、`claims[].text/evidence`；不返回密文或账号字段 |

普通创建、查询保存、正文/来源/证据写入和幂等键完成均仍在同一事务中。清除事务继续包括正文删除、查询快照级联删除、记录墓碑、确认消费和删除 outbox；任何一步失败全部回滚。同一账号、入口、操作、请求号重放只返回同一结果，变更载荷冲突；清除后的旧保存请求不能恢复记录。

## 迁移与公开 DTO 交接

`006` 是追加迁移，未改写历史迁移及其校验和。部署顺序为先迁移再启动新代码。历史来源只可从当前共享表补录：`snapshotOrigin=LEGACY_BACKFILL`；无法恢复旧系统未保存的无摘要来源，也无法还原早已被覆盖的原始标题/时间。新保存标记 `SAVED`。重复执行迁移没有新增写入。

`GET /api/records/:id` 的 QUERY 正文新增字段：

| 字段 | 含义及前端使用 |
| --- | --- |
| `content.sources[]` | 全部保存来源；含 id、url、title、publisher、sourceTier、quality、publishedAt、retrievedAt、verificationState。不要仅从 claims 推导来源列表 |
| `content.status` | 保存结果状态，如 `PARTIAL_SUCCESS`；不是对来源真实性的保证 |
| `content.uncertaintyNote` | 原查询不确定性说明，应按普通文本展示 |
| `content.snapshotOrigin` | `SAVED` 为保存时快照；`LEGACY_BACKFILL` 应提示“历史来源信息为迁移补录” |
| `content.question`、`claims[]` | 原接口字段保留，正文解密只发生在通过账号与入口过滤之后 |

清除返回后应清空详情、列表选中项与显式上下文选择。清除确认 409 表示需要重新获取当前版本并重新确认；不得静默替换确认 ID 后直接清除。已清除详情为 404，重放同一个成功清除请求仍幂等返回成功。

清除会保留最小墓碑、幂等元数据和删除作业；共享来源目录保留以供其他记录引用。`PENDING` outbox 只表示后续删除作业已登记，**不表示备份或外部副本已物理销毁**。
